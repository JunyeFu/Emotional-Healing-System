# Agent协作与人工责任 v1.2

本章是落实包内任务的建议角色分工，不证明独立Agent或真人审查已经发生。原对话中的“独立审查”与真实外部审稿严格区分。[C1]

| 判断对象 | 首选执行者 | 完成证据与边界 |
|---|---|---|
| JSON/CSV字段、依赖环、哈希、边界用例、负测试 | 确定性脚本/测试 | 自动日志；无需人重复按确认按钮 |
| 统计代码逻辑、独立复算、主张—数据一致性 | 独立Agent+脚本 | 盲态/隔离输入、代码版本、可重跑输出；不代替真实统计审批 |
| 相关工作事实、量表来源、最新期刊说明 | 联网检索Agent | 原始来源、时间、访问层级；未取全文不伪装已读 |
| 场景概念与替代解释、问卷可理解性 | 设计Agent准备+真实形成性参与者 | Agent建议不等于人类理解证据 |
| 风险接受、团队工时/经费、场地设备、研究主张责任 | 真实研究负责人/团队 | 有权限者的真实决定，不能由模型生成签名 |
| 机构审批、量表授权、真实专家、同意与退出 | 真实对应角色/机构 | 外部回执或实际记录；不能脚本造PASS |
| 揭盲、公开、全体作者同意、投稿 | 真实授权人员 | 审核对象与版本清晰；不自动提交 |

## 内部串联

文档校验→依赖校验→分类器反例→规划复算→主张审计，可在用户给定目标和边界内自动串联。任何机器可判断的完成条件不再要求用户逐节点复算。

## 必须停在人类门的节点

相应活动的真实批准/许可未取得、缺少责任人对预算与风险的承诺、参与者停止请求、需要更改正式研究参数、准备公开或投稿。

## 每个任务的完成摘要

说明做了什么、对应版本、实际运行了哪些检查、输出路径、未验证项、下一依赖。分开`artifact_status`、`verification_status`、`approval_status`、`research_evidence_status`；不得用一个DONE覆盖四种状态。

## 给本地Codex的首个任务

阅读根README、最终审计和应用说明；先`git status --short`，执行包内验证与`apply_upgrade.py --check`。只有基线匹配且工作区干净时，按用户批准的变更范围在独立分支应用；不修改历史v1.1或运行v2.2合同。应用后优先UP-01，确认所有正式入口仍因未冻结/未批准而拒绝，再推进UP-02至UP-06。不能以“最终包”作为正式参与者研究授权。
