## 1. 一页结论

SRP 当前不是在旧原型上直接补齐交付材料，而是在保持“天气隐喻、呼吸引导、真实设备数据、Unity 体验和 TD 操作台”大方向不变的前提下，重新设计完整产品与研究主线。

目标产品是一套参与者全程平坐、无需键盘、鼠标、控制器或场景选择操作的8分钟 Unity 独立体验。参与者依次经历四个固定天气—呼吸复合模块，真实设备数据只在场景内部驱动周期反馈和累计天气变化；TD 不参与参与者体验的必要渲染，只承担实验员侧记录、实时分析、质量监控和后续可视化。

主论文的核心不是“做了四个天气”“采集了真实数据”或“跑了随机实验”，而是两项可复用知识：

1. **场景原生呼吸引导框架**：把目标呼吸协议、真实执行反馈、累计环境变化和数据降级统一转译为场景自身的视觉机制。
2. **可解释闭环序列编排方法**：根据参与前信息、已完成模块和历史过程表现，在合法剩余模块中形成可追溯、可版本化、可重放的下一模块选择。

24种完整顺序的均衡随机探索、前后量表、真实设备过程数据、策略学习和新参与者独立比较共同构成证据链，不与两项核心贡献并列。

当前仍处在**顶层研究设计冻结前**。尚未确认场景原生提示的唯一主要经验主张、最小比较基准、主要设备指标、非劣界值、修正后样本量和最终策略表示，因此暂不进入成员任务包拆分。

## 3. 项目目标与体验边界

### 3.1 项目目标

面向普通大学生构建天气隐喻与呼吸引导结合的短时交互体验，通过真实设备形成实时反馈，并用可复核实验回答：

1. 场景自身的视觉机制能否承担不同呼吸协议的目标提示和实际反馈。
2. 不同天气—呼吸复合模块及其顺序如何影响执行过程和整体短期结果。
3. 可解释编排是否比均衡随机顺序产生可重复的增量价值。

### 3.2 参与者体验

- 参与者全程平坐观看屏幕并跟随呼吸，不进行手部操作。
- 四个模块全部经历，系统自动进入下一模块。
- Unity 是参与者侧完整制品，启动和体验不依赖 TD。
- 参与者侧不出现跨场景统一呼吸圈、双圈 HUD 或 TD Spout 呼吸纹理。
- 提示从天气和环境机制自然出现，不由角色说教。
- 每种天气只保留一个核心视觉系统，避免多个反馈机制竞争注意力。

### 3.3 制品职责

| 制品 | 目标职责 | 不承担 |
|---|---|---|
| Unity | 四场景完整体验、场景原生提示、周期反馈、累计天气变化、自动转场、原生降级 | 不依赖 TD 才能完成参与者流程 |
| Python | 真实设备采集、统一时钟、信号质量、交互状态估计、策略决策、全量记录 | 不向参与者直接展示操作界面 |
| TouchDesigner | 实验员操作台、波形与相位监控、质量告警、实时分析、记录状态和研究可视化 | 不向 Unity 提供必要参与者画面 |
| 离线分析 | 数据清洗、预注册特征计算、统计模型、策略学习、重放审计和论文图表 | 不用运行时综合分替代正式结果 |

## 4. 四个天气—呼吸复合模块

| 模块 | 呼吸流程基线 | 场景原生提示与反馈 | 主要可测结构 |
|---|---|---|---|
| 风暴 | `3-3-3-3` 四阶段箱式流程 | 保护罩形成、稳定、排开风雨、锁定修复；风雨和闪电累计衰减 | 四阶段识别、停顿保持、周期误差 |
| 炙烤 | `4-6` 延长呼气，不停顿 | 吸气蓄积冷色气流，长呼气推动气流并削弱热浪 | 实际吸呼比、呼气时长、节律误差 |
| 暴雪 | `5-5` 等时慢呼吸，不停顿 | 对称节律驱动脚印和路径显现，累计表现降低雪雾遮蔽 | 周期稳定性、吸呼对称误差、相位同步 |
| 褪色 | 舒适吸气、较短补吸、缓慢完整呼气的循环叹息 | 两段吸气汇聚色彩，呼气把色彩扩散回环境 | 双吸峰、补吸间隔、呼气完整度 |

固定配对意味着研究对象是四个**天气—呼吸复合模块**。当前设计不能把观察到的差异分别归因于单一视觉特征或脱离天气后的单一呼吸流程。

## 5. 统一模块协议

每个模块固定120秒：

| 阶段 | 时间 | 数据与体验语义 |
|---|---:|---|
| `demo` | 0-15秒 | 使用本场景原生机制示范目标协议；记录原始数据，但不进入主要过程估计 |
| `closed_loop` | 15-105秒 | 真实设备驱动周期级原生反馈和累计天气变化；唯一主要过程分析窗口 |
| `lock_transition` | 105-120秒 | 锁定105秒时的真实累计状态并自动转场；不得强制显示完全恢复 |

四个模块共480秒，即8分钟主体验。前量表在第一模块前完成，后量表在第四模块后完成；模块之间不增加量表或参与者操作。

## 6. 两项核心贡献

### 6.1 场景原生呼吸引导框架

核心设计不是单向的“天气设计到天气变化”，而是三条同步映射：

```text
目标呼吸协议 -> 场景原生节律提示
实际呼吸数据 -> 场景原生周期反馈
累计执行表现 -> 天气恢复进程
```

数据质量不足时，仍由当前场景的原生机制提供开环目标节律或中性降级，并记录原因和区间。

可复用映射语法为：

```text
目标呼吸阶段
-> 场景原生节律提示
-> 真实执行的周期级反馈
-> 段内累计环境变化
-> 场景原生降级
```

四个场景用于证明该语法能够跨越结构不同的呼吸协议，而不是四个彼此独立的美术案例。

### 6.2 可解释闭环序列编排方法

编排状态由以下信息构成：

- 参与前状态量表信息；
- 已完成模块及其位置；
- 之前模块的呼吸执行特征和心电过程特征；
- 信号质量、降级事件和数据窗口；
- 尚未访问的合法模块集合。

编排输出至少包含：下一模块、选择概率、决策理由、策略版本、回退条件和可离线重放记录。参与后量表不能在运行时使用，只能在离线策略学习和最终结果分析中作为终局信息。

## 7. 研究证据链

### 7.1 已确认的三阶段结构

```text
阶段一：24种完整顺序均衡随机探索
-> 阶段二：学习、审计并冻结可解释策略
-> 阶段三：新参与者中比较冻结策略与均衡随机基准
```

阶段一中：

- 前量表只用于分层和平衡，不直接决定第一模块。
- 24种完整模块顺序以已知概率均衡分配。
- 实时设备数据只驱动当前场景内部反馈，不改变当次预分配顺序。

阶段三中，策略组可以根据前量表和此前模块过程数据选择剩余模块，但必须记录选择概率、理由和版本，并与均衡随机组独立比较。

### 7.2 场景原生框架的建议比较

以下是当前推荐、**尚未确认**的最小比较：

- `scene_native`：目标节律和实际反馈均由场景原生机制表达。
- `abstract_pacer`：研究专用统一抽象节律提示；天气、呼吸协议、时长、累计恢复算法和声音保持一致，只改变节律信息载体。

抽象提示只作为研究基准，不进入最终 Unity 制品。没有该基准或其他合理比较时，可以报告原生框架的可行性、可辨识性和跨模块设计知识，不能声称其优于抽象提示。

## 8. 数据处理与数学模型

### 8.1 数据职责分离

```text
呼吸数据 -> 原生提示能否被理解和执行
心电及可选辅助数据 -> 执行过程中出现什么变化
前后量表 -> 整个体验结束后出现什么结果
策略日志 -> 系统为什么选择该顺序
```

量表结果与设备过程结果使用不同模型，不合成为一个论文总分。运行时综合指标可以用于视觉控制，但不能自动成为主要论文结果。

### 8.2 呼吸数据

建议处理链：

```text
原始呼吸波形
-> 信号质量和有效窗口
-> 个体内归一化
-> 吸气/停顿/呼气/补吸事件
-> 与模块目标模板对齐
-> 周期级执行特征
```

当前推荐、尚未确认的唯一主要设备结果是 `protocol_fidelity`：中央90秒内满足该模块预注册时序容差的有效周期比例。次要结果包括阶段转换误差、进入稳定节律所需时间、周期稳定性、特有结构完成率和降级时间比例。

若采用原生提示与抽象提示比较，建议以周期级混合模型估计提示模式差异：

```text
cycle_valid
~ cue_mode
+ module
+ module_order_position
+ cue_mode:module
+ participant_random_intercept
```

主要主张建议采用“原生提示的执行质量相对抽象提示达到预先冻结的非劣界值”；非劣界值和样本量尚未确定。

### 8.3 心电及辅助过程数据

建议从原始 ECG 或 RR 间期生成信号质量、心率、`lnRMSSD` 和呼吸—心率耦合等特征，用于：

- 解释正确跟随呼吸时的过程响应；
- 构造后续模块的交互状态估计；
- 分析参与者差异和顺序差异。

单模块主要窗口只有90秒，而且规定呼吸会直接影响HRV，因此心电特征默认承担次要过程证据，不替代前后量表。如果未来要回答静态前后变化，需要另行冻结标准化静坐记录窗口。

可选辅助数据只能在设备、质量规则和样本量全部冻结后进入次要分析，不能成为正式实验的隐含必需条件。

### 8.4 前后量表

已确认使用中文版20项 PANAS，相同“此刻”时间框架：

- 10项负性情绪分量表为唯一主要量表结果；
- 10项正性情绪分量表为次要结果；
- `Delta_NA = NA_pre - NA_post`，正值表示负性情绪下降，用于描述和稳健性分析；
- 主要推断使用基线校正后的参与后得分。

候选模型为：

```text
# 场景原生提示的增量结果
NA_post ~ NA_pre + cue_mode + prespecified_order_terms

# 冻结编排策略的增量结果
NA_post ~ NA_pre + policy_arm
```

前后量表都进入论文分析；前量表还可用于第一阶段分层和后续策略状态，后量表不进入实时实验决策。

### 8.5 策略学习与独立确认

策略学习不把量表和设备特征加权成一个总奖励。推荐结构是：

- 终局目标：基线校正后的 `NA_post`；
- 运行状态：前量表、已完成模块、此前过程特征和数据质量；
- 过程约束：不能以降低呼吸执行质量为代价取得表面结果；
- 独立确认：在新参与者中比较冻结策略与均衡随机基准。

14自由度位置与转换结构模型保留为次要分析和策略学习工具；唯一确认性低自由度主张尚未重新冻结。

## 9. 结果到论文结论的对应关系

以下是预先规定的解释边界，不是对未来结果的保证：

| 结果模式 | 可以支撑 | 不能声称 |
|---|---|---|
| 原生提示执行质量非劣，场景一致性更高 | 原生框架可以替代抽象控件并提高跨模态一致性 | 不能仅凭此声称整体短期结果更强 |
| 原生提示执行质量非劣，且校正后 `NA_post` 更低 | 原生表达产生了相对抽象提示的增量价值 | 不能拆分归因于某一天气或某一呼吸流程 |
| 体验评分更高但执行质量更差 | 视觉吸引力较强，但引导框架尚未成立 | 不能声称原生框架有效 |
| 冻结策略组校正后 `NA_post` 低于随机组 | 可解释编排相对随机顺序产生增量价值 | 不能外推到未测试人群、时长或模块 |
| 策略组只改善过程指标 | 编排改善执行过程 | 不能声称整体短期结果改善 |
| 各组都出现前后下降但组间无差异 | 参与期间观察到整体变化 | 不能把共同变化归因于核心设计 |
| 心电过程特征变化但量表无变化 | 存在过程响应 | 不能用过程响应替代整体结果 |

如果主论文还要声称“完整项目本身导致整体短期变化”，则需要增加不经历完整项目流程的第三个比较条件。当前两项核心贡献只要求回答“原生提示相对抽象提示”和“冻结策略相对均衡随机”的增量价值；是否增加第三条件尚未确认。

## 10. 论文叙事

高质量论文不是围绕显著结果事后组织故事，而是建立预先定义的论证链：

```text
现有抽象节律提示和固定顺序的局限
-> 场景原生呼吸引导框架
-> 四个异质复合模块实例化
-> 真实过程数据检验可执行性
-> 合理基准检验场景原生设计的增量价值
-> 24顺序探索形成可解释编排
-> 新参与者独立确认策略价值
-> 提炼可迁移设计原则、方法契约和失效边界
```

当前暂定工作题目：

> **场景原生呼吸引导与可解释闭环序列编排：基于真实交互状态估计的设计与实证**

当前建议、尚未确认的一句话主线：

> 我们提出一种将目标呼吸协议、真实执行反馈和累计环境变化统一转译为场景原生视觉机制的设计框架，并通过可解释闭环编排，使异质模块能够根据实时交互状态形成可验证的个体化序列。
