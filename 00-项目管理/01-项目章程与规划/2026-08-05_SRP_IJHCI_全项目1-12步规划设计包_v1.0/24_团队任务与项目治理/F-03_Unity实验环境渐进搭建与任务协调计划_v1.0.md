# F-03 Unity实验环境渐进搭建与任务协调计划 v1.0

> 冻结日期：2026-08-17
> 适用工程：`02-技术研发/04-Unity视觉/SRP-Weather-Visual`
> 当前可执行起点：`F-03 READY`
> 裁定：先建立可复现环境和会话运行壳，再以风暴完成首个端到端纵向切片，随后并行扩展其他场景。

## 1. 目标与非目标

本计划把Unity方向从“分别制作多个场景”调整为“逐级装配可验证制品”。每一级都有固定输入、输出、验收证据和下一任务放行条件，最终形成不依赖TouchDesigner或Spout的完整参与者体验。

本轮不直接实现全部场景，不改变F-01消息合同，不让Unity拥有模块顺序、研究流程或有效计时权威，也不把开发回放、已有场景文件或Python测试解释为正式制品证据。

## 4. F-03执行过程

### 第1步：冻结可复现环境

1. 核对`ProjectVersion.txt`、`manifest.json`和`packages-lock.json`；记录Unity完整修订号、包版本、Git包提交和三者哈希。
2. 在不导入未登记素材的条件下恢复工程，记录包解析、脚本编译、场景列表和Build Settings。
3. 输出环境漂移报告；版本、锁文件、必需场景或必需脚本不一致时失败关闭。

### 第2步：建立测试与构建基线

1. 建立Edit Mode和Play Mode测试入口，至少覆盖启动、暂停、恢复、结束、非法转换和重复控制。
2. 建立Windows开发构建配置和可重复构建命令；开发构建必须带`DEV-REPLAY`可见标记。
3. 扫描运行依赖，证明TD和Spout关闭时工程仍可启动；发现依赖时记录为阻断，不做静默回退。

### 第3步：实现会话运行壳

1. 使用P-01候选golden轨迹驱动`demo -> closed_loop -> lock_transition`，四个天气各进入一次。
2. Unity只镜像`session/module/segment/control_seq`，不根据本地帧时钟改变模块顺序或研究流程。
3. 暂停、恢复、重试和重复事件不得重复推进；非法或倒退状态保留当前画面并记录原因码。

### 第4步：建立正式门负路径

1. 正式模式缺少manifest、构建哈希、P-01握手或G-02资产放行时不得开始核心内容。
2. 开发fixture、模拟输入和候选golden轨迹只生成开发证据，不写成真实链或正式运行证据。
3. 输出当前资产阻断清单，保持与G-02许可台账的ID和状态一致。

### 第5步：交接U-01与U-02

1. 向U-01交付状态镜像接口、控制事件fixture、回执挂点和网络故障测试架。
2. 向U-02交付生命周期挂点、场景加载边界、锁定/重置时点和降级入口。
3. F-03进入`IN_REVIEW`后才可视为开发候选完成；U-01仍必须等待P-01真实第二人签收为`DONE`。

## 5. 职责边界

| 责任域 | 拥有 | 不拥有 |
|---|---|---|
| Python / P-01 | manifest门、模块顺序、有效计时、控制事件、策略决策 | Unity画面内部参数和渲染性能 |
| Python / P-02 | manifest耐久确认、L0/L1、完整性、封存与重放 | Unity场景状态推进 |
| Unity / F-03至U-08 | 完整参与者呈现、四层视觉接口、渲染镜像、ACK/回执、降级画面、构建 | 顺序随机化、量表处理、交互状态估计、研究记录权威 |
| TD / F-04至T-02 | 可选只读监控、记录查看和经Python仲裁的操作请求 | 参与者核心体验、Unity纹理来源、流程权威 |
| G-02 | 资产许可台账、正式环境门和隐私检查 | Unity表现设计取舍 |

## 6. 资产替换并行通道

资产工作不阻断E0至E3的开发回放，但任何未知、未跟踪或未登记项都会阻断E4正式候选和后续正式环境。

1. F-03只盘点实际被Build Settings、Resources、Addressables、场景、Prefab、材质、音频混合器和插件引用的发布闭包。
2. 场景负责人在各自任务内为新增图片、音频、字体、Shader、插件和包提供来源、许可、作者、版本、用途和替换策略。
3. 无法补齐许可的资产在U-08前替换；替换后重新做画面、音频、性能和回归测试。
4. U-08调用G-02许可门。扫描范围、台账哈希、Unity构建哈希和发布闭包不一致时不得形成正式构建。

## 8. 验收与治理

- 每个任务单独分支、测试、提交、推送，并由第二人依据固定提交复核。
- Unity证据至少包含Unity版本、提交SHA、工作区状态、测试XML、构建日志、运行录像和证据哈希。
- F-03验收以P-01候选golden轨迹为开发输入；在P-01正式签收前不得把联调结果升级为正式合同证据。
- 任务状态只由`05_可领取任务包.csv`控制；依赖未满足不得人工提前领取。
- 本计划不解除G-02、P-01、P-02、设备、Level、预注册和外部复核门。
