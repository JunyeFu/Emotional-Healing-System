## 1. 目标与不承担项

G-02建立三项可执行治理能力：

1. 对L0至L5及联系方式、研究编号、密钥进行分级和最小权限控制；
2. 在Level B、Level C、阶段一和阶段三之间阻止同一人重复进入；
3. 对Unity正式发布依赖建立完整的作者、来源、许可和替换证据。

G-02不承担设备读取、会话编排、随机分配、交互状态估计、Unity场景实现、正式招募或数据分析。它只向X-01、Z-01和W-03提供稳定的治理接口和门禁结果。

## 2. 冻结决策

| 决策 | 冻结值 |
|---|---|
| 去重标识 | 仅手机号精确去重，不做姓名、证件或模糊身份推断 |
| 规范格式 | 严格E.164 |
| 令牌算法 | HMAC-SHA-256，32字节随机密钥 |
| 域分隔载荷 | `srp:g02:phone:v1\0<canonical_e164>` |
| 密钥主存 | 专机Windows Credential Manager，目标名`SRP/G02/dedup-hmac/v1` |
| 治理根目录 | 必须由`SRP_GOVERNANCE_ROOT`指向独立加密卷 |
| 去重存储 | SQLite，事务式预约，不保存手机号或研究编号 |
| 研究编号 | `SRP-R-`加UUID4十六进制，不编码联系方式、时间或顺序 |
| 保留期限 | `PENDING_INSTITUTIONAL_APPROVAL` |
| 资产范围 | Unity正式发布的全部Git跟踪依赖及直接包依赖 |
| 正式失败策略 | 密钥、治理根目录、权限、登记库或许可证据缺失时失败关闭 |

手机号变化可能绕过精确去重。该风险作为已知剩余边界记录，不以更多身份信息或模糊匹配扩大收集范围。

## 3. 数据分级与分离

| 层或隔离库 | 内容 | 分级 | 允许角色 | 发布边界 |
|---|---|---|---|---|
| 联系方式去重库 | HMAC令牌、阶段、暴露状态、预约和审计事件 | `RESTRICTED_CONTACT_TOKEN` | 数据管理员；项目负责人只读审计 | 不公开 |
| 研究编号映射库 | 不透明招募引用到随机研究编号的映射 | `RESTRICTED_IDENTITY_MAPPING` | 数据管理员 | 不公开 |
| 密钥凭据 | HMAC密钥与单独密封恢复副本 | `SECRET_KEY_MATERIAL` | 专机数据管理员账户 | 不进入仓库或数据备份 |
| L0 | 设备原始包、设备时间、主机接收时间 | `RESTRICTED_RAW` | 数据管理员；获批主实验员最小访问 | 不公开 |
| L1 | 同步、SQI、控制、ACK、回执、策略决策 | `RESTRICTED_PSEUDONYMOUS` | 数据管理员；会话服务写入 | 受控 |
| L2 | 目标机会、呼吸事件、机会分类 | `CONTROLLED_PSEUDONYMOUS` | 分析人员、数据管理员 | 受控 |
| L3 | 模块与会话摘要 | `CONTROLLED_PSEUDONYMOUS` | 分析人员、数据管理员 | 受控或披露复核后的汇总 |
| L4 | 锁定分析数据 | `LOCKED_ANALYSIS` | 锁库后授权分析人员 | 受控 |
| L5 | 表图、模型、复现报告 | `INTERNAL_RELEASE_CANDIDATE` | 论文与设计负责人 | 仅披露复核后的汇总可公开 |

必须满足以下物理和逻辑分离：

- 去重库不得包含`research_id`、姓名、手机号、邮箱或其他联系方式；
- 研究编号映射库不得包含手机号、HMAC令牌或密钥；
- manifest不得包含姓名、手机号、邮箱、联系方式哈希或可逆身份字段；
- 密钥不得写入仓库、环境文件、SQLite、日志、任务包、备份清单或截图；
- L0只追加，L1至L5必须能由L0、manifest、冻结配置和代码提交重建。

## 4. 手机号规范化与HMAC

`normalize_phone(raw)`执行以下确定性规则：

1. 输入必须是字符串；仅移除空格、连字符和圆括号；其他非号码字符直接拒绝；
2. 中国大陆11位、首位为`1`的号码规范为`+86`加11位号码；`86`、`0086`和`+86`前缀的同一号码得到相同结果；
3. 其他号码必须显式使用`+`，国家码与号码合计8至15位；
4. 空值、分机、位数错误、含字母或无法唯一解释的输入以`INVALID_PHONE`拒绝；
5. 原始输入与规范化结果只在调用栈内短暂存在，不得写入日志、异常消息或持久化文件。

HMAC输入固定为UTF-8编码的`srp:g02:phone:v1\0<canonical_e164>`，输出保存完整32字节摘要。禁止截断、无密钥哈希、跨用途复用密钥或把令牌返回给调用方。

Windows凭据提供器使用标准库`ctypes`调用`CredReadW`和`CredWriteW`，凭据类型固定为`CRED_TYPE_GENERIC`。正式模式只允许专机数据管理员Windows账户读取；凭据不存在、读取失败或账户不符时返回`KEY_UNAVAILABLE`并停止预约。

## 5. 去重状态机与公开接口

阶段枚举固定为：

```text
level_b, level_c, stage_1, stage_3
```

预约状态固定为：

| 状态 | 含义 | 后续进入其他阶段 |
|---|---|---|
| `RESERVED` | 已获得临时预约，尚未展示任何核心材料 | 阻止，直到释放或转为暴露 |
| `RELEASED_BEFORE_EXPOSURE` | 在任何核心材料展示前取消 | 允许重新预约 |
| `EXPOSED` | 已展示核心材料或进入核心体验 | 永久阻止 |
| `COMPLETED` | 已完成该阶段 | 永久阻止 |
| `WITHDRAWN_AFTER_EXPOSURE` | 暴露后退出 | 永久阻止 |

公开Python接口固定为：

```python
normalize_phone(raw: str) -> str
check_and_reserve(phone: str, stage: Stage, actor_id: str) -> DedupDecision
mark_exposed(reservation_id: str, actor_id: str) -> None
release_before_exposure(reservation_id: str, reason: str, actor_id: str) -> None
audit_cross_stage() -> AuditReport
privacy_lint_manifest(manifest: dict) -> None
```

`DedupDecision`只包含：

```text
allowed, reason_code, reservation_id, audit_event_id, token_version
```

不得包含手机号、规范化号码或HMAC令牌。原因码固定为：

```text
NEW
ACTIVE_RESERVATION
PRIOR_EXPOSURE
INVALID_PHONE
KEY_UNAVAILABLE
REGISTRY_UNAVAILABLE
UNAUTHORIZED
```

`check_and_reserve`必须通过SQLite `BEGIN IMMEDIATE`事务和唯一约束保证并发调用只有一个`NEW`。任何异常不得按允许处理。X-01必须在揭示分配结果前获得`allowed=true`，并只记录`reservation_id`与`audit_event_id`。

## 6. Manifest隐私门

F-01合同允许前向兼容字段，因此G-02在manifest持久化前增加独立的递归检查：

- 拒绝规范化键名包含`name`、`phone`、`mobile`、`email`、`contact`、`wechat`、`qq`、`姓名`、`电话`、`手机`、`邮箱`或`联系方式`；
- 拒绝扩展字段中符合邮箱或可规范为E.164的字符串值；
- 明确拒绝`contact_hash`、`phone_hash`、`dedup_token`及同义字段；
- 仅允许合同中的`research_id`作为研究标识；
- 错误只返回JSON路径和原因码，不回显被拒绝的值。

该检查在P-01生成manifest后、P-02首次落盘前执行；失败时正式会话不得开始。

## 7. 存储、权限与审计

`SRP_GOVERNANCE_ROOT`必须位于独立加密卷，至少包含两个分开的SQLite文件：

```text
dedup/dedup_registry.sqlite
identity/research_id_mapping.sqlite
```

去重库记录HMAC令牌、令牌版本、阶段、状态、预约时间和审计事件；映射库只记录不透明招募引用、随机研究编号、创建时间和状态。两库不得通过外键、共同主键或复制字段互联。

每个治理操作写入追加式审计事件：`event_id`、事件类型、操作者、UTC时间、对象类型、对象不透明ID、结果、原因码、前一事件哈希和当前事件哈希。修改或删除既有事件必须导致审计链验证失败。

最小权限矩阵固定为：

| 能力 | 数据管理员 | 项目负责人 | 主实验员 | 分析人员 | 设计成员 |
|---|:---:|:---:|:---:|:---:|:---:|
| 写入联系方式并预约 | 是 | 否 | 否 | 否 | 否 |
| 读取HMAC去重记录 | 是 | 仅汇总审计 | 否 | 否 | 否 |
| 维护研究编号映射 | 是 | 否 | 否 | 否 | 否 |
| 查看L0/L1 | 是 | 受控 | 必要范围 | 去标识化后 | 否 |
| 查看L2/L3 | 是 | 是 | 否 | 是 | 去标识化汇总 |
| 批准L4/L5披露 | 否 | 是 | 否 | 提交申请 | 否 |

## 8. 备份与恢复

- 使用SQLite在线备份API写入配置的加密备份目录；不得直接复制活动中的数据库文件；
- 每次备份生成包含文件名、模式版本、大小、SHA-256、创建时间和审计链尾哈希的清单；
- HMAC密钥不进入数据库备份；另存一份密封加密恢复副本，由不同保管位置控制；
- 恢复只能写入空目录，依次验证备份哈希、Schema版本、审计链、密钥可用性和合成决策期望；
- 篡改备份、缺少密钥、目标非空或操作者未授权时恢复失败关闭；
- 恢复演练只使用合成号码和合成研究编号，不使用真实联系方式。

## 9. Unity资产许可门

权威扫描根固定为Git跟踪的`02-技术研发/04-Unity视觉/SRP-Weather-Visual`。扫描器必须使用`git ls-files -z`建立文件集合，并覆盖：

- 图像、音频、字体、视频及其他媒体；
- Unity原生插件和第三方DLL；
- `Packages/manifest.json`与`Packages/packages-lock.json`中的直接依赖；
- 正式构建引用的其他第三方文件。

机器清单逐文件保存Git路径、SHA-256、资产类型和许可组ID；许可台账按组保存作者、来源URL、获得日期、许可名称、许可证据路径、允许用途、署名要求、责任人和状态。状态只允许：

```text
PROJECT_ORIGINAL
CLEARED
REPLACE
UNKNOWN
BLOCKED
```

`PROJECT_ORIGINAL`和`CLEARED`可进入候选构建。`REPLACE`必须有责任人、期限和排除方案，且替换或从构建排除前继续阻止发布。`UNKNOWN`、`BLOCKED`、未跟踪文件、缺失登记或构建引用到根目录未跟踪`SRP/`时均失败关闭。

## 12. 测试矩阵

必须至少覆盖：

1. `1xxxxxxxxxx`、`86`、`0086`、`+86`格式归一为同一号码，其他合法E.164保持确定；非法和歧义输入拒绝；
2. 数据库、日志、标准输出、异常和manifest均不出现原始手机号或规范化号码；
3. Level B到阶段三、Level C到阶段一及任意同阶段重复均被阻止；
4. 暴露前释放允许再次预约，暴露、完成和暴露后退出均永久阻止；
5. 两个并发预约只有一个返回`NEW`；
6. 缺少密钥、登记库、加密根或权限时失败关闭；
7. manifest嵌套联系方式键和值被拒绝，合法`research_id`通过；
8. 去重库与研究编号映射库不存在交叉标识；
9. 正常备份恢复保持审计链和决策一致，篡改、缺密钥和未授权恢复失败；
10. 资产扫描能发现未跟踪、未登记、哈希变化和未知许可，已清除或有阻断替换计划的状态准确报告；
11. 仓库中不存在真实联系方式、真实密钥、治理SQLite或密封恢复副本。

## 13. 验收与证据

G-02只有同时满足以下条件才可从`READY`进入复核：

- AC1：HMAC去重表、密钥、研究编号映射和manifest完成物理与逻辑分离；
- AC2：Level B、Level C、阶段一和阶段三重复审计、最小权限负测试及恢复演练全部通过；
- AC3：所有发布资产具备许可证据，或具备责任人、期限、排除方案且仍被发布门阻断；
- 全部测试在合成数据上可重复执行；
- `SRP_GOVERNANCE_ROOT`、凭据目标、ACL和备份位置有专机检查记录；
- X-01、Z-01、W-03、P-01和P-02的消费接口由第二人复核；
- 提交中不含真实联系方式、密钥、治理数据库或不受控资产。

必需证据为：权限负测试报告、跨阶段重复fixture与报告、并发事务测试、备份恢复日志、审计链验证、资产许可台账、Git资产扫描报告、下游接口说明、第二人复核记录、commit和push SHA。

## 14. 外部门与停止条件

- 保留期限维持`PENDING_INSTITUTIONAL_APPROVAL`，获批前不得自行设定或对外承诺；
- 正式联系方式录入前必须确认告知内容、授权路径、数据管理员账户和加密卷；
- 专机凭据、ACL或密封恢复副本任一缺失时，G-02技术实现可以继续用合成数据验证，但正式收集门保持关闭；
- 任何需要扩大身份字段、改变跨阶段单次参与规则或允许未清许可资产发布的需求，必须先走治理变更，不得在实现中静默放宽。
