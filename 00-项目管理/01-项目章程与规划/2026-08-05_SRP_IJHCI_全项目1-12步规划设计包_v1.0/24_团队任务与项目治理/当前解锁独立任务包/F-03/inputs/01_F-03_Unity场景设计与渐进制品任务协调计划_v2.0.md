> 冻结日期：2026-08-18
> 适用工程：`02-技术研发/04-Unity视觉/SRP-Weather-Visual`
> 状态权威：`05_可领取任务包.csv`
> 替代关系：本文件取代`F-03_Unity实验环境渐进搭建与任务协调计划_v1.0.md`作为Unity任务领取与设计先后顺序依据；v1.0仅保留为历史记录。
> 核心裁定：先形成研究体验契约、概念选择、呼吸提示原型、映射合同、全程预演和灰盒，再制作最高风险垂直切片；通过后才并行生产其余场景。

## 1. 订正原因

v1.0从现有工程结构出发，直接采用“环境壳、双接口、风暴切片、其余天气复制”的装配顺序。这条路线适合迁移旧原型，但不构成从零开始的游戏场景设计流程，主要存在四个问题：

1. 在目标体验和完整旅程未冻结前就默认了天气名称和首个场景；
2. 把场景原生提示和抽象提示的具体形式当作既定方案，没有先分别比较其清晰度；
3. 只要求单场景灰盒，没有先验证四模块顺序和跨场景连续性；
4. 声音、实时映射、资产来源和形成性回退门进入过晚，容易把一个场景的问题复制到全部场景。

v2.0保留F-01、F-02、R-01、P-01和P-02已经形成的合同、构念与技术候选，不回退其任务状态；但将Unity的具体天气表现、统一提示形式、场景节拍、声音和垂直切片选择重新置于可审查的前期设计门之后。

## 2. 外部方法依据

本计划使用以下资料复核设计顺序，访问日期均为2026-08-18：

- [MDA原始论文](https://www.cs.northwestern.edu/~hunicke/MDA.pdf)：从期望体验反推运行动态和实现机制，并在结果与实现之间迭代；
- [ISO 9241-210:2019](https://www.iso.org/standard/77520.html)：以人为中心的设计活动贯穿交互系统生命周期；
- [Epic Level Blockout官方文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/designer-01-project-setup-and-level-blockout-in-unreal-engine)：在正式资产前用灰盒验证尺度、视线和流程，并尽早测试；
- [Unity Vertical Slice课程](https://learn.unity.com/tutorial/66f53a14edbc2a0e75d4fe90?version=6.0)：垂直切片是用于验证最终观感和运行方式的完整局部；
- [呼吸视觉比较研究](https://tee.codes/Papers/ICHI_2020.pdf)：相同时序下，不同呼吸视觉在同步表现和主观清晰度上仍可能不同。

这些资料提供方法依据，不替代本项目研究冻结、合同、资产许可或后续证据。

## 3. 冻结项与重新设计项

### 3.1 本轮不得擅自改变

- 四个模块各进入一次，顺序由Python权威会话和manifest决定；
- 核心体验期间参与者平坐观看，不进行手部操作；
- 推荐段结构为`demo -> closed_loop -> lock_transition`，推荐时长为25/150/25秒，具体值读取冻结配置；
- Unity独立完成参与者视听体验，不依赖TouchDesigner或Spout；
- Python拥有会话、顺序、有效计时、交互状态估计、控制和记录权威；
- Unity只呈现并回报内部渲染状态，不从本地帧时钟推进研究流程；
- 场景接口保持`Target / Actual / Recovery / Fallback`四类语义；
- 两种提示条件的信息内容、时点和失败状态必须可比较；
- 未登记、来源未知或许可状态未知的发布资产阻断正式构建。

### 3.2 必须重新论证后才能冻结

- 四个天气的用户可见名称、环境隐喻和核心视觉机制；
- 场景原生条件如何通过天气表达目标和实际，以及抽象条件采用圆环、波形或其他完整表示形式；
- 场景叙事角色、镜头、构图、层级、色彩、声音和转场；
- 哪个天气承担最高风险垂直切片；
- 旧Storm、Heat、Snow、Fade场景和素材是否复用；
- 视觉资产规格、动画规格和声音规格。

F-01合同中的稳定模块ID不得由场景设计者直接改名。若V-02选择结果需要改变合同标识，先提出版本化合同变更；未批准前保持技术ID和用户可见概念分离。

## 6. 各设计包的完成边界

### V-01 研究体验契约与完整旅程

- 明确研究固定项、设计开放项、技术固定项和证据需求；
- 从期望体验反推运行动态和Unity表现责任；
- 形成入口、四模块、跨模块转场和结束的完整旅程；
- 每个设计主张必须映射到研究变量、运行遥测或明确标注为非研究装饰。

V-01不制作天气资产、不选择统一提示、不修改F-01 Schema。

### V-02 天气概念与呼吸提示专项原型

- 每个功能位置至少提出两个低成本天气/环境候选；
- 分别制作场景原生和抽象条件候选，并在各自条件内保持相同时序、信息和音频以比较清晰度；
- 记录概念差异、理解成本、实现成本、视觉风险、资产来源风险和淘汰理由；
- 输出四个入选概念、稳定技术ID映射和最高风险候选。

抽象条件的圆环、波形或其他完整表示形式只有在本任务验收通过后才可冻结；场景原生条件仍须由天气机制表达目标和实际，不能由旧TD原型或旧Unity脚本自动继承。

### V-03 四层视听映射与资产来源基线

- 为每个入选天气定义`Target / Actual / Recovery / Fallback`的视觉和声音角色；
- 冻结更新频率、延迟、平滑、保持、锁定和恢复语义；
- 区分研究语义层和纯背景层，禁止用背景随机动画泄露目标节律；
- 为预期图片、动画、字体、音频、Shader、插件和包建立来源与替换计划。

### V-04 完整分镜与声音预演

- 按真实推荐时长制作完整低保真预演，而不是只画静态概念图；
- 覆盖两种提示条件的共同内容和差异内容；
- 声音从预演阶段进入，不等到最终完善阶段；
- 对每个镜头记录目的、持续区间、前后状态、声音、数据输入和失败显示。

### V-05 四模块全旅程灰盒与形成性回退门

- 使用明显标识为`DEV-REPLAY`的记录fixture，不将随机Mock接入正式路径；
- 四模块在任意合法manifest顺序下只进入一次；
- 使用简单色块、占位声音和标签验证构图、视线、提示清晰度、节奏和转场；
- 形成性评审人员不得计入后续正式样本；
- 任何关键不理解、遮挡、节奏断裂或条件信息不匹配都必须回退V-02至V-04，而不是带入正式美术。

## 7. 垂直切片选择规则

U-03不得在任务规划阶段固定为“风暴”。V-02按下列维度评分并选择总风险最高的入选天气：

1. 四层同时呈现的视觉冲突风险；
2. 呼吸阶段边界的可辨识风险；
3. 粒子、Shader、动画和声音实现风险；
4. 目标设备性能风险；
5. 降级和恢复状态的可读性风险；
6. 资产来源和替换风险；
7. 与另一提示条件发生信息不匹配的风险。

U-03完成后冻结可复用Scene模板、Prefab边界、Sorting Layer、音频总线、场景生命周期和证据采集方式。U-04至U-07只能通过扩展点实现差异，不得重新定义公共合同。

## 8. 形成性评审与正式样本隔离

- V-02、V-04、V-05和U-03允许使用团队成员、独立设计评审人员或专门招募的形成性评审人员；
- 这些人员及其数据只用于界面理解、节奏和实现修订，不进入正式分析数据；
- 形成性评审记录使用独立编号、目录和用途声明；
- 进入后续正式流程前仍须经过G-01及Level相关门，不得用前期评审替代。

## 9. 资产与证据从第一天开始

1. V-02为每个概念登记预期资产类型和来源风险；
2. V-03建立资产来源计划和替换优先级；
3. V-04为Animatic中的第三方临时材料标记`TEMP_REFERENCE_ONLY`；
4. U-03只允许把可追踪资产进入垂直切片候选；
5. U-08以G-02发布闭包和许可台账作为正式构建前置门。

开发回放、截图、自动测试和形成性评审不能单独证明资产放行、真实设备链或研究效果。
