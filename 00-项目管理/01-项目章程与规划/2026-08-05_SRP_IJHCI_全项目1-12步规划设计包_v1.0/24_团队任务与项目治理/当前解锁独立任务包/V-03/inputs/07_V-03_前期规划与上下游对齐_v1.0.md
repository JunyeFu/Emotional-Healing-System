## 1. 本轮目标

V-03把V-02确认的四个场景与R-01确认的四层表示语义转换为可执行、可审计的设计任务。规划阶段回答四个问题：

1. 每项详细设计从哪个上游权威取得真值；
2. 六项交付物必须包含哪些字段和失败关闭语义；
3. U-02、V-04和U-03至U-07分别消费什么；
4. 什么条件满足后才能开始天气级详细填充。

详细填充已在本目录形成候选文档和JSON，但仍不操作Unity Editor，不修改Unity场景、Prefab、脚本、音频或资产，也不产生运行、构建、真实输入链或研究结果证据。

## 3. 已冻结边界

### 3.1 系统职责

| 模块 | 唯一职责 | V-03禁止赋予的职责 |
|---|---|---|
| Python | 会话、顺序、单调时钟、目标协议、交互状态估计、累计值、质量状态、记录 | 不由Unity视觉状态反向修改 |
| Unity | 完整参与者呈现、四层渲染镜像、ACK和渲染回执 | 不自行推进模块，不生成缺失输入，不依赖TD |
| TouchDesigner | 可选只读操作台 | 不控制Unity，不覆盖Python真值 |

### 3.2 四层不变量

| 层 | 输入源 | 必须回答 | 绝对禁止 |
|---|---|---|---|
| `TargetCue` | `python.target_protocol` | 当前应跟随的阶段与进度 | 读取实际、累计或质量值改变目标 |
| `ActualFeedback` | `python.interaction_state_estimate` | 当前实际阶段、进度与置信程度 | 用目标动画、零值或随机动画冒充实际输入 |
| `RecoveryState` | `python.recovery_aggregate` | 从模块开始累计到的过程区间 | 编码当前相位或为画面完整继续增长 |
| `FallbackState` | `python.signal_quality` | 哪些信息受限以及显示如何变化 | 表达参与者表现评价或伪造成功 |

### 3.3 两条件不变量

- `scene_native`和`abstract_pacer`共享场景、相机、卷轴、累计变化、音频、时序、输入真值和奖励时点。
- 原生条件以中远景核心机制表达目标、近景痕迹表达实际。
- 抽象条件只以外环表达目标、内环表达实际；背景不得泄露当前周期。
- 两条件是完整提示表示方案，不允许把结果归因于天气、呼吸结构或单一视觉变量。

### 3.4 降级可见语义

后台继续记录`GOOD/DEGRADED/UNUSABLE/DISCONNECTED`四级质量状态，参与者只看到两类降级：

| 参与者可见类别 | 后台状态 | 实际反馈 | 目标提示 | 累计状态 |
|---|---|---|---|---|
| 低确定性 | `DEGRADED` | 继续运动，轮廓断续、柔化并降低确定性 | 按Python规则继续 | 按Python唯一规则处理 |
| 暂不可用 | `UNUSABLE/DISCONNECTED` | 停止相位推进，保留静态断续轮廓 | 开环继续或由Python中止 | 暂停或保持锁定 |

`GOOD`不显示额外降级标记。场景原生条件只改变近景实际痕迹，抽象条件只改变内环；不得增加文字、提示音、全屏变暗、红色警告或技术原因说明。

### 3.5 累计状态生命周期

| 会话位置 | 累计视觉行为 | 数据语义 |
|---|---|---|
| `demo` | 保持当前天气中性基线 | 不启动模块累计呈现 |
| `closed_loop` | 按Python的`recovery_value`缓慢变化 | 只表达本模块累计过程 |
| `closed_loop`结束 | 锁定当前实际结果 | 不强制达到100% |
| `lock_transition` | 保持锁定结果后平缓退出到山雾长廊 | 不再增长或回退 |
| 下一模块入口 | 重置为新天气自身中性基线 | 不继承上一模块视觉值 |

上一模块最终值继续进入权威记录，但不得成为下一模块的初始视觉值或叙事前提。

### 3.6 目标与实际的跨层关系

- 目标与实际允许通过同时可见的独立运动形成“感知同步”，不生成系统判定式奖励。
- 场景原生条件的中远景目标与近景实际始终空间分离；抽象条件的外环与内环始终保持固定层级和最小间距。
- 禁止吸附、合并、误差箭头、连接线、红绿变化、成功闪光或其他对齐奖励。
- 实际层不得读取`target_phase`、`target_progress`或`phase_error_band`改变自身视觉样式。
- 两条件均由参与者比较并置的目标与实际运动关系，不增加一方独有的信息通道。

### 3.7 相位保持插值

| 情况 | 视觉规则 |
|---|---|
| 同一相位内的新进度帧 | 允许在相邻20 Hz帧间插值，候选平滑窗口`100–250 ms` |
| Python相位真值改变 | 首个可呈现帧立即切换运动语义，不跨相位混合 |
| 输入帧暂缺 | 保持最后合法画面并等待Python降级状态，不外推实际进度 |
| 下一相位尚未到达 | 不预测、不预播、不用视觉惯性提前进入 |

精确平滑值由U-03结合外部呈现延迟证据冻结；V-03不把候选范围写成已验证值。

### 3.8 累计环境状态的双向映射

`RecoveryState`只作为技术合同名，参与者可见设计统一称“累计环境状态”。Unity对`recovery_value ∈ [0,1]`做双向慢变量映射，不取历史最大值、不强制单调上升、不自动补到1.0；候选低通范围为`2–5 s`。

| 天气 | 低值方向 | 高值方向 | 必须保留的身份 |
|---|---|---|---|
| `storm` | 雨势更强、能见度更低 | 雨势减弱、路径更清楚 | 高值仍有风雨 |
| `heat` | 热霭更强、远景更模糊 | 热霭减弱、远景更清楚 | 高值仍有炎热感 |
| `snow` | 雪雾更密、树线更隐 | 雪雾减薄、树线更清楚 | 高值仍持续降雪 |
| `fade` | 轮廓破碎、纹理与基础色彩较弱 | 轮廓连续、纹理与基础色彩增强 | 高值不强制全饱和 |

数值下降时允许沿同一路径缓慢回退。Unity不得通过视觉美化继续增长或冻结历史最好状态。

### 3.9 共享累计曲线

- 四个天气首版统一使用经过相同低通后的线性`0–1`映射。
- 各天气只定义低值和高值视觉端点，不得自行增加阈值、加速段、平台段或后半程奖励。
- 同一天气的`scene_native`与`abstract_pacer`使用完全相同的曲线、端点和更新时间。
- U-03只有在实图或录像证据表明线性映射不可辨识时，才能提出版本化非线性调整；调整必须记录依据、旧值、新值和条件一致性证据。
- 正式配置冻结后不得在会话中或条件间调整曲线。

### 3.10 实际置信包络

`actual_phase`和`actual_progress`唯一控制实际反馈相位几何；`actual_confidence`只控制可见确定性：

| 可受置信度影响 | 禁止受置信度影响 |
|---|---|
| 轮廓连续度 | 相位类型与运动方向 |
| 边缘清晰度 | 相位进度与速度 |
| 有限透明度范围 | 尺寸与路径几何 |
| 实际载体可定位程度 | 颜色、闪烁、抖动和奖励 |

四个天气的近景实际痕迹和抽象条件内环使用同一归一化置信包络。具体透明度下限、断续比例和边缘范围由U-03实图可辨识证据冻结；低置信状态仍须保持载体可定位。

### 3.11 非节律环境母带候选边界

声音只承担天气空间与连续环境质感，不响应`TargetCue`、`ActualFeedback`、累计环境状态或参与者可见降级类别：

| 参数 | V-03候选边界 | 冻结门 |
|---|---|---|
| 综合响度 | `-24至-20 LUFS-I` | U-03/U-08测量 |
| 真实峰值 | `≤ -3 dBTP` | U-08测量 |
| 场景/中性雾廊交叉淡化 | `2–4 s` | U-03/U-08测量 |
| 循环长度 | 优先完整模块母带；循环时`≥ 60 s`且循环点不与呼吸周期对齐 | U-03听审与时间线检查 |

每个模块从相对时间零确定性播放，不生成运行期随机声音事件。暂停时冻结播放位置并停止输出，恢复后从冻结位置继续。同一天气的`scene_native`和`abstract_pacer`必须使用相同文件、哈希、起点、循环、响度和包络；V-03只冻结候选边界，不声明已完成声音测量。

### 3.12 横向卷轴与视差候选边界

采用固定观察者构图下的相机横向自动前进。相机只改变横向位置，高度、旋转、正交尺寸、地平线和提示安全区保持固定；“固定观察者”不得误写为相机完全静止。

| 参数 | V-03候选边界 | 说明 |
|---|---|---|
| 基础卷轴速度 | `0.015–0.025屏宽/秒` | 首选候选值`0.02屏宽/秒` |
| 候选`1920×1080`像素换算 | `28.8–48 px/s` | 首选候选值`38.4 px/s`；正式值必须同时记录分辨率 |
| 天空 | 严格静止 | 可逐帧检测，无周期运动 |
| 远景表观速度因子 | `0.30–0.45` | 相对近景/地面基础速度 |
| 中景表观速度因子 | `0.60–0.80` | 相对近景/地面基础速度 |
| 近景/地面表观速度因子 | `1.00` | 基准速度带 |

背景资产可多于三个文件层，但运行时最多归入远、中、近三个运动速度带；提示层不得参与世界视差。四天气及两种提示条件使用相同基础速度，不允许天气身份、目标、实际或累计环境状态改变卷轴速度。暂停时冻结相机、视差、粒子、提示、累计变化和转场等所有视觉时间源。

U-03须提交`parallax_preview`、实际滚动接缝录像和暂停逐帧对比，并据此冻结精确值；U-08执行联合验证。当前高分辨率分层插画方向不采用`640×360/32 PPU`像素画候选默认值。

### 3.13 确定性分段长卷轴资产策略

近景、地面和主要中景采用固定顺序的分段条带，不使用单张巨型运行纹理、短周期可见循环或运行期随机重排。有效覆盖按最长候选模块计算：

```text
首屏视口 + 最大候选模块时长 × 最大候选基础速度
= 1 + 220 s × 0.025屏宽/s
= 6.5屏宽
```

加入接缝余量后，候选有效覆盖不得低于`6.75屏宽`。首版建议四段，每段原始宽度不超过`2屏宽`；相邻段重叠`0.10–0.15屏宽`，按候选`1920×1080`换算为`192–288 px`。

天空保持静止。远景可使用较短的确定性无缝条带，但完整模块内不得出现容易识别的重复地标。所有段共用画布、原点、地平线和提示安全区；拆层后补齐原遮挡区域并禁止自动裁边。

F-03依据目标显示尺寸冻结纹理尺寸、压缩、图集与内存拆分；U-03提交静态拼接预览和完整候选时长滚动录像并冻结最终段数。出现可见接缝、透明空洞、补绘断层或明显重复即不通过。

### 3.14 固定构图与提示安全区候选

以屏幕左下角为`(0,0)`、右上角为`(1,1)`，统一使用归一化屏幕坐标和`16:9`画面：

| 构图项 | V-03候选边界 |
|---|---|
| 地平线 | `y=0.56–0.62`，首选`0.59` |
| 场景原生目标安全区 | `x=0.55–0.85, y=0.34–0.72` |
| 场景原生实际安全区 | `x=0.20–0.45, y=0.18–0.52` |
| 抽象双环中心 | `(0.50,0.50)` |
| 抽象外环最大直径 | 屏幕短边`18%–24%` |

同一天气全部分段及两种提示条件使用相同地平线。目标和实际安全区不得重叠，前景、地标和高对比背景不得持续穿越安全区。抽象条件关闭场景原生目标和实际层，因此居中双环无需同时避让两个场景原生安全区。

F-03按该归一化构图换算相机高度和正交尺寸，不绑定旧工程像素画参数。U-03提交安全区叠加图、灰阶截图和完整滚动录像，据此冻结精确值并检查持续遮挡。

## 5. 六项执行制品模板

以下模板冻结字段，不填天气级内容。执行者不得删列或把`TBD_EXECUTION`解释为默认值。

### 5.1 四层视听映射合同

每个`technical_id × cue_mode × layer`一行：

| 字段 | 必填规则 |
|---|---|
| `technical_id` | 仅`storm/heat/snow/fade` |
| `cue_mode` | `scene_native/abstract_pacer` |
| `layer` | `target/actual/recovery/fallback/background` |
| `source_fields` | 必须来自F-01/R-01允许字段；背景必须为空 |
| `semantic_question` | 参与者从该层应能理解什么 |
| `visual_carrier` | 场景对象或双环通道；不得是未登记第二核心机制 |
| `audio_role` | 角色ID或`NONE` |
| `update_trigger` | 遥测帧、可靠事件或模块事件 |
| `quality_behavior` | GOOD至DISCONNECTED四状态行为 |
| `forbidden_coupling` | 明确不得读取的层或字段 |
| `evidence_hook` | 日志、截图掩膜、回执或审查项 |

### 5.2 参数边界与锁定规则

| 字段 | 必填规则 |
|---|---|
| `parameter_id` | 稳定技术ID，不使用显示名 |
| `owner_layer` | 四层之一或背景 |
| `unit` | 秒、毫秒、归一化值、像素、分贝等 |
| `candidate_min/max` | 只写上游允许或待测候选区间 |
| `default_candidate` | 可为空；不得冒充正式冻结值 |
| `update_rate` | 不得高于输入权威；20 Hz输入不等于20 Hz语义变化 |
| `smoothing/hold/lock/recovery` | 分开填写，不用一个动画曲线混合四种语义 |
| `freeze_gate` | V-04、V-05、U-03或外部测量中的明确门 |
| `runtime_log_field` | 每个动态参数必须可日志化 |

### 5.3 两条件信息匹配审查

每个`technical_id × segment × event_truth`一行，记录：真值字段、原生可见编码、抽象可见编码、共同音频、共同累计、奖励时点、缺失状态、必须匹配项、只记录差异项、证据路径和审查结论。结论只能为`PASS/FAIL/NOT_TESTED`，没有证据不得填`PASS`。

### 5.4 声音角色表

每项记录`audio_id、scene、role、semantic_layer、event_source、loop_or_one_shot、condition_policy、loudness_candidate、ducking_rule、fallback_behavior、source_status、license_group、replacement_owner`。阶段同步声音若导致一条件额外提示，必须删除或在两条件等值实现；不得用语言评价参与者。

### 5.5 资产来源与替换计划

### 5.6 工程风险矩阵与U-03选择

每个天气对七类风险各按0至4分：

| 分值 | 定义 |
|---:|---|
| 0 | 已有签收合同和直接复用路径，未见特有风险 |
| 1 | 常规实现，可由单一组件测试覆盖 |
| 2 | 需要跨层或跨条件联调，但边界明确 |
| 3 | 存在未验证参数、复杂降级或显著资产替换 |
| 4 | 上游合同未闭合、失败会推翻公共模板或无法在当前门内验证 |

七类风险固定为：四层冲突、阶段辨识、实现、性能、降级可读性、资产来源、条件匹配。总分相同时依次以“上游合同缺口、条件匹配、降级可读性、性能”决胜。评分必须附证据与理由；本轮不填写任何分数，也不预设U-03为风暴。

七类风险等权相加。V-03设计负责人和独立复核者分别评分并保留原始理由；任一维度相差2分以上，或两人选出的最高风险天气不同，必须讨论并记录最终裁定。旧Unity资产存在、制作偏好和场景吸引力不得作为降分或加分依据。
