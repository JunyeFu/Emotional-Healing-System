# V-04 节点19：分镜数据源与字段结构

> 状态：ACCEPTED
> 日期：2026-08-24
> 目标：冻结五十条主分镜节拍的机器可读来源、生成关系、字段结构和验证规则。

## 1. 文件体系

### 1.1 编辑权威

```text
V-04_分镜节拍源_v1.0.json
V-04_分镜节拍源_v1.0.schema.json
V-04_设计预演轨迹_v1.0.json
```

- `分镜节拍源`承载节拍身份、目的、事件锚点、画面要求和条件差异。
- `Schema`承载字段类型、枚举、必填关系和禁止组合。
- `设计预演轨迹`承载目标、实际、累计和质量等输入值的唯一权威。
- 分镜文件只引用预演轨迹，不手工复制另一套输入权威。

### 1.2 自动生成文件

```text
V-04_参考顺序展开_v1.0.json
V-04_分镜表_v1.0.md
V-04_时序核对表_v1.0.csv
V-04_生成清单_v1.0.json
```

自动生成文件不得手工编辑。生成清单记录源文件哈希、生成器版本、生成时间和输出哈希。

## 5. 身份字段

| 字段 | 类型 | 约束 |
|---|---|---|
| `beat_id` | ASCII字符串 | 全局唯一 |
| `scope` | 枚举 | `GLOBAL_HOLD`或`WEATHER_MODULE` |
| `weather_id` | 枚举或`null` | `storm/heat/snow/fade` |
| `module_local_id` | 枚举或`null` | `M01–M12` |
| `segment` | 枚举 | `outside_core/demo/closed_loop/lock_transition` |
| `purpose_code` | ASCII枚举 | 不使用自由文本承担机器语义 |

`G01/G02`的天气与模块局部ID为`null`，并填写`null_reason=GLOBAL_HOLD`。

## 6. 结构化触发字段

```json
{
  "kind": "PREVIEW_RECOVERY_KNOT",
  "authority": "EVENT",
  "match": {
    "event_id": "PREVIEW_RECOVERY_KNOT_1",
    "recovery_value": 0.58
  }
}
```

允许的`kind`：

```text
GLOBAL_HOLD_START
SEGMENT_START
TARGET_CYCLE_START
VISUAL_STATE_REACHED
PREVIEW_RECOVERY_KNOT
SEGMENT_END
TRANSITION_PROGRESS
CORE_END
```

允许的`authority`为`EVENT`、`SEGMENT_CONFIG`和`REVIEW_EXCERPT`。内部周期、实际淡入和累计节点使用事件；段边界使用配置；首尾示意使用评审摘录。参考秒数不得覆盖事件结果。

## 7. 时间定位字段

```json
{
  "module_reference_ms": 55000,
  "segment_reference_ms": 30000,
  "core_reference_ms": 55000,
  "outside_core_reference_ms": null,
  "counts_toward_core": true,
  "resolution": "FIXED_REFERENCE",
  "event_order": 0
}
```

`resolution`允许`FIXED_REFERENCE`、`FROM_PREVIEW_TRACE`、`FROM_SEGMENT_CONFIG`和`OUTSIDE_CORE_REVIEW_EXCERPT`。`M02/M03`从轨迹解析，`M04/M09`从段配置解析，`M05–M08`从预演轨迹节点解析，`M10–M12`同时记录转场进度。

同刻边界示例：

```json
[
  {"beat_id": "STORM_M12", "core_reference_ms": 200000, "event_order": 0},
  {"beat_id": "HEAT_M01", "core_reference_ms": 200000, "event_order": 1}
]
```

## 15. 参考顺序装配

模块模板中不保存固定位置。参考装配单独记录：

```json
{
  "assembly_id": "V04_REFERENCE_STORM_HEAT_SNOW_FADE",
  "status": "REVIEW_REFERENCE_ONLY",
  "weather_order": ["storm", "heat", "snow", "fade"],
  "module_offsets_ms": [0, 200000, 400000, 600000],
  "first_position_boundary_weather": "storm",
  "final_exit": "COMMON_END_BASELINE"
}
```

生成器据此计算位置、核心时间、下一天气和首末位置。24种排列检查使用同一模块模板，不复制24份分镜源。

## 16. 生成格式

- JSON使用UTF-8无BOM和LF；机器字段、ID和枚举使用ASCII。
- JSON哈希使用键排序、紧凑分隔符和UTF-8规范化字节的SHA-256。
- Markdown使用UTF-8和LF，由生成器覆盖。
- CSV使用UTF-8-SIG和CRLF，复杂字段展开为固定列，不保存嵌套JSON字符串。
- 所有生成文件写入源JSON、Schema、预演轨迹和生成器哈希。

## 17. 版本规则

- 已签收版本禁止原地改写。
- 字段兼容扩展升级为`1.1`，删除、改名或改变语义升级为`2.0`。
- 节拍增删、时间语义变化或条件差异扩大必须新增ADR。
- 生成器变化但源数据不变时只更新生成清单。
- F-05完成后若只补充运行绑定，不得静默覆盖V-04 v1.0。

## 19. 验收要求

1. Schema使用JSON Schema Draft 2020-12。
2. 恰好存在两条全局节拍和四乘十二条天气节拍。
3. 五十个`beat_id`全局唯一。
4. 每条节拍均能解析到预演轨迹快照，且快照哈希一致。
5. `M12/M01`同刻事件顺序正确。
6. 两条件共享状态逐字段一致，条件覆盖不越过允许字段。
7. 差异像素不越过预期掩码。
8. 音频源时间、增益和淡化状态一致。
9. 全部资产可在台账中解析，临时资产保持`formal_use_allowed=false`。
10. Markdown、CSV和展开JSON可以从源文件重新生成且哈希稳定。
11. 24种顺序均可由同一模块模板装配，每个天气恰好六次处于第一位置。
12. 十二种有向相邻关系全部覆盖。
13. 参考顺序始终标记`REVIEW_REFERENCE_ONLY`。
14. 自动验证结果不扩大为Unity运行、正式构建或正式输入链已经完成。
