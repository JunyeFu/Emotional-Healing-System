# 目标运行接口 v2.1

> 状态：`IMPLEMENTATION_BASELINE_V1_1`

> F-01机器可读合同：[runtime-contract-v2.1.schema.json](../../../../../../02-技术研发/05-通信协议/contracts/runtime-contract-v2.1.schema.json)。合同实现不表示P-01会话服务、U-01 Unity客户端或T-01 TD面板已经完成。

## 1. 模块和权威

```text
PLUX respiBAN BLE ----> Device Adapters ----> Python Session Core
Polar H10 ------------>       |                    |
                              |                    +--> immutable L0/L1
                              |                    +--> reliable control + ACK
                              |                    +--> UDP telemetry 20Hz
                              |                              |--> Unity participant product
                              |                              `--> TD operator console
                              `--> deterministic offline replay
```

Python Session Core是会话、单调时钟、分配、模块顺序、目标相位、交互状态估计、质量、累计状态和落盘的唯一权威。Unity是参与者体验的唯一渲染制品。TD只读监控，只能向Python提交人工标记或中止请求。

正式Unity不得依赖TD或Spout。TD退出、未安装或崩溃时，Unity核心体验和Python落盘继续运行。

## 2. 传输职责

| 传输 | 语义 | 要求 |
|---|---|---|
| TCP 5010可靠控制通道 | `prepare/start/pause/abort/segment/module/end`、ACK、渲染回执与TD请求 | 仅绑定127.0.0.1；有序、幂等、重连补发；已登记为配置预留 |
| UDP 5006 | Unity实时自包含遥测 | 20Hz；新帧覆盖旧帧 |
| UDP 5005 | TD实时自包含遥测 | 20Hz；只读；失联不影响主链 |
| 追加式文件 | 原始包、事件、控制、ACK、渲染回执、策略决策 | 每条含源时间、接收时间、单调时间、时钟域、版本和完整性 |


manifest不得保存姓名、电话、邮箱或联络哈希。`formal_*`模式拒绝Mock、未知构建、缺失清单、重复分配或未冻结配置。

## 4. ControlEvent与ACK

```text
schema_version, session_id, event_id, control_seq,
event_type, issued_monotonic_ns, effective_monotonic_ns,
clock_domain_id, payload
```

ACK包含`event_id`、接收时间、应用时间、Unity帧号、结果和错误码。重复`event_id`不得重复推进状态。超过重试上限进入冻结降级或中止。

```text
schema_version
session_id, frame_seq
clock_domain_id
source_monotonic_ns, received_monotonic_ns, sent_monotonic_ns
clock_offset_ns, clock_drift_ppm, sync_uncertainty_ns
module_id, module_position, segment

recovery_value, recovery_locked
```

帧必须自包含。`calm_index`只允许出现在旧兼容适配器，不得控制正式条件、顺序、Gate结果或Unity四层接口。

## 6. PolicyDecision

阶段一随机决策与阶段三策略决策均保存：

```text
decision_id
session_id
stage
position
candidate_actions[]
selected_action
behavior_probability
target_policy_probability|null
state_snapshot_hash
random_draw
reason_code
fallback_applied
fallback_reason|null
policy_version|null
created_monotonic_ns
```

阶段一的`behavior_probability`必须等于剩余合法动作数的倒数。阶段三随机组保存同一字段，策略组另存目标策略概率。任何概率缺失会使该决策不能进入离线策略评价。

## 7. Unity四层接口

```text
ApplyTarget(phase, progress)
ApplyActual(phase, progress, confidence)
ApplyRecovery(value, locked)
ApplyFallback(state, reason)
ResetModule(module_id, cue_mode)
```

`scene_native`由场景机制表达四层；`abstract_pacer`由双环表达目标和实际，天气保留匹配背景与累计变化但不编码相位。两者被视为完整提示表示方案。

## 8. 数据层

```text
L0: 设备原始包、设备时间、主机接收时间
L1: 同步帧、SQI、控制、ACK、渲染回执、策略决策
L2: 目标机会、呼吸事件、机会分类
L3: 模块与会话摘要
L4: 锁定分析数据
L5: 表图、模型与复现报告
```

L0只追加。缺失测量使用空值与原因码，不得填零。L1至L5必须可由L0、manifest、配置和代码提交重建。

## 9. 时钟同步

- 进程内持续使用单调时钟；UTC只用于审计锚点；
- Python与Unity使用四时间戳交换估计偏移、漂移和不确定度；
- 进程重启、时钟回拨、超时和丢包具有显式状态；
- 每次同步结果写入L1；
- 设备样本到屏幕呈现延迟必须由高速摄像、光敏元件或等效外部方法验证，不能只比较两个进程日志。

## 10. 降级

| 状态 | 目标提示 | 实际反馈 | 累计状态 | 记录 |
|---|---|---|---|---|
| `GOOD` | 继续 | 真实 | 更新 | 正常 |
| `DEGRADED` | 继续 | 按冻结规则降低置信或淡出 | 暂停或按唯一冻结规则更新 | 原因码 |
| `UNUSABLE` | 继续开环 | 停止 | 暂停 | 技术不可观测机会 |
| `DISCONNECTED` | 安全开环或中止 | 停止 | 暂停 | 断流与重连 |

正式模式禁止切换Mock、伪造成功、零值替代缺失或平滑跨越长断流。

## 11. 集成验收

- 干净机器上的Unity独立构建完成推荐13分20秒四模块流程；
- 两台真实设备完成完整会话、连续多小时压力和故障注入；
- 控制事件重复发送不重复推进；
- 时钟偏差不高于50毫秒，外部测量端到端延迟P95不高于200毫秒；
- 断开任一设备进入对应降级，不切换Mock；
- 同一L0和种子重放生成一致L2/L3与策略决策哈希；
- 端口和权限负测试证明TD不能直接连接Unity或覆盖正式记录；
- 只有`LIVE_E2E`证据可关闭本接口的完整实现门。
