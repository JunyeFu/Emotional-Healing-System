# 目标运行接口 v2

> 状态：`IMPLEMENTATION_BASELINE`

## 1. 模块和权威

```text
PLUX respiBAN BLE ----> Device Adapters ----> Python Session Core
Polar H10 ------------>       |                    |
                              |                    +--> immutable L0/L1 records
                              |                    +--> reliable control + ACK
                              |                    +--> UDP telemetry 20Hz
                              |                              |--> Unity participant product
                              |                              `--> TD operator console
                              `--> offline replay
```

Python Session Core是会话状态、单调时钟、条件、天气顺序、呼吸目标、信号质量、事件、累计状态和落盘的唯一权威。Unity是参与者体验的唯一渲染制品。TD只读监控，并且只能向Python提交人工标记或中止请求。

Unity不得依赖TD或Spout。TD退出、未安装或崩溃时，Unity核心体验和Python落盘继续运行。

## 2. 传输职责

| 传输 | 语义 | 要求 |
|---|---|---|
| 可靠控制通道 | `prepare/start/pause/abort/segment/module/end`与ACK | 有序、幂等、重连后补发；TCP端口在任务实现前按全局端口注册表登记 |
| UDP 5006 | Unity实时自包含遥测 | 20Hz；允许丢包；新帧覆盖旧帧 |
| UDP 5005 | TD实时自包含遥测 | 20Hz；只读；TD失联不影响主链 |
| 追加式文件 | 原始数据、事件、控制、ACK、渲染回执 | 每条带源时间、接收时间、单调时间、版本和完整性信息 |

已有UDP 5005/5006在 `D:\Agent\全局端口注册表.md` 中登记。可靠控制通道的实际TCP端口由首个合同任务先登记再实现，禁止直接复用未确认候选端口。

## 3. SessionManifest

启动前由Python生成并校验，至少包含：

```text
schema_version
session_id
study_phase
runtime_mode
cue_mode
weather_sequence[4]
module_durations
protocol_config_version
randomization_version
strategy_version|null
device_config
unity_build_hash
python_commit
td_build_hash|null
source_policy
created_utc
```

`formal_*`模式必须拒绝 `mock` 数据源、未知构建、缺失随机化或未冻结配置。开发与重放模式必须持续显示并记录非正式水印。

## 4. ControlEvent与ACK

每个控制事件包含：

```text
schema_version, session_id, event_id, control_seq,
event_type, issued_monotonic_ns, effective_monotonic_ns, payload
```

ACK包含 `event_id`、接收时间、应用时间、Unity帧号、结果和错误码。重复 `event_id` 不得重复推进状态。未收到ACK时Python重试；超过冻结上限进入降级或中止，不得静默继续。

## 5. TelemetryFrame

每帧至少包含：

```text
schema_version
session_id, frame_seq
source_monotonic_ns, sent_monotonic_ns
module_id, module_position, segment
target_phase, target_progress
actual_phase, actual_progress, actual_confidence
recovery_value, recovery_locked
signal_quality, fallback_state, fallback_reason
resp_device_state, ecg_device_state
cue_mode, runtime_mode
policy_decision_id|null
```

遥测帧必须自包含，接收方不得依赖上一帧补全当前语义。`calm_index`可保留在旧兼容适配器中，但不得控制正式条件、天气顺序、Gate结果或Unity四层接口。

## 6. Unity四层接口

Unity只向场景适配器公开：

```text
ApplyTarget(phase, progress)
ApplyActual(phase, progress, confidence)
ApplyRecovery(value, locked)
ApplyFallback(state, reason)
ResetModule(module_id, cue_mode)
```

所有场景复杂度隐藏在适配器实现内。`scene_native`由场景表达目标和实际相位；`abstract_pacer`由双环表达，天气仅保留匹配的背景与累计宏观变化，不编码相位。

## 7. 数据记录层

```text
L0: 设备原始包、设备时间、主机接收时间
L1: 同步帧、SQI、控制事件、ACK、渲染回执
L2: 呼吸事件与周期
L3: 模块和会话摘要
L4: 锁定分析数据集
```

L0只追加。人工修订以独立标注文件存在。L1至L4必须可由L0、manifest、配置和代码提交重建。

## 8. 降级

| 状态 | 目标提示 | 实际反馈 | 累计状态 | 记录 |
|---|---|---|---|---|
| `GOOD` | 继续 | 真实 | 更新 | 正常 |
| `DEGRADED` | 继续 | 降低置信或淡出 | 暂停或按冻结规则谨慎更新 | 原因码 |
| `UNUSABLE` | 继续开环 | 停止 | 暂停 | 不可用窗口 |
| `DISCONNECTED` | 安全开环或中止 | 停止 | 暂停 | 断流与重连 |

正式模式禁止自动切换Mock、伪造成功、平滑跨越长断流或为画面完整强制恢复。

## 9. 集成验收

- Unity在TD未启动时完成四模块自动体验；
- 30分钟真实设备双流稳定性测试通过；
- 控制事件重复发送不重复推进状态；
- 时钟偏差不高于50毫秒；端到端反馈延迟P95不高于200毫秒；
- 断开任一设备会进入对应降级且不切Mock；
- 每个控制事件、遥测帧抽样和渲染回执可按时间对齐；
- 同一L0重放生成一致的L2/L3语义结果；
- 正式模式对Mock、未知构建和未冻结配置失败关闭。
