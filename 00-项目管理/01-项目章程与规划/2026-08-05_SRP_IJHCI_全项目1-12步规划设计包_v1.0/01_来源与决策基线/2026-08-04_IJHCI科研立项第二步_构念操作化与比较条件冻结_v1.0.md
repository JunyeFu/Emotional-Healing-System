# 0. 本步骤冻结结论

第一篇 IJHCI 目标论文采用以下实验主线：

```text
同一参与者完成两个独立实验日
→ scene_native 场景原生提示
  与 abstract_pacer 统一抽象提示交叉比较
→ 两条件使用相同天气场景、呼吸协议、真实设备、
  累计恢复算法、声音和模块顺序
→ 只改变“目标节律与实时反馈的视觉信息载体”
→ 先检验 protocol_fidelity 非劣
→ 再检验提示—场景语义一致性优效
```

正式实验拟采用：

> **两实验日、参与者内、随机顺序、平衡交叉设计。** `[D]`

唯一主要结果链冻结为：

1. **Gate 1：`protocol_fidelity` 非劣性**；
2. **Gate 2：Scene–Cue Congruence Index（SCCI）优效性**。

Gate 2 只在 Gate 1 通过后进入确认性解释。

本步骤同时冻结：

- `scene_native` 和 `abstract_pacer` 的信息层级；
- 四模块的目标模板与周期判定框架；
- `protocol_fidelity` 的计算结构；
- 非劣界值的上限；
- SCCI 的初始条目；
- 次要构念及测量负担；
- 操纵检查；
- 三级预试与失败门；
- 初始统计模型；
- 正式实验前必须写入数据协议的字段。

# 1. 研究设计骨架

## 1.1 设计类型

采用**参与者内交叉设计**，每名参与者完成两个实验日：

| 实验日 | 条件 | 主体验 |
|---|---|---|
| Session A | `scene_native` 或 `abstract_pacer` | 四模块，共8分钟 |
| Session B | 另一条件 | 相同四模块，共8分钟 |

条件顺序采用：

```text
AB：scene_native → abstract_pacer
BA：abstract_pacer → scene_native
```

AB 与 BA 等量分配。

## 1.2 两实验日间隔

候选范围冻结为：

- 最短：48小时；
- 最长：7天；
- 同一参与者尽量在相同时间段完成，允许偏差不超过2小时。

理由：

- 避免同日连续体验导致疲劳、情绪残留和设备压迫不适；
- 保留参与者内比较以降低个体呼吸差异；
- 通过条件顺序平衡和模型中的 `session_index` 控制练习效应。

## 1.3 模块顺序

第一篇论文不承担24种顺序比较，因此正式比较采用**四序列 Williams 平衡**，而不是把24种完整排列全部作为实验单元。

每名参与者在两个实验日使用**相同模块顺序**，从而使同一模块处于相同位置，只改变提示方式。跨参与者平衡四种顺序，以控制：

- 模块位置；
- 一阶相邻转换；
- 疲劳与学习。

24种完整顺序探索继续保留在后续自适应编排研究中，不在第一篇中取消。

## 1.4 参与者行为边界

- 8分钟主体验内不进行键盘、鼠标、控制器或问卷操作；
- 参与者只需平坐、观看并跟随呼吸；
- 所有量表和访谈在主体验结束后完成；
- 正式主体验中不插入场景间评分。

# 2. 条件共同结构

两个条件都包含三条信息通道：

```text
通道T：Target Cue
系统要求参与者现在如何呼吸

通道A：Actual Feedback
真实设备检测到参与者实际上如何呼吸

通道C：Cumulative Recovery
截至当前的累计执行表现如何改变天气
```

## 2.1 两条件完全相同的内容

| 项目 | 冻结要求 |
|---|---|
| Unity场景 | 同一场景、相机、构图、角色、天气资产 |
| 显示设备 | 同一屏幕、分辨率、刷新率、观看距离 |
| 呼吸协议 | 同一模块使用同一目标模板 |
| 时间线 | 15秒示范 + 90秒闭环 + 15秒锁定转场 |
| 环境声音 | 完全一致，不提供呼吸阶段提示 |
| 真实设备 | 同一型号、位置、采样率和算法版本 |
| 信号质量 | 同一质量门和降级规则 |
| 实时控制 | 同一原始信号、滤波、时间同步和反馈延迟 |
| 累计恢复 | 同一公式、上限、平滑和锁定规则 |
| 训练说明 | 同一脚本、说明时长和练习次数上限 |
| 模块顺序 | 同一参与者两个实验日保持一致 |
| 问卷 | 同一版本和呈现顺序 |
| 日志 | 同一字段、精度和版本记录 |

## 2.2 唯一实验操纵

> **通道T和通道A的视觉承载方式。**

- `scene_native`：由天气场景自身的对象和运动表达；
- `abstract_pacer`：由统一、低语义、非叙事性的几何控件表达。

通道C在两个条件中都由相同天气恢复结果表达，避免把“有没有环境奖励”与提示方式混为一体。

# 3. `scene_native` 条件规格

## 3.1 通用设计语法

```text
目标模板 T(t)
→ 场景原生目标运动

实际呼吸 A(t)
→ 同一场景机制中的实际响应层

周期执行质量 Q(cycle)
→ 单次周期结束后的累计恢复增量

信号不可用
→ 目标运动继续
→ 实际响应停止或进入中性态
→ 不伪造闭环反馈
```

## 3.2 三层必须可区分

| 层 | 时间尺度 | 冻结要求 |
|---|---|---|
| 目标提示层 | 周期内连续变化 | 完全由协议决定，不受实际信号拖动 |
| 实际反馈层 | 周期内连续变化 | 只由真实设备驱动，允许与目标产生可见偏差 |
| 累计恢复层 | 完整周期后离散或缓慢更新 | 单调、平滑，不随吸呼来回震荡 |

若目标提示层被实际数据直接拖动，参与者将无法知道“应该怎么呼吸”；若累计天气随每次吸气和呼气往复，参与者将无法区分即时反馈和长期进展。

## 3.3 四模块映射冻结

### 风暴模块

| 信息 | 场景表达 |
|---|---|
| 目标吸气 | 保护罩从核心向外形成 |
| 目标吸气后停顿 | 保护罩维持张力和稳定 |
| 目标呼气 | 保护罩向外推开雨幕 |
| 目标呼气后停顿 | 修复纹理锁定，外界短时稳定 |
| 实际反馈 | 第二层边缘、亮度或形变跟随实际胸带相位 |
| 累计恢复 | 风雨、闪电和裂纹随有效周期缓慢衰减 |

### 炙烤模块

| 信息 | 场景表达 |
|---|---|
| 目标吸气 | 冷色气流在场景一侧蓄积 |
| 目标呼气 | 气流持续横向推进并带走热浪 |
| 实际反馈 | 气流的内层流速或宽度跟随实际呼吸 |
| 累计恢复 | 热浪扭曲、火星和高温色调逐周期衰减 |

### 暴雪模块

| 信息 | 场景表达 |
|---|---|
| 目标吸气 | 一段路径轮廓逐渐显现 |
| 目标呼气 | 下一段脚印或路径稳定落下 |
| 实际反馈 | 路径内层清晰度跟随实际呼吸相位 |
| 累计恢复 | 雪雾遮蔽和路径缺失逐周期减少 |

### 褪色模块

| 信息 | 场景表达 |
|---|---|
| 第一段吸气 | 色彩光点向中心汇聚 |
| 第二段补吸 | 新一层光点短促叠加 |
| 缓慢呼气 | 色彩向环境扩散 |
| 实际反馈 | 内层光点轨迹跟随实际呼吸结构 |
| 累计恢复 | 场景饱和度和可见色域逐周期增加 |

## 3.4 场景原生不等于“动画越多越好”

禁止：

- 同时使用多个互相竞争的节律控件；
- 用颜色、尺寸、粒子、角色动作同时表达同一阶段；
- 为追求美术完整而篡改真实反馈；
- 在参与者实际未完成周期时自动显示完全恢复；
- 在断流时继续展示看似真实的实际反馈。

# 4. `abstract_pacer` 条件规格

## 4.1 统一几何控件

抽象提示采用**双环几何节律器**，放置于画面下方中央的安全区域：

- 外环：目标呼吸模板；
- 内环：真实设备检测到的实际呼吸；
- 不使用天气语义、角色、图标或叙事文字；
- 闭环阶段不显示“吸气、停顿、呼气”等文字标签；
- 使用中性灰白视觉，不使用代表冷、热、风暴或恢复的颜色；
- 控件所占视觉角度和亮度在预试中固定。

## 4.2 外环目标运动

| 协议阶段 | 外环表现 |
|---|---|
| 吸气 | 半径连续扩大 |
| 吸气后停顿 | 半径保持不变 |
| 呼气 | 半径连续缩小 |
| 呼气后停顿 | 半径保持不变 |
| 循环叹息第一吸气 | 第一次连续扩大 |
| 循环叹息补吸 | 在当前半径基础上短促二次扩大 |
| 循环叹息呼气 | 连续缩小至起始半径 |

## 4.3 内环实际反馈

- 内环半径由标准化胸带信号驱动；
- 使用与场景原生条件完全相同的滤波、归一化、延迟和断流判断；
- 内环不得自动吸附到目标外环；
- 当信号质量不足时，内环淡出并进入明确中性状态；
- 外环继续提供开环目标节律。

## 4.4 场景元素在抽象条件中的处理

为避免两个条件变成“有场景动画”和“无场景动画”的比较：

- 四个场景及核心对象仍然存在；
- 核心对象保留低幅度、与呼吸无关的空闲动画；
- 核心对象不表达周期内目标相位或实时实际相位；
- 累计天气恢复仍由与原生条件相同的 `Q(cycle)` 更新；
- 抽象条件不得通过场景动画泄露目标节律。

## 4.5 等信息量原则

两个条件均提供：

1. 当前目标相位；
2. 当前实际相位；
3. 目标与实际偏差的可见性；
4. 完成周期后的累计进展；
5. 信号断流状态。

不同之处仅是这些信息是“场景内生”还是“几何外置”。

# 5. 主要结果：`protocol_fidelity`

## 5.1 信号处理链

```text
原始呼吸胸带波形
→ 时间同步
→ 去漂移与平滑
→ 信号质量判定
→ 吸气、呼气、停顿、补吸事件提取
→ 与目标模板对齐
→ 周期级结构与时序判定
→ cycle_valid
→ protocol_fidelity
```

BreathMetrics等工作证明，呼吸分析可以提取吸气、呼气、停顿、阶段持续时间、瞬时相位和周期变异，但本项目使用胸带而非鼻腔气流，因此不能直接把既有算法精度当成本项目精度，必须在本设备上重新做人工标注验证。 `[L][V]`

## 5.2 分析窗口

主要结果只使用：

```text
closed_loop：15–105秒
```

`demo` 与 `lock_transition`：

- 继续记录；
- 可用于适应和稳健性分析；
- 不进入主要 `protocol_fidelity`。

## 5.3 周期匹配

每个目标周期 `j` 与实际呼吸周期对齐，输出：

- `structure_ok_j`；
- `phase_duration_error_j`；
- `phase_onset_error_j`；
- `signal_quality_ok_j`；
- `cycle_valid_j`。

## 5.4 通用时序误差

定义：

```text
phase_duration_error_j
= Σ_k w_k × |d_actual(j,k) - d_target(k)|
  / Σ_k w_k × d_target(k)
```

其中：

- `k` 为协议阶段；
- `w_k` 初始均设为1；
- 风暴停顿阶段可在预试后提高权重，但不得在正式数据后调整。

候选周期有效规则：

```text
cycle_valid_j = 1，当且仅当：
1. signal_quality_ok_j = 1
2. structure_ok_j = 1
3. phase_duration_error_j ≤ 0.25
4. 总周期持续时间相对误差 ≤ 0.20
```

`0.25` 和 `0.20` 是预试起始阈值，不是假装来自统一行业标准。正式阈值必须经过人工标注、可执行性和专家评审；允许收紧，不允许在正式实验后放宽。 `[D][V]`

## 5.5 模块特定结构规则

### 风暴：`3-3-3-3`

周期结构：

```text
吸气 → 吸气后停顿 → 呼气 → 呼气后停顿
```

候选结构门：

- 四阶段顺序完整；
- 两个停顿都被检测；
- 每个停顿至少覆盖目标停顿时长的60%；
- 不允许把停顿误识别为极慢吸气或呼气。

### 炙烤：`4-6`

周期结构：

```text
吸气 → 呼气
```

候选结构门：

- 呼气时长大于吸气时长；
- 实际吸呼比位于预试冻结范围；
- 不要求精确达到单一比例点，而使用可接受区间。

候选初始区间：

```text
吸气：3–5秒
呼气：5–7.5秒
```

### 暴雪：`5-5`

周期结构：

```text
吸气 → 呼气
```

候选结构门：

- 吸呼顺序完整；
- 吸气与呼气持续时间差不超过目标周期的20%；
- 周期总时长位于预试冻结范围。

候选初始区间：

```text
吸气：4–6秒
呼气：4–6秒
```

### 褪色：循环叹息

周期结构：

```text
第一吸气 → 较短补吸 → 缓慢完整呼气
```

候选结构门：

- 检测到两个连续吸气子峰；
- 两个吸气子峰之间没有完整呼气；
- 补吸短于第一吸气；
- 随后呼气长于任一单独吸气；
- 90秒内达到预试冻结的最低有效尝试数。

循环叹息没有被现有项目定义为固定秒数协议，因此本步骤不伪造单一精确模板。其最终时间包络必须通过舒适性预试和胸带可检测性冻结。

## 5.6 主要比例

参与者 `i`、条件 `c`、模块 `m`：

```text
PF_i,c,m
= Σ cycle_valid
  / Σ analyzable_cycle
```

总体条件结果：

```text
PF_i,c
= 四个模块有效周期数之和
  / 四个模块可分析周期数之和
```

为避免参与者通过极少呼吸周期获得虚高比例，还必须报告：

- `valid_cycle_count`；
- `total_cycle_count`；
- `target_cycle_completion_rate`；
- 各模块有效数据时长。

## 5.7 非劣界值

正式主张采用绝对比例差：

```text
D = PF_scene_native - PF_abstract
```

本步骤将最大可接受损失上限冻结为：

```text
Δ_NI = 0.10
```

通过条件：

```text
D 的单侧97.5%置信区间下限 > -0.10
```

解释：

- 90秒模块通常包含约7–9个周期；
- 10个百分点约对应每模块少于1个有效周期；
- 超过该损失将被视为具有实际意义，而不能用“体验更好”抵消。

该界值属于工程与HCI最小重要差异决定，不是严肃健康应用标准。正式实验前必须由专家组和预试确认；若证据认为10个百分点过宽，只能收紧，不能放宽。 `[D][V]`

# 6. 第二道结果：Scene–Cue Congruence Index

## 6.1 构念定义

**提示—场景语义一致性**指参与者感知到的：

> 呼吸指导、实际反馈和环境变化在意义、运动和体验上是否构成一个统一、合理而非彼此割裂的系统。

它不等同于：

- 喜欢程度；
- 美术质量；
- 临场感；
- 易用性；
- 呼吸准确率。

## 6.2 研究专用SCCI-5初始条目

使用7点同意度：

```text
1 = 完全不同意
7 = 完全同意
```

初始中文条目：

1. **呼吸引导感觉是这个场景自然的一部分。**
2. **视觉变化与我被要求跟随的呼吸阶段相匹配。**
3. **系统对我实际呼吸的反馈与场景含义相协调。**
4. **呼吸引导和环境变化像一个统一的体验，而不是两个分开的部分。**
5. **呼吸与视觉反馈之间的对应关系对我来说是合理的。**

计分：

```text
SCCI = 5个条目的平均值
```

条目不包含“场景原生一定更好”等诱导性语言，两个条件均可回答。

## 6.3 SCCI使用边界

- SCCI是**本研究专用复合指标**；
- 不将其宣传为已完成跨场景验证的通用量表；
- 只承担本研究H1b；
- 论文应公开条目生成、专家审查、认知访谈和可靠性结果；
- 如结构不稳定，则降为探索结果，不强行维持H1b。

## 6.4 内容效度门

由6–8名专家评价每条目的：

- 相关性；
- 清晰度；
- 构念覆盖；
- 条件中立性。

通过标准：

```text
I-CVI ≥ 0.78
S-CVI/Ave ≥ 0.90
```

必须明确报告采用的是平均法 `S-CVI/Ave`，不能只写模糊的“S-CVI”。 `[L]`

## 6.5 认知访谈门

8–12名目标参与者完成：

- 逐项释义；
- 为什么选择该评分；
- 是否把“语义一致性”误解为“画面好看”；
- 是否能区分目标提示、实际反馈和累计恢复。

任一条目若超过20%的参与者产生同类误解，必须改写。

## 6.6 可靠性门

预试中：

- 报告 McDonald’s `ω`；
- `ω ≥ 0.70` 为最低保留标准；
- 检查项目—总分相关；
- 不因删除条目能提高少量系数而盲目删题；
- 正式实验前冻结最终条目。

# 7. 次要结果与测量工具

## 7.1 负性情绪

继续使用项目已确认的中文版20项PANAS：

- 每个实验日前测一次、后测一次；
- 使用一致的“此刻”时间框架；
- NA为主要量表构念，但在本篇提示方式论文中属于**次要结果**；
- PA作为补充结果；
- 不把PA与NA相减形成总分。

候选模型：

```text
NA_post
~ NA_pre
+ cue_mode
+ session_index
+ cue_order
+ (1 | participant)
```

具体中文版、条目来源、许可和计分脚本仍需在伦理提交前锁定。

## 7.2 用户投入

使用 **User Engagement Scale–Short Form（UES-SF）**：

- 12项；
- 4个维度；
- 每个实验日体验后填写一次；
- 按原作者建议计分；
- 不自行改写成“疗愈投入度量表”。

若测量负担过高，可以在预试后仅保留原量表中理论相关的完整子量表，但必须在正式预注册前决定，不能在结果后筛选。

## 7.3 心智努力

使用 Paas 单项9点评分：

> “在刚才的体验中，我投入了多少心智努力？”

```text
1 = 非常非常低
9 = 非常非常高
```

该指标用于比较理解和跟随提示所需的总体心智努力，不把它解释为多维NASA-TLX的等价替代。

## 7.4 舒适性与不适

研究专用3项，7点评分：

1. 跟随这种呼吸引导对我来说是舒适的；
2. 视觉提示没有让我感到压迫或不适；
3. 我可以在不明显勉强自己的情况下完成这种呼吸。

同时记录：

- 头晕；
- 胸闷；
- 呼吸困难；
- 恶心；
- 明显焦虑；
- 提前停止；
- 其他不适。

不适事件不是普通缺失值，必须进入安全日志。

## 7.5 模块级探索评分

主体验结束后，以四个场景缩略图辅助回忆，每模块仅回答一项：

> “这个场景中的呼吸引导与场景的含义和运动相匹配。”

7点评分。

该单项只用于探索模块差异，不承担H1b总体确认性结论。

## 7.6 定性访谈

第二实验日结束后，从正式样本中选取16–24人进行最大差异取样访谈，平衡：

- cue mode偏好；
- 高/低 `protocol_fidelity`；
- 高/低 SCCI；
- 是否出现理解困难。

核心问题：

1. 你从哪里看出应该吸气、停顿或呼气？
2. 你如何判断画面是在告诉你目标，还是在反馈你的实际呼吸？
3. 哪个场景最容易理解？为什么？
4. 哪个场景最容易混淆？为什么？
5. 抽象提示和场景提示分别让你把注意力放在哪里？
6. 哪些变化感觉自然，哪些像附加控件？
7. 如果保留一种方式，你会选择哪一种，理由是什么？

定性结果用于解释机制和提炼设计原则，不替代主要统计检验。

# 8. 操纵检查

## 8.1 条件识别

每个实验日结束后回答：

1. “呼吸指导感觉主要来自场景本身。”
2. “我注意到一个独立于场景的节律控件。”

预期：

- `scene_native`：第1项高、第2项低；
- `abstract_pacer`：第1项低、第2项高。

如果两条件在操纵检查上没有清晰分离，正式实验不能解释为“原生与抽象提示比较”。

## 8.2 三层理解检查

参与者需要能分别说明：

- 目标提示是什么；
- 实际反馈是什么；
- 累计恢复是什么。

预试中使用开放回答，由两名编码者独立判断。

通过标准：

- 至少80%参与者在第一次示范后正确区分；
- 至少95%参与者在一次重复说明后正确区分。

## 8.3 协议理解

预试中，每个模块示范后要求参与者口头复述目标结构。

例如：

- 风暴：吸气—停顿—呼气—停顿；
- 褪色：吸气—补吸—慢呼气。

不能仅用“我理解了”自评代替结构复述。

# 10. 预试分级

## Level A：专家与内容审查

### 对象

6–8名专家，至少覆盖：

- HCI/交互设计；
- 视觉或数字媒体设计；
- 软件与实时系统；
- 呼吸生理或心理测量。

### 任务

- 审查两条件是否等信息量；
- 审查四模块映射是否能传递协议；
- 审查SCCI条目；
- 审查10个百分点非劣界值；
- 审查安全与停止规则。

### 通过门

- SCCI达到内容效度标准；
- 没有专家指出明显条件混杂；
- 非劣界值未被多数专家判定为过宽；
- 四模块均有明确目标、实际和累计层。

## Level B：认知与可理解性预试

### 对象

8–12名目标大学生。

### 任务

- 体验短版示范；
- 口头复述协议；
- 区分三层信息；
- 完成SCCI认知访谈；
- 报告视觉和呼吸不适。

### 通过门

- 首次示范协议复述正确率≥80%；
- 一次重复后≥95%；
- 三层区分达到同样标准；
- 无系统性误解；
- 不适退出率<10%。

## Level C：真实设备交叉技术预试

### 对象

16–24名新参与者，不进入正式确认性样本。

### 设计

- 完成两个条件；
- 使用正式设备和完整120秒模块；
- 使用候选正式日志与问卷。

### 技术门

| 项目 | 最低要求 |
|---|---:|
| 原始日志完整率 | ≥99% |
| Unity/Python关键事件时间偏差 | ≤50 ms |
| 实际反馈端到端延迟P95 | ≤200 ms |
| closed_loop降级时长中位比例 | ≤5% |
| 吸气/呼气事件人工标注F1 | ≥0.90 |
| 停顿/双吸结构人工标注F1 | ≥0.80 |
| 关键事件时间MAE | 动态阶段≤250 ms；复杂结构≤400 ms |
| SCCI McDonald’s ω | ≥0.70 |
| 重大不适事件 | 0 |
| 因呼吸不适退出 | <10% |

### 分布门

抽象提示总体 `protocol_fidelity`：

- 若 >0.95：存在明显天花板，应收紧判定或提高辨识要求；
- 若 <0.65：任务、说明或设备算法可能不可用；
- 理想预试范围：0.70–0.90。

场景原生条件若比抽象条件低超过15个百分点，先判定为设计重构问题，不直接进入正式非劣实验。

# 11. 初始统计模型

## 11.1 Gate 1：非劣性

周期级广义线性混合模型：

```text
cycle_valid
~ cue_mode
+ module
+ session_index
+ cue_order
+ module_order_position
+ cue_mode:module
+ (1 + cue_mode | participant)
```

分布：

```text
binomial / logit
```

模型估计后计算标准化边际比例：

```text
PF_scene_native
PF_abstract
D = PF_scene_native - PF_abstract
```

通过：

```text
D的单侧97.5%置信区间下限 > -0.10
```

同时报告：

- 参与者级比例；
- 模块级比例；
- 有效周期数；
- 数据质量；
- 全样本与协议完整样本敏感性分析。

不能把“差异不显著”解释为非劣。

## 11.2 Gate 2：SCCI优效

线性混合模型：

```text
SCCI
~ cue_mode
+ session_index
+ cue_order
+ module_order_sequence
+ (1 | participant)
```

若SCCI只在Session级测量，则不加入 `module`。

确认性检验只在Gate 1通过后进行，使用双侧 `alpha = 0.05`，报告均值差、标准化效应和95%置信区间。

## 11.3 次要模型

### 心智努力、UES-SF与舒适度

```text
outcome
~ cue_mode
+ session_index
+ cue_order
+ (1 | participant)
```

### PANAS-NA

```text
NA_post
~ NA_pre
+ cue_mode
+ session_index
+ cue_order
+ (1 | participant)
```

### 模块差异

```text
cycle_valid
~ cue_mode * module
+ session_index
+ order_position
+ (1 + cue_mode | participant)
```

模块交互属于次要分析；若样本量不足，只报告估计与区间，不做四模块逐项显著性排行榜。

## 11.4 缺失与降级

- 不用Mock补齐正式缺失；
- 原始信号不可用时标记 `analysis_eligible = 0`；
- 主要模型按预注册质量门处理；
- 同时报告全会话、可分析窗口和降级比例；
- 不因结果不理想而临时删除某个模块或参与者。

# 14. 失败模式与应对

| 失败模式 | 判断 | 处理 |
|---|---|---|
| 原生提示准确率明显低 | 功能底线失败 | 重做场景节律，不用体验评分掩盖 |
| 抽象提示泄露到场景语义 | 操纵污染 | 重做抽象条件 |
| 两条件运动量差异过大 | 视觉复杂度混杂 | 调整空闲动画和显著性 |
| 参与者无法区分目标与实际 | 框架语法失败 | 重构视觉层 |
| 循环叹息胸带不可识别 | Oracle失败 | 更换传感器/算法或调整模块协议 |
| SCCI只测到“喜欢” | 构念失败 | 改写条目并重新认知访谈 |
| 抽象条件天花板 | 非劣实验失去分辨力 | 收紧周期规则或改进任务 |
| 两实验日练习效应明显 | 交叉设计偏差 | 保留顺序平衡并检查交互 |
| 降级过多 | 工程证据不足 | 先修复真实设备链路 |
| PANAS共同下降但条件无差异 | 共同时间效应 | 不归因于提示方式 |
| 原生提示非劣但SCCI不提高 | 仅证明可替代 | 不声称设计增益 |
| SCCI提高但非劣失败 | 美术吸引但引导失效 | 主框架不成立 |
