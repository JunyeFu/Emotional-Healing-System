# 0. 本次冻结结果

本次立项将第一篇 IJHCI 论文的研究对象收束为：

> **场景原生呼吸引导（scene-native breathing guidance）作为一种交互提示机制，是否能够在不同结构的呼吸协议中维持可靠的协议执行质量，并相对于统一抽象节律提示提高提示—场景语义一致性。**

冻结后的**唯一主要经验主张**为：

> **与统一抽象节律提示相比，场景原生呼吸引导在呼吸协议执行质量上达到预先定义的非劣标准；在该功能底线成立后，场景原生引导提高提示—场景语义一致性。** `[D]`

该主张是一个**门控式复合主张**：

1. **Gate 1：功能有效性**  
   场景原生提示不能显著损害参与者对目标呼吸协议的执行。
2. **Gate 2：设计增益**  
   只有 Gate 1 通过后，才确认其是否相对抽象提示提高语义一致性。

这避免了“画面更受喜欢，但实际无法正确引导呼吸”的无效设计结论。

# 1. 来源同步与不可变项目边界

## 1.1 当前产品边界 `[P]`

第一篇论文必须建立在以下已确认项目事实之上：

- 参与者全程平坐观看屏幕并跟随呼吸，不使用键盘、鼠标、控制器或手部选择。
- Unity 独立完成参与者侧完整体验，不依赖 TouchDesigner 才能运行。
- Python 负责真实设备采集、时间同步、信号质量、特征计算、闭环控制与日志。
- TouchDesigner 仅承担实验员侧监控、记录、质量提示和研究可视化。
- 正式实验使用真实生理采集设备；Mock 只允许用于开发联调和故障测试。
- 参与者侧不使用跨天气统一呼吸圈；四个场景的原生视觉机制承担目标提示和实际反馈。
- 每个模块统一为 120 秒：
  - `demo`：0–15 s；
  - `closed_loop`：15–105 s；
  - `lock_transition`：105–120 s。
- 四个模块共 8 分钟主体验。
- 量表结果与设备过程数据分别建模，不合成为单一“疗愈总分”。

## 1.2 四个固定天气—呼吸复合模块 `[P]`

| 模块 | 呼吸流程基线 | 场景原生机制 | 主要可测结构 |
|---|---|---|---|
| 风暴 | `3-3-3-3` 四阶段箱式流程 | 保护罩形成、稳定、排开风雨、锁定修复 | 四阶段识别、停顿保持、周期误差 |
| 炙烤 | `4-6` 延长呼气 | 冷色气流蓄积与推进、热浪衰减 | 吸呼比、呼气时长、周期误差 |
| 暴雪 | `5-5` 等时慢呼吸 | 脚印与路径显现、雪雾降低 | 对称误差、周期稳定性、相位同步 |
| 褪色 | 循环叹息 | 两段吸气汇聚色彩、长呼气扩散色彩 | 双吸峰、补吸间隔、呼气完整度 |

固定配对意味着第一篇论文研究的是四个**天气—呼吸复合模块**，不能把差异分别归因为某种天气或某种呼吸法的独立作用。

## 1.3 不改变的大方向 `[P][D]`

原项目后续仍保留：

```text
24 种完整顺序均衡随机探索
→ 位置与转换规律分析
→ 可解释策略学习与冻结
→ 新参与者中比较冻结策略与均衡随机顺序
```

第一篇论文的作用是先验证这些可编排模块的**基础交互接口是否成立**。  
这属于研究阶段重排，不是删除自适应编排方向。

# 3. 问题定义

## 3.1 现象

传统呼吸节律指导通常通过圆环、条形、波形、数字或其他抽象控件表达节奏。这类界面能够清楚传达时序，但可能与环境叙事割裂。沉浸式或环境式生物反馈研究尝试将反馈嵌入自然场景、光线或声音中，以提高参与和意义感。 `[L]`

本项目进一步面临一个尚未被直接回答的问题：

> 当呼吸协议不再只有简单的等时吸呼，而同时包含四阶段停顿、非对称吸呼、对称慢呼吸和双吸—长呼气时，场景自身的视觉机制能否承担清晰、可靠且可复用的节律提示？

## 3.2 核心矛盾

场景原生提示可能带来：

- 更高的提示—场景语义一致性；
- 更少的 HUD 割裂；
- 更连续的视觉体验；
- 更强的环境参与感。

但也可能造成：

- 呼吸阶段边界不清楚；
- 对停顿或补吸的误判；
- 美术变化遮蔽节律信息；
- 不同场景之间提示规则不一致；
- 体验更好但任务执行更差。

因此，第一篇论文不能先假设其“更有效”，而必须先检验其是否在基本引导功能上可成立。

# 5. 唯一主要研究问题与研究假设

## 5.1 唯一主要研究问题 RQ1

> **RQ1：与统一抽象节律提示相比，场景原生呼吸引导能否在不同呼吸协议中维持非劣的协议执行质量，并在此基础上提高提示—场景语义一致性？**

## 5.2 门控式主要假设

### H1a：功能非劣假设

> 场景原生提示相对于抽象提示，在 `protocol_fidelity` 上不低于预先冻结的非劣界值。

说明：

- `H1a` 是第一道确认门；
- 非劣界值尚未在本步骤中数值化；
- 界值必须在正式实验前通过文献、专家判断、预试与功效分析冻结；
- 不能在看到正式结果后调整。

### H1b：语义一致性优效假设

> 在 H1a 通过后，场景原生提示的提示—场景语义一致性高于抽象提示。

`H1b` 只有在 H1a 通过后才承担确认性解释；否则只能作为探索结果。

## 5.3 次要研究问题

- **RQ2**：两种提示方式在可理解性、认知负荷、投入感和舒适度上有何差异？
- **RQ3**：提示方式与四种复合模块之间是否存在交互，即哪些呼吸结构更适合场景原生表达？
- **RQ4**：呼吸执行过程指标与参与后负性情绪之间存在何种预设关联？
- **RQ5**：参与者如何区分“目标节律提示”“自身执行反馈”和“累计天气恢复”？

RQ2–RQ5 不与 RQ1 竞争唯一主要检验地位。

# 6. 实验条件的操作定义

## 6.1 `scene_native`

场景原生提示条件：

```text
目标呼吸协议
→ 场景自身的节律动画
实际呼吸数据
→ 场景自身的周期级反馈
累计执行表现
→ 天气恢复进程
信号质量不足
→ 场景自身的开环或中性降级
```

具体载体：

- 风暴：保护罩与风雨系统；
- 炙烤：冷却气流与热浪系统；
- 暴雪：脚印、路径与雪雾系统；
- 褪色：色彩汇聚、扩散与饱和度系统。

## 6.2 `abstract_pacer`

研究专用统一抽象提示条件：

- 使用相同显示设备和相同 Unity 场景；
- 使用统一抽象节律控件表达目标呼吸阶段；
- 控件可采用圆环、条带或其他低语义视觉形式；
- 不作为最终产品必要界面；
- 仅用于隔离“信息载体”这一设计变量。

## 6.3 两条件必须保持相同的内容

| 必须保持一致 | 原因 |
|---|---|
| 四个天气场景及美术资产 | 避免把天气或画面差异误当成提示差异 |
| 呼吸协议和时长 | 避免任务难度差异 |
| 音频与环境声 | 避免听觉线索混杂 |
| 显示设备、分辨率与观看距离 | 避免呈现介质混杂 |
| 真实设备及算法 | 避免感知精度差异 |
| 累计天气恢复算法 | 避免奖励机制差异 |
| 模块顺序与平衡协议 | 避免顺序偏差 |
| 说明文本与练习量 | 避免教学差异 |
| 数据质量和降级规则 | 避免异常处理差异 |

## 6.4 唯一计划改变的变量

> **目标节律与实时反馈的视觉信息载体：场景原生机制 vs 统一抽象控件。**

若实际实现中同时改变声音、天气强度、设备算法或恢复速度，则本主张失去可识别性。

# 7. 构念—数据—结论映射

## 7.1 唯一主要设备结果：`protocol_fidelity`

定义框架：

```text
protocol_fidelity
= 满足模块预注册时序容差的有效呼吸周期数
  / 可分析的有效呼吸周期数
```

各模块的有效周期判定应分别包括：

| 模块 | 必须包含的判定维度 |
|---|---|
| 风暴 | 四阶段顺序、阶段时长、两次停顿保持、总周期误差 |
| 炙烤 | 吸气时长、呼气时长、实际吸呼比、总周期误差 |
| 暴雪 | 吸呼对称误差、周期稳定性、目标相位偏差 |
| 褪色 | 双吸峰检出、补吸间隔、长呼气完整度、结构顺序 |

本步骤只冻结**指标角色和结构**，不冻结数值容差。

## 7.2 关键次要结果

| 构念 | 建议数据 | 解释作用 |
|---|---|---|
| 提示—场景语义一致性 | 经内容验证的多题项量表 | H1b 关键结果 |
| 提示可理解性 | 量表 + 访谈 + 示范后复述 | 判断是否能理解阶段语义 |
| 认知负荷 | 简短负荷量表 | 判断原生设计是否增加解码成本 |
| 投入感/临场参与 | 经验证的简短量表 | 评价体验增益 |
| 舒适度 | 量表 + 不适事件 | 安全与可接受性 |
| 负性情绪 | 中文版 PANAS-NA 前后测 | 会话级次要结果 |
| 信号可用性 | 有效数据比例、降级时长 | 判断工程与数据质量 |
| 心电过程 | HR、`lnRMSSD`、耦合等 | 过程解释，不替代主要结果 |

## 7.3 禁止合成

以下内容不得加权合成为单一“疗愈分数”：

- `protocol_fidelity`；
- PANAS；
- HRV；
- 主观喜欢；
- 运行时 `calm_index`；
- 信号质量。

它们属于不同构念、不同时间尺度和不同分析单位。

# 8. 预期论文贡献

## Contribution 1：场景原生呼吸引导框架

提出一个跨不同呼吸结构的映射语法：

```text
目标阶段
→ 原生节律提示
→ 实际执行反馈
→ 累计环境变化
→ 数据质量降级
```

贡献不在于“制作四个天气”，而在于说明：

- 哪些生理时序信息必须显式表达；
- 哪些视觉变化适合周期反馈；
- 哪些变化适合累计恢复；
- 如何在不使用通用 HUD 的情况下保持跨场景一致性；
- 如何在数据质量不足时避免伪造闭环。

## Contribution 2：可运行、可审计的真实设备闭环系统

系统贡献包括：

- 真实呼吸与心电设备接入；
- Unity 独立体验；
- Python 统一时钟、信号质量和事件记录；
- 周期级反馈和累计恢复分离；
- 降级状态记录；
- 可供离线复核的输入、输出和版本信息。

这些工程内容支撑贡献，但只有当其实现并验证上述新交互机制时，才具有论文意义。

## Contribution 3：受控证据与可迁移设计原则

通过严格控制呈现介质和场景内容，检验：

- 原生提示是否保持功能；
- 哪些呼吸结构更难场景化；
- 语义一致性是否获得增益；
- 设计收益是否以额外认知负荷为代价；
- 用户如何区分提示、反馈与累计变化。

最终输出应为可被其他呼吸训练、具身交互和环境生物反馈系统复用的设计原则。

# 9. 最接近工作对照

## 9.1 Closest Work A：Blum 等，2019

**题目**：*Heart Rate Variability Biofeedback Based on Slow-Paced Breathing With Immersive Virtual Reality Nature Scenery*  
**DOI**：10.3389/fpsyg.2019.02172  
**设计**：60 名健康参与者；标准抽象 HRV 生物反馈 vs 虚拟自然环境生物反馈。  
**主要结果**：两种条件的生物反馈表现相近；虚拟环境在部分体验、注意和自我效能指标上更好。 `[L]`

**与本项目的重叠**：

- 将生理反馈嵌入环境；
- 比较环境式与抽象式反馈；
- 同时测量功能表现与体验。

**本项目必须超越之处**：

1. 该研究主要使用单一慢呼吸结构；
2. 两条件的呈现设备不同，存在 HMD 与普通屏幕混杂；
3. 未提出跨多种呼吸结构的场景原生映射框架；
4. 本项目应在相同 Unity、相同显示设备、相同场景中只改变提示载体。

## 9.2 Closest Work B：VeatherReflect，DIS 2023

**题目**：*VeatherReflect: Employing Weather as Qualitative Representation of Stress Data in Virtual Reality*  
**DOI**：10.1145/3563657.3596125  
**设计**：使用天气隐喻呈现压力数据，并与标准可视化比较。  
**主要结果**：天气隐喻提高参与者对个人压力数据的投入和压力觉察，并形成设计建议。 `[L]`

**与本项目的重叠**：

- 使用天气隐喻；
- 处理压力与福祉相关数据；
- 与标准表示进行比较。

**本项目必须超越之处**：

1. VeatherReflect 主要支持数据反思，不负责实时呼吸协议指导；
2. 本项目将天气机制用于目标节律、实际执行和累计恢复三重映射；
3. 本项目需验证具体呼吸行为，而不仅是参与和觉察。

## 9.3 Closest Work C：RESonance，2018

**题目**：*RESonance: Lightweight, Room-Scale Audio-Visual Biofeedback for Immersive Relaxation Training*  
**DOI**：10.1109/ACCESS.2018.2853406  
**设计**：通过环境光和自然声景表达呼吸与 HRV；24 人用户研究。  
**主要结果**：系统支持呼吸调节，并提供较强的沉浸与参与体验。 `[L]`

**与本项目的重叠**：

- 环境媒介表达生理信息；
- 强调自然映射与沉浸体验；
- 同时考虑呼吸与 HRV。

**本项目必须超越之处**：

1. 不能只证明单个环境系统可用；
2. 需提出跨四种不同呼吸结构的统一设计语法；
3. 需设置控制严格的抽象提示基准；
4. 需将目标提示、真实反馈和累计变化明确分层。

## 9.4 Closest Work D：BreathVR，CHI 2018

**题目**：*BreathVR: Leveraging Breathing as a Directly Controlled Interface for Virtual Reality Games*  
**DOI**：10.1145/3173574.3173914  
**设计**：将不同呼吸动作作为 VR 游戏直接输入；16 人研究。  
**主要结果**：呼吸输入提高临场感、趣味性和挑战感，并形成设计策略。 `[L]`

**与本项目的重叠**：

- 呼吸作为无手部交互输入；
- 将呼吸映射为虚拟环境变化；
- 输出设计策略。

**本项目必须超越之处**：

1. BreathVR关注主动游戏输入，不是规范呼吸节律的指导；
2. 本项目需要检验协议执行准确性；
3. 本项目处理实时提示、反馈、累计恢复和降级；
4. 本项目面向短时情绪调节体验而非游戏动作。

## 9.5 理论锚点：Slovák 等，2023

**题目**：*Designing for Emotion Regulation Interventions: An Agenda for HCI Theory and Research*  
**DOI**：10.1145/3569898  
该工作要求 HCI 情绪调节技术明确区分：

- 心理目标；
- 技术支持的干预机制；
- 具体实现方式。 `[L]`

本项目据此固定：

- **目标**：支持短时状态调节与呼吸执行；
- **机制**：节律呼吸、实时反馈和环境恢复；
- **实现**：场景原生提示与真实设备闭环。

# 10. 新颖性定位

本项目不能声称以下元素本身新颖：

- 天气隐喻；
- 呼吸驱动画面；
- 虚拟自然环境；
- 生理信号实时反馈；
- 抽象提示与沉浸提示比较；
- 用 Unity 实现闭环系统。

候选新颖性应定位为：

> **一种跨异质呼吸协议的场景原生引导框架，明确分离目标节律、实际执行、累计环境变化和信号降级，并在相同场景与呈现介质下通过抽象提示基准验证其功能底线与设计增益。**

新颖性依赖以下四个条件同时成立：

1. 四种呼吸结构确实存在不同的提示需求；
2. 映射语法能够跨模块复用，而不是四套无关动画；
3. 研究对照只改变提示载体；
4. 结果能够提炼出超出本地场景的设计知识。

---

# 11. 可证伪条件

以下任一结果都可能推翻或削弱主张：

| 结果 | 对主张的影响 |
|---|---|
| 场景原生提示未达到 `protocol_fidelity` 非劣标准 | 主框架未满足功能底线 |
| 原生提示显著增加理解错误或认知负荷 | 设计需要重构 |
| 语义一致性没有差异 | 不支持体验增益部分 |
| 只有个别模块有效 | 框架跨协议可迁移性不足 |
| 设备数据大量不可用或降级比例过高 | 实证结果不可靠 |
| 提示条件同时改变其他变量 | 无法归因于提示载体 |
| 参与者无法区分目标提示和自身反馈 | 三层映射语法失效 |
| 结果仅表现为“更喜欢画面” | 不能支撑引导框架贡献 |

允许发表的负面结果形式：

- 明确指出哪些呼吸结构不适合原生化；
- 描述语义一致性与执行准确性之间的权衡；
- 提出失败映射类型和修正原则；
- 证明抽象提示在某些结构中具有不可替代优势。

因此，本项目不是以“必须证明原生提示更好”为成立条件。

---

# 12. 结论边界

## 可以支持的结论

在相应结果成立时，可以说：

- 场景原生机制可以承担多种结构呼吸协议的节律提示；
- 在本研究条件下，其协议执行质量不劣于抽象提示；
- 场景原生提示提高了提示—场景语义一致性；
- 某些模块或结构更适合原生视觉映射；
- 提炼出的映射原则可供类似环境生物反馈设计参考。

## 不可以支持的结论

- 本项目能够缓解焦虑、抑郁或其他健康状况；
- 四种天气分别具有独立效果；
- 四种呼吸法具有独立优劣；
- 场景原生提示在所有人群和所有时长中都更有效；
- 前后 PANAS 变化完全由本系统导致；
- HRV变化等同于情绪改善；
- 运行时综合指标是真实情绪；
- 第一篇实验已经证明自适应编排优于随机顺序。

# 13. Minimum Publishable Unit（最小可发表单元）

第一篇 IJHCI 论文必须至少完成：

1. 场景原生映射框架的正式定义；
2. 四个复合模块的原生提示原型；
3. 研究专用抽象提示基准；
4. 相同呈现介质下的受控条件比较；
5. 真实设备采集与信号质量记录；
6. `protocol_fidelity` 的预注册定义；
7. 功效分析和正式样本；
8. 随机化或顺序平衡；
9. 客观执行结果；
10. 语义一致性和少量关键体验结果；
11. 访谈或开放式证据解释设计机制；
12. 效应量、区间、缺失与降级报告；
13. 可迁移设计原则；
14. 不越界的结论。

以下版本不达到最小发表单元：

- 四个场景展示 + 满意度问卷；
- 只有参与前后 PANAS；
- 只有 8–12 人可用性测试；
- 只报告生理曲线变化；
- 没有抽象提示或其他合理基准；
- 使用 Mock 数据完成正式实验；
- 没有信号质量和降级记录。

| **Oracle Kill-Test** | `protocol_fidelity` 可以作为行为真值近似，但模块容差尚未冻结 | **REVISE REQUIRED** |
| **Runner Kill-Test** | Unity、Python、TD职责明确，可形成可运行实验系统；旧 Spout 和旧呼吸方案需重构 | **PASS WITH REFACTOR** |
| **Comparator Kill-Test** | `abstract_pacer` 能隔离提示载体，但具体视觉形式与等信息量规则未冻结 | **REVISE REQUIRED** |
| **Causal Scope Kill-Test** | 条件可只改变提示载体，允许对该交互机制做有限因果解释 | **PASS** |
| **Population Kill-Test** | 普通大学生目标清楚，不外推严肃健康应用效果 | **PASS** |
| **Minimum Publishable Unit Kill-Test** | 缩减后第一篇可在不删除后续编排主线的情况下独立成立 | **PASS** |
| **Journal Fit Kill-Test** | 符合 IJHCI 的交互系统、人因、健康与实证研究范围 | **PASS** |

# 17. 暂定论文题目、摘要主线和关键词

## 17.1 暂定中文题目

> **场景原生呼吸引导：嵌入交互天气环境的生理节律提示设计与评估**

## 17.2 暂定英文题目

> **Scene-Native Breathing Guidance: Designing and Evaluating Physiological Pacing Embedded in Interactive Weather Environments**

## 17.3 摘要主线骨架

```text
背景：
抽象呼吸节律控件能够清楚传达节奏，但可能与交互环境割裂；
环境式生物反馈更具意义和参与感，但其跨复杂呼吸协议的功能可靠性尚不清楚。

方法：
提出场景原生呼吸引导框架；
在四个天气—呼吸复合模块中实例化；
构建真实设备闭环系统；
在相同场景与呈现介质中比较场景原生提示和统一抽象提示。

主要检验：
场景原生提示在协议执行质量上是否达到非劣；
通过后检验提示—场景语义一致性是否提高。

结果：
报告协议执行、模块差异、体验结果、信号质量和定性解释。

贡献：
跨协议映射框架；
可运行闭环系统；
可迁移设计原则和失败边界。
```
