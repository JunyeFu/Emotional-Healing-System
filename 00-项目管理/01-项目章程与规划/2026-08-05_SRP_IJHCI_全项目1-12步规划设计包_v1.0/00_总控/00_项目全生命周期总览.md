# 项目全生命周期总览

## 1. 项目定位

本项目不是四个独立的美术场景，也不是单纯的呼吸训练工具。其目标是形成：

```text
场景原生呼吸引导框架
+ 真实设备闭环系统
+ 可解释、可审计的数据链
+ 受控用户研究
+ 可复现离线处理
+ IJHCI论文与科研资产
```

## 2. 参与者产品

参与者全程平坐观看屏幕并跟随提示，不使用键盘、鼠标、控制器或场景选择操作。

每个模块推荐200秒：

| 阶段 | 时间 | 语义 |
|---|---:|---|
| demo | 目标25秒 | 场景原生示范目标呼吸 |
| closed_loop | 目标150秒 | 真实设备驱动实际反馈和累计恢复 |
| lock_transition | 目标25秒 | 锁定真实恢复状态并自动转场 |

四个模块推荐共13分20秒；精确时长由技术预试在冻结区间内一次确定，并在正式条件间匹配。

## 3. 四个固定复合模块

| 场景 | 呼吸基线 | 核心视觉系统 |
|---|---|---|
| 风暴 | 3-3-3-3四阶段箱式 | 风雨—保护罩 |
| 炙烤 | 4-6延长呼气 | 热浪—冷却气流 |
| 暴雪 | 5-5等时慢呼吸 | 雪雾—路径与脚印 |
| 褪色 | 循环叹息 | 灰度—色彩汇聚与扩散 |

参与者侧统一呼吸圈已移除。抽象双环只作为第一篇论文的研究对照，不进入最终产品必要界面。

## 4. 三个运行制品

1. **Unity参与者制品**：场景、提示、反馈、恢复、转场、降级。
2. **Python真实数据系统**：设备、时钟、信号质量、事件检测、协议、记录、离线处理。
3. **TouchDesigner实验员台**：波形、相位、质量、延迟、降级、会话和告警。

## 5. 两条科研主线

### 主贡献：阶段一场景原生提示

比较：

- `scene_native`
- `abstract_pacer`

主要门：

1. `protocol_fidelity`非劣；
2. 场景—提示语义一致性提高。

### 次贡献：同篇论文的序列编排

```text
24种完整顺序均衡随机探索
→ 位置与转换规律
→ 可解释策略学习
→ 新参与者独立比较策略与随机基准
```

阶段二只学习并冻结策略，阶段三用全新参与者进行独立比较。Gate 1、Gate 2、Gate 3按顺序解释，次贡献不吞掉主贡献。

## 6. 最终成果组合

- 一篇IJHCI目标主论文；
- 一项会议或交互展示；
- Unity、Python、TD三个运行制品；
- 数据字典、协议、分析代码和复现包；
- 软件著作权；
- 通过检索与权属评审后的条件性专利材料；
- 中英文演示视频、海报和答辩材料；
- 后续序列编排论文储备。

## 7. 完成定义

项目“完成”不是仅指软件能运行，而是同时达到：

- 产品可运行；
- 数据可审计；
- 伦理合规；
- 预试通过；
- 正式样本完成；
- 数据锁库；
- 分析可复现；
- 论文可投稿；
- 资产可交接。
