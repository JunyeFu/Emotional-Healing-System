# Q-01 Level A构念审查与独立重建框架 v1.0

> 状态：`INDEPENDENT_REREVIEW_PASS_PENDING_SECOND_PERSON`
> 任务：Q-01【研究工具】
> 目的：判断候选四层语法是否具备内容完整性、边界清晰度和跨场景生成性。
> 边界：本目录没有真实专家、独立设计者或盲态评分数据，不关闭Level A、Level B或Gate 2。
> 当前复核：首轮4项P1及后续2项P2已修复，候选`a9b5c69`经第三轮独立Agent复审为`PASS`，见`10_独立Agent复审报告_PASS.md`。

## 1. 研究位置

阶段一比较的是`scene_native`与`abstract_pacer`两种完整提示表示方案，不保证任一条件胜出。Q-01只回答一个更窄的问题：R-01提出的目标、实际、累计、降级四层语法，能否被未参与框架制定的人准确理解并迁移到未见结构。

Q-01不评价短时负性情绪结果，不比较天气顺序，不检验单一视觉机制，也不把材料完成写成真人研究完成。独立重建失败不推翻阶段一的完整方案比较，但必须把设计知识主张降为“四场景设计模式”。

## 2. 方法依据与项目适配

| 方法来源 | 采用内容 | 在本项目中的限制 |
|---|---|---|
| COSMIN内容效度方法 | 构念、目标对象和使用情境先冻结；相关性、完整性、可理解性分开 | 专家只审查专业材料的表达清晰度；目标使用者是否真正理解仍由Level B回答 |
| Munzner分层设计验证 | 不同层级采用不同威胁和验证方法，上游错误会传递到下游 | 四层逐层评分，不允许用总分掩盖目标层或实际层失配 |
| ITU-R BT.500 / ITU-T P.910 | 固定素材、观看条件、匿名呈现、随机顺序和可重复报告 | 只借用静态图与回放评价程序，不把画质标准当作构念标准 |
| ACCORD/CREDES共识报告原则 | 预先声明角色、共识规则、分歧和修订方法 | 不以会后协商替换原始独立评分 |

## 3. 角色隔离

框架使用匿名代码；真实身份映射由获批活动负责人在仓库外保存。

| 人员池 | 数量 | 构成 | 可见材料 | 不得承担 |
|---|---:|---|---|---|
| 构念专家 | 8 | 构念/方法3，HCI/视觉3，运行系统2 | 完整构念包、评分项和主张边界 | 独立重建、盲态评分、框架作者身份 |
| 独立设计者 | 4 | HCI/视觉2，实时视觉/游戏2 | 去条件标签的语法包与任务书 | 查看R-01全文、现有样片、预期答案或评分键 |
| 盲态评分者 | 2 | 熟悉视觉表达但未参与框架和重建 | 匿名重建结果、评分规则和参考真值 | 查看设计者身份、条件名称和相互评分 |
| 裁定人 | 1 | 项目研究负责人 | 自动汇总、原始意见和分歧记录 | 改写原始评分或事后改变阈值 |

同一人不得跨任专家、设计者、评分者或裁定人。框架作者不得进入任一人员池。

## 4. 五阶段过程

### Q1-0 权威冻结

冻结以下输入：

- R-01四层定义、来源、时间尺度和禁止耦合；
- F-02构念边界及条件中性规则；
- 两种完整提示表示方案的主张边界；
- 本目录的角色、项目、阈值、任务和裁定规则。

任何含义变化都产生新框架版本；执行开始后不得覆盖原版本。

### Q1-1 八专家构念审查

专家独立评价`framework_contract_v1.0.json`中的10个项目。每项使用1至4分评价相关性、完整性、表达清晰度和构念纯度，并单独标记关键阻断项。

- `3/4`计入内容有效；
- 相关性、完整性、表达清晰度和构念纯度四个维度分别计算`I-CVI`与`S-CVI/Ave`；
- 每个维度的逐项`I-CVI >= 0.78`；8名完整评分实际要求至少7名给出3或4；
- 每个维度的`S-CVI/Ave >= 0.90`；
- 不允许存在未关闭关键阻断项；
- 必须同时保留逐项分布和开放意见。

未达到阈值进入`REVISE`，不允许用平均总分覆盖单项失败。

### Q1-2 双任务盲态独立重建

每位独立设计者完成两个低成本设计任务，只提交分镜、关键帧、动效参数表和图层职责，不制作正式Unity场景。

| 任务 | 固定输入 | 需要证明的迁移能力 |
|---|---|---|
| `R-UNSEEN-RHYTHM` | 非正式研究使用的未见节律结构＋中性自然环境 | 四层语法能迁移到未见时间结构 |
| `R-NON-WEATHER` | 当前目标/实际/累计/降级事件＋非天气空间主题 | 四层语法能迁移到非天气场景 |

任务包不得出现`scene_native`、`abstract_pacer`、天气名称、现有机制图、呼吸答案结构或“预期成功方案”等身份线索。

### Q1-3 匿名评分

重建结果按随机代码呈现。两名评分者分别判断：

- 目标层、实际层、累计层、降级层是否职责正确；
- 是否出现来源耦合、时间尺度耦合、累计泄露相位或降级评价化；
- 是否泄露现有条件身份；
- 是否仅靠颜色承载关键区别。

两名评分者任一字段不一致时进入`REVISE`并交裁定人逐字段填写`adjudications.csv`；工具保留原评分并仅消费独立裁定记录，不得静默取平均。

### Q1-4 自动裁定与交接

单个重建只有在四层全部正确、无禁止耦合且无条件身份泄露时才通过。框架生成性通过要求：

- 至少3/4设计者同时通过两个任务；
- 每个任务至少3/4设计者通过；
- 两名评分者不存在未裁定分歧。

裁定只有四种：

| 状态 | 含义 | 下游动作 |
|---|---|---|
| `PASS` | 构念审查和独立重建均通过 | 可保留“候选四层设计知识”，等待最终渲染复核和Level B |
| `REVISE` | 材料不完整、专家门失败或评分存在分歧 | 修订后产生新版本并重做受影响阶段 |
| `DOWNGRADE_TO_FOUR_SCENE_DESIGN_PATTERN` | 专家门通过，但独立重建稳定性不足 | 保留完整方案比较，删除跨结构框架主张 |
| `INCOMPLETE` | 人员、任务或评分记录不完整 | 不作研究裁定 |

独立重建阈值是本项目事前裁定，不声称来自通用标准。执行前如需修改，必须记录理由并升级框架版本。

## 5. 文件与接口

| 文件 | 用途 |
|---|---|
| `framework_contract_v1.0.json` | 机器可读角色、项目、阈值、任务和裁定合同 |
| `templates/roster.csv` | 匿名角色与资格登记模板 |
| `templates/expert_reviews.csv` | 专家逐项评分模板 |
| `templates/reconstruction_scores.csv` | 两名评分者逐任务评分模板 |
| `templates/adjudications.csv` | 逐字段分歧的独立裁定记录模板 |
| `templates/revision_log.csv` | 版本差异与处置日志模板 |
| `tools/summarize_q01.py` | 自动检查完整性并输出裁定摘要 |
| `tests/test_summarize_q01.py` | PASS、REVISE、DOWNGRADE三类合成验证 |
| `fixtures/synthetic_fixture_report.json` | 合成验证预期与本轮结果 |
| `04_课题实际构念与证据矩阵.md` | 当前权威、四场景实例和十项审查证据 |
| `05_盲态材料母版与编号方案.md` | 两项确定性任务、事件时间线和顺序平衡 |
| `06_重建真值与评分键.md` | 不规定画风的功能真值与评分依据 |
| `07_完整执行SOP与空白报告.md` | 从冻结到裁定的执行流程及空白报告 |
| `materials/` | 专家项目、盲态任务和分配的机器可读版本 |
| `tools/validate_q01_materials.py` | 材料一致性、权威路径和身份泄露检查 |

运行：

```powershell
py -3.14 tests/test_summarize_q01.py
py -3.14 tests/test_validate_q01_materials.py
py -3.14 tools/validate_q01_materials.py
py -3.14 tools/summarize_q01.py --roster <roster.csv> --expert <expert_reviews.csv> --reconstruction <reconstruction_scores.csv> --adjudication <adjudications.csv> --out <summary.json>
```
