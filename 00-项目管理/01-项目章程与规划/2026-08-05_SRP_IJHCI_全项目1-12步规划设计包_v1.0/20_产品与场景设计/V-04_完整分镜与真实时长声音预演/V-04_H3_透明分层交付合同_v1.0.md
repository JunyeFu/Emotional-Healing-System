# V-04 H3 透明分层交付合同 v1.0

## 1. 目标与边界

`H3_LAYERABLE_BACKGROUND_REBUILD`只把四张已确认的固定镜头底片重建为可独立管理的透明层，不改变构图、色彩、镜头或天气核心机制。本合同通过不代表 Unity 运行、正式构建、真实设备链或 V-04 整体完成。

4K工作制品位于仓库内的本地忽略目录`.artifacts-local/V-04/H3/layerable-background-rebuild/<candidate-id>/`。Git仅保存配方、生成器、验证器和轻量评审证据。

## 2. 冻结输入

输入及SHA-256由`V-04_H3_透明分层配方_v1.0.json`冻结：storm、heat、snow使用H3 v1确认底片，fade使用H3 v5确认底片。生成时统一规范化为`3840 x 2160 RGBA`，不得二次生成或重绘可见像素。

## 3. 层级与排序

每个天气必须交付以下7层，共28张透明PNG：

| 索引 | layer_id | 责任 |
|---:|---|---|
| 0 | `sky_clouds` | 天空与云层，作为全画布不透明底层 |
| 1 | `far_landform_01` | 最远地貌 |
| 2 | `far_landform_02` | 次远地貌 |
| 3 | `far_landform_03` | 最近的远景地貌 |
| 4 | `mid_terrain` | 中景地形与主要结构 |
| 5 | `ground_visual` | 地表、水面、雪地或道路主体 |
| 6 | `foreground_occluders` | 最近景遮挡物 |

所有层共享同一画布、原点和固定镜头，不启用横向滚动或视差。非底层必须同时包含透明与不透明像素；透明区RGB必须为零。相邻层允许32像素隐藏覆盖区，覆盖区不得改变最终可见像素。

本任务交付的是固定顺序叠放层，不是可单独展示的完整场景，也不允许单层移动、替换或视差。隐藏区可使用确定性边界延展；只评审冻结顺序下的可见边缘。Unity导入时必须保持0至6的排序、共同原点和固定相机。

## 4. 可复现性与重组

生成入口：

```powershell
py -3.14 build_v04_h3_layer_exports.py --output-root .artifacts-local/V-04/H3/layerable-background-rebuild/layer-export-candidate-v2 --candidate-id layer-export-candidate-v2 --tracked-review
```

验收入口：

```powershell
py -3.14 validate_v04_h3_layer_exports.py <candidate-path> --report <report-path>
```

按索引0至6执行标准alpha合成后，结果必须与对应4K确认底片逐字节一致。`asset_manifest.csv`必须覆盖28个唯一`scene + layer_role`组合，并记录文件哈希。候选ID必须与不可覆盖的输出目录名一致；新修订使用递增候选ID，不覆盖旧候选。

## 5. 状态与发布边界

- 机器门通过后：`READY_FOR_TEAM_DIRECTOR_REVIEW`。
- 团队总监四天气人工评审全部通过后：`H3_LAYERABLE_BACKGROUND_REBUILD=PASS`。
- 任一人工项不通过：保持H3，不进入下一硬门。
- 所有资产许可状态固定为`PENDING_G02_CLEARANCE`，`formal_use_allowed=false`。
- H3通过后，V-04仍为`IN_PROGRESS`，下一硬门为`H3_FIXED_COMBINED_REVIEW`。
