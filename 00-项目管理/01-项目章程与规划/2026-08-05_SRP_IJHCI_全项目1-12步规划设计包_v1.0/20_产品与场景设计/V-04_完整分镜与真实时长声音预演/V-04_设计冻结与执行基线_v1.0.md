## 1. 任务目标与职责边界

V-04交付一套可重排、可复现、可审查的完整时长视听预演，用于在Unity实现前验证：

1. 四个天气模块能按任意合法顺序装配，且每个天气恰好出现一次。
2. `scene_native`与`abstract_pacer`两种提示条件除提示载体外保持信息与时序匹配。
3. 每个模块的`demo -> closed_loop -> lock_transition`时轴、画面节拍、声音入口和降级语义可被机器核对。
4. 预演可为F-03、F-04、F-05、U-03及后续Unity实现提供稳定输入，但不接管P-01会话编排权威，也不替代V-03映射合同。

V-04不负责：

- 修改F-01协议Schema、P-01会话状态机或V-03映射边界；
- 生成实验顺序、读取后测数据或判断某种顺序的结果；
- 制作U-03最终美术、正式声音资产或Unity正式构建；
- 把`DESIGN_PREVIEW_TRACE`描述为真实输入或正式运行证据。

## 3. 冻结的母版与时轴

### 3.1 唯一母版

- 使用一个模块化母版Animatic，由中性入口、四个可重排天气模块和中性结束组成。
- 四个天气技术ID固定为`storm`、`heat`、`snow`、`fade`；完整排列为`4! = 24`种。
- 评审参考顺序固定为`storm -> heat -> snow -> fade`，必须标记`REVIEW_REFERENCE_ONLY`。
- 24种排列与12种有向相邻关系必须由机器清单验证，不制作24条手工完整视频。

### 3.2 核心时长

每个天气模块按以下连续段执行：

| 段 | 默认值 | 允许区间 | 作用 |
|---|---:|---:|---|
| `demo` | 25秒 | 24-30秒 | 从中性基线显现目标与实际提示 |
| `closed_loop` | 150秒 | 140-160秒 | 展示目标、实际、累计和质量语义 |
| `lock_transition` | 25秒 | 20-30秒 | 锁定本模块并过渡到下一模块或结束 |

- 默认单模块200秒，四模块核心时轴严格为800秒。
- `MIN/DEFAULT/MAX`总核心时长分别为736/800/880秒；与24种顺序组合形成72条机器验证。
- 入口和结束各约5秒的中性画面只供评审，不进入核心时轴或正式配置。
- 暂停、事件等待和正式运行时钟语义由P-01负责，V-04不得把30 fps预演帧号变成会话权威。

### 3.3 镜头与卷轴

- 每个天气模块为一个固定观察点的连续长镜头，仅做横向卷动。
- 不使用跳切、镜头推拉、旋转、黑场切换或参与者可见评审标注。
- 分层动态故事板至少包含天空、远景、中景、近景和提示层；长卷轴至少覆盖`6.75`个视口宽度。
- 四天气以自然环境为主体，国风建筑只作为少量地标和路径结构，不形成统一建筑群背景。

## 4. 五十条主分镜

共享主分镜固定为50条记录：

- `G01`：入口示意保持；
- 四天气各`M01-M12`，共48条；
- `G02`：结束示意保持。

模块节拍语义固定如下：

| 节拍 | 冻结语义 |
|---|---|
| `M01` | `demo`首帧；第一位置记录`FIRST_POSITION_BOUNDARY` |
| `M02` | 第二个目标周期开始时实际提示首次出现 |
| `M03` | `demo`显现完成，目标与实际表示齐全 |
| `M04` | 进入`closed_loop`并维持连续长镜头 |
| `M05-M08` | 非完美实际轨迹与双向累计变化的状态结 |
| `M09` | 进入`lock_transition`并冻结本模块累计 |
| `M10` | 转场进度`p=0.3` |
| `M11` | 转场进度`p=0.7` |
| `M12` | 转场进度`p=1.0`，回到无提示中性边界 |

`M12`与下一模块`M01`可以具有相同时间戳，但必须由`event_order`保证先完成当前转场，再启动下一模块目标与声音。

## 5. 数据源与双条件约束

### 5.1 分镜源

- 唯一可编辑分镜源为Draft 2020-12约束的JSON。
- JSON记录结构化的节拍ID、模块ID、触发条件、段相对时间、输入引用、共享画面状态、条件覆盖、差异掩码、声音状态、证据标签和断言。
- Markdown、CSV与展开JSON均由分镜源和确定性轨迹生成，不得分别手工维护。
- 生成清单必须记录Schema、输入、生成器和全部输出的SHA-256。

### 5.2 预演轨迹

- 两条件逐帧共享同一版本化`DESIGN_PREVIEW_TRACE`。
- 主路径使用非单调中性累计轨迹`0.45 -> 0.58 -> 0.51 -> 0.66 -> 0.60`，并包含实际提前、滞后和幅度差异。
- 不复制目标值充当实际值，不补零，不构造持续变好的结果故事。
- 低确定性、暂时不可用、恢复和中止只进入独立失败状态评审卷，不插入800秒主视频。

### 5.3 条件匹配

- 共享天气、卷轴、累计、转场、输入和声音只维护一次。
- 两条件只允许在目标与实际提示载体上不同：场景原生提示或统一抽象提示。
- 每条节拍必须附条件覆盖与预期差异掩码；掩码外的像素或语义差异直接失败。
- 参与者视图不得出现条件名、时间码、段名、数据字段、原因码或评审文字。

## 6. 画面和导出规格

| 制品 | 规格 | 数量与边界 |
|---|---|---|
| 单条件参与者视图 | `1920x1080`、30 fps CFR | 两条件各带声版和静音版，共4条 |
| 双条件评审视图 | `3840x1200`、30 fps CFR | 顶部120像素评审区，下方保留两幅未缩放`1920x1080`画面 |
| 失败状态评审卷 | 双条件并列，约2分钟 | 四天气降级/不可用与统一平稳中止 |
| 转场检查 | 12种有向相邻关系 | 短预览与机器核对表，不替代主视频 |

- 800秒核心区在30 fps下恰好为24000帧。
- 静音版不得用全零音轨替代无音轨。
- 双条件评审视图只保留一条共享声音轨，评审文字只位于顶部外部区域。
- 30 fps仅为V-04预演规格，不是Unity运行性能目标。

## 7. 临时视觉资产

资产按以下顺序生产，前一门未通过不得扩量：

1. `H1`：`storm/heat/snow/fade/corridor`各生成2个风格锚点候选，由团队总监选择5张。
2. `H2`：使用已选锚点制作`fade`十秒双条件样片，同时确认分层、差异掩码和临时声音身份。
3. 完成`fade`默认200秒模块。
4. 扩展`storm/heat/snow`三个模块。
5. 完成长廊、12种有向转场与完整母版装配。
6. `H3`：审阅完整双条件预演和失败状态评审卷。

全部画面由分层长卷轴、参数化天气层和提示层装配，不逐张绘制50个完整画面。临时资产不得宣称为U-03最终资产或已获正式许可。

## 8. 临时声音

- 生成四条225秒非循环天气环境母带和一条65秒无缝循环长廊母带。
- 格式固定为48 kHz、24-bit、立体声WAV；目标响度`-22 LUFS-I`，允许`-24..-20 LUFS-I`，真峰值不高于`-3 dBTP`。
- 使用固定种子和参数生成非节律环境声；不得跟随目标、实际、累计、质量状态或呼吸周期变化。
- 每个天气模块在自身`M01`启动天气母带。上一模块转场只预显现下一天气视觉基线，不提前播放下一天气声音。
- 默认使用3秒等功率天气/长廊淡化；第一天气从长廊中性声进入。
- 全部声音标记`TEMP_REFERENCE_ONLY`和`formal_use_allowed=false`，记录来源、工具、版本、参数、权利说明与哈希。

## 9. 制作工具与确定性渲染

工具锁候选固定为：

| 工具 | 候选版本 | 用途 |
|---|---|---|
| Python | 3.14.4 | 数据生成、装配、验证 |
| Pillow | 12.2.0 | 分层图像渲染 |
| NumPy | 2.4.6 | 确定性数值与声音生成 |
| FFmpeg/ffprobe | 9.0.1，gyan release essentials | 编码、复用、媒体探测 |

- 工具锁必须记录来源、绝对路径、SHA-256和许可状态；不允许从未知系统`PATH`回退。
- FFmpeg是外部制作工具，不进入Unity制品。
- 当前只冻结候选版本；实现开始前仍需安装、验签并形成工具探测记录。
- 渲染顺序固定为10秒技术烟雾、25秒demo、200秒单模块、双条件模块、800秒核心、完整导出。
- 任一级出现帧数、音频、差异掩码、资产登记、哈希或编码异常时阻断下一层级。

## 10. 本地存储与候选分发

- 大型本地制品根固定为被Git忽略的`.artifacts-local/V-04/<candidate_id>/`。
- 普通Git只跟踪源数据、Schema、工具锁、脚本、配置、清单和验证报告；本轮不启用Git LFS。
- `H3`通过后生成确定性分卷ZIP，单附件目标小于1.5 GiB，硬上限小于2 GiB。
- 候选附件上传到绑定候选提交的GitHub `PRERELEASE`，不得标记Latest或正式产品。
- 提交A冻结源和本地候选清单；提交B只写回Release地址、附件ID、远端大小和下载哈希。
- 候选Git SHA与`candidate_release.json` SHA共同构成审核对象；附件变化必须创建新候选，不得覆盖。

## 11. 六人日执行结构

V-04保持一个负责人、一个任务状态和一个签收对象，主动工作量估算为6人日：

| 单元 | 人日 | 主要交付 |
|---|---:|---|
| A 数据与渲染基础 | 1.5 | 分镜JSON/Schema、预演轨迹、生成器、工具锁、最小渲染 |
| B 临时视觉资产 | 2.0 | H1锚点、H2样片、四天气分层长卷轴与转场 |
| C 声音与完整装配 | 1.0 | 五条声音母带、混音规则、完整双条件装配 |
| D 验证与候选发布 | 1.5 | 72条时轴、24顺序、12转场、媒体检查、候选清单与预发布 |

等待H1/H2/H3确认和机器渲染的时间不计入主动人日；四个单元不得拆成独立签收任务。
