## 1. 修订结论

`storm`、`heat`、`snow`与`fade`四个天气模块统一采用固定镜头和固定场景，不再横向滚动。运行中相机位置、旋转、缩放、背景位置和世界视差位移均保持不变。

本合同替换V-04当前交接中的天气镜头字段，并在后续V-05、U-03及Unity实现中优先于V-02/V-03的横向卷轴候选参数。V-02/V-03签收文件、旧H3样片和机器记录保留为历史决策与证据，不回写、不删除；旧H3合并候选不再是当前团队总监确认对象。

通用山雾长廊是模块间转场，不属于四个天气背景，本轮不修改其既有合同。

## 2. 统一固定镜头合同

| 项 | 当前值 |
|---|---|
| 画面比例 | `16:9` |
| 相机模式 | `FIXED` |
| 相机平移、旋转、缩放 | 全部为零 |
| 背景平移 | 全部为零 |
| 横向卷轴与视差卷动 | 关闭 |
| 地平线候选 | `y=0.56-0.62`，首选`0.59` |
| 目标安全区 | `x=0.55-0.85, y=0.34-0.72` |
| 实际安全区 | `x=0.20-0.45, y=0.18-0.52` |
| 参与者操作 | 无 |

固定场景只取消观察点和背景的位移，不冻结局部环境。基础雨丝、云雾、热霭、非周期降雪、水面微波纹、反光和植被轻摆可以继续运动，但必须可重放、低幅、非周期，且不得承担呼吸步骤、实际跟随或累计状态语义。

暂停时，局部环境、目标、实际与累计过渡全部冻结；恢复后从同一视觉状态继续。Python/SessionCore仍是顺序、时钟和状态权威。

## 3. 四天气固定构图

| 天气 | 固定环境构图 | 唯一核心机制 | 固定镜头下的运动边界 |
|---|---|---|---|
| `storm` | 风雨隘口；中右侧保留雨幕廊道，左下保留近场气流区 | 雨幕风门 | 风门和近场气流在各自安全区内变化；基础雨和雾仅作非周期环境运动 |
| `heat` | 热浪盐原；中右侧保留冷流路径，左下保留近场盐尘区 | 冷流风道 | 目标冷流在固定画幅内完成汇集、贴地前行和回收；基础热霭不得按周期变化 |
| `snow` | 雪雾松林；中右侧预留枝头与地表锚点，左下保持低遮挡 | 粉雪升沉 | 粉雪沿固定轨迹升沉；基础降雪和林间雾不得形成呼吸周期 |
| `fade` | 彩色湿地；主水道由中远景通向右下，左侧支流汇入 | 色潮回流 | 色潮在固定水系内完成主吸、补吸和长呼回流；整屏复色仍按已确认合同执行 |

旧文档中的“前方”统一解释为固定画面中右侧的中远景目标安全区，不再表示相机或背景向右前进。`heat`的较长行程和`fade`的长距离回流必须在固定画幅的路径内完成，不能借相机位移表达时长。

## 4. 两条件公平边界

- `scene_native`与`abstract_pacer`使用同一背景、固定裁切、相机参数、局部环境运动、累计环境状态、声音和时长。
- 两条件的相机与背景逐帧配准，不允许用微小漂移制造动感。
- 场景原生条件只在固定安全区显示目标与实际载体；抽象条件关闭这些载体并显示双环。
- 背景不得预先包含雨幕风门、冷流风道、粉雪升沉、色潮、双环、复色过程或累计变化。

## 5. 高精度背景方向

四个背景改为高精度3D游戏环境建模质感的2D渲染参考：细致地形与植被、PBR材质、清楚的前中远景、克制的体积光和可拆分轮廓。它们不是3D模型，也不是可直接进入正式构建的资产。

本轮提供A、B、C三组四联预览：

| 组 | 方向 | 当前观察 |
|---|---|---|
| A | 写实电影级自然PBR | 材质真实；storm偏暗、snow偏白，作为写实上限对照 |
| B | 明亮东方艺术化写实 | 四天气综合色彩与空间层次最均衡，适合作为统一方向候选 |
| C | 实时游戏关卡可读性 | 地表和前景细节最强，固定构图与后续分层锚点更明确 |

四联图只用于选择美术方向。团队总监选择统一组或逐天气组合后，下一轮才生成四张独立16:9背景，并进行安全区、去提示、拆层和许可门检查。
