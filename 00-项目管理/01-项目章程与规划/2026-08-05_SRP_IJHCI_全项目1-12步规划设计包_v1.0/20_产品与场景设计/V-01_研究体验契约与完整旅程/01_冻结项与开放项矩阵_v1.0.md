# V-01 冻结项与开放项矩阵 v1.0

## 使用规则

- `FROZEN`：V-02 及后续 Unity 任务必须满足，不能用视觉方案覆盖。
- `OPEN`：后续任务必须做出明确选择并记录理由，当前不预设答案。
- `VERSIONED_CHANGE_ONLY`：只有更新上游权威、合同、测试和分析计划后才能改变。
- 旧 Unity 实现、旧场景名称和既有素材均不自动获得冻结资格。

## 研究与体验矩阵

| ID | 状态 | 项目 | 当前约束 | 验证或变更路径 |
|---|---|---|---|---|
| F-001 | FROZEN | 研究对象 | 第一阶段比较两种完整提示表示包，不拆解为单一天气、单一呼吸流程或单一视觉机制的独立效应 | 协议与分析计划共同核对 |
| F-002 | FROZEN | 条件 | `scene_native` 与 `abstract_pacer` 必须表达同一目标、实际、累计与降级真值 | F-02 理解真值、R-01 四层合同与 Unity 对照截图 |
| F-003 | FROZEN | 模块集合 | `storm`、`heat`、`snow`、`fade` 恰好各出现一次 | manifest、P-01 轨迹与 Unity 回执 |
| F-004 | FROZEN | 模块顺序 | Unity 只消费 Python 下发顺序，不读取前量表、不自行随机、不自行重排 | 控制事件与回执比对 |
| F-005 | FROZEN | 核心操作 | 四模块核心过程中参与者不进行手部操作，保持平坐观看与跟随提示 | 旅程评审、观察记录与界面检查 |
| F-006 | FROZEN | 核心结构 | 每个模块固定经过 `demo -> closed_loop -> lock_transition` | 会话轨迹和段级回执 |
| F-007 | FROZEN | 推荐时长 | 默认 25/150/25 秒，四模块默认合计 800 秒；运行时以已冻结配置为准 | 配置哈希与 P-01 快照 |
| F-008 | VERSIONED_CHANGE_ONLY | 时间范围 | `demo` 24-30 秒、`closed_loop` 140-160 秒、`lock_transition` 20-30 秒 | 先修订协议配置，再更新测试和预试材料 |
| F-009 | FROZEN | 前后测关系 | 前量表发生在 Unity 核心前，后量表及其他评估发生在 Unity 核心后；Unity 不显示、不计算、不保存量表答案 | 旅程检查与数据流审计 |
| F-010 | FROZEN | 单次参与 | 同一人只进入一个阶段、一个条件和一次核心体验 | G-02 去重门与分配记录 |
| F-011 | FROZEN | 参与者产品 | Unity 必须独立形成完整观看体验，不依赖 TouchDesigner 画面或操作 | 离线构建验收 |
| F-012 | FROZEN | TouchDesigner | TouchDesigner 是只读操作台和数据监控端，不控制参与者流程 | 网络消息权限测试 |
| F-013 | FROZEN | Python 权威 | Python 唯一负责会话、顺序、计时、交互状态估计、控制和记录 | F-01/P-01/P-02 合同测试 |
| F-014 | FROZEN | Unity 权限 | Unity 只渲染、镜像状态、回传 ACK 和渲染回执，不推进研究流程 | 状态机测试与断连测试 |
| F-015 | FROZEN | 四层信息 | 目标、实际、累计变化和降级状态在需要时可区分，不能用单一“好坏分数”替代 | 理解测试与画面审查 |
| F-016 | FROZEN | 非评价性 | 画面不对参与者作好坏评分，不承诺必然恢复，也不要求每模块达到相同终点 | 文案、动画状态与结束态审查 |
| F-017 | FROZEN | 降级语义 | `GOOD/DEGRADED/UNUSABLE/DISCONNECTED` 由上游给出；Unity 不填零、不伪造正常数据 | 故障注入与回执检查 |
| F-018 | FROZEN | 声音公平 | 两条件使用相同的声音内容、时序和语义；声音不成为隐藏的第二套提示条件 | 音轨清单和事件时间线核对 |
| F-019 | FROZEN | 研究门 | 先检验提示跟随功能下限，再检验场景融合感、理解与负担；现阶段不写成已观察结果 | 统计分析计划与论文主张表 |
| F-020 | FROZEN | 证据 | 每个模块必须保留控制事件、段状态、帧序、ACK、渲染回执、降级原因和构建哈希 | P-02 追加记录与重放核对 |
| F-021 | FROZEN | 发布许可 | 未跟踪、未登记或许可状态未知的发布资产阻止正式构建 | G-02 Unity 资产许可门 |
| F-022 | FROZEN | 参与者文案 | 仅显示中性、操作必要的信息，不显示端口、设备、哈希、内部状态名或研究假设 | 界面文案审查 |
| F-023 | VERSIONED_CHANGE_ONLY | 合同标识 | `storm/heat/snow/fade` 是稳定技术标识；参与者可见名称可变，但不能反写合同 | F-01 版本变更流程 |
| F-024 | FROZEN | 正式输入 | 正式运行不使用 mock 或静默补值；开发回放必须显式标识且不构成正式证据 | runtime mode、源策略和存储门检查 |

## 场景创作开放项

| ID | 状态 | 开放问题 | V-02 最低输出 |
|---|---|---|---|
| O-001 | OPEN | 四个技术模块对参与者呈现为何种天气、环境或自然隐喻 | 至少两套四模块完整方向，不只列单场景点子 |
| O-002 | OPEN | 每个模块唯一核心视觉机制是什么 | 每模块一个主机制、辅助元素上限和信息层映射 |
| O-003 | OPEN | `scene_native` 的目标与实际如何嵌入环境 | 目标和实际可区分但不脱离场景的表达方案 |
| O-004 | OPEN | `abstract_pacer` 的具体形态 | 不预设必须使用内外圆环；需与场景原生条件信息等价 |
| O-005 | OPEN | 旅人、观察点或叙事载体是否存在 | 明确其功能、是否影响研究变量，以及无角色版本备选 |
| O-006 | OPEN | 镜头、构图、层级、色彩、材质和像素风格 | 视觉系统板与四场景一致性规则 |
| O-007 | OPEN | 声音素材、声景密度与转场听觉语法 | 共用声音语义表和两条件公平方案 |
| O-008 | OPEN | 场景间转场隐喻 | 保证自动、无操作、可在配置时长内结束的转场脚本 |
| O-009 | OPEN | 累计变化在四场景中的视觉载体 | 单调、可锁定、可重放的场景内表达 |
| O-010 | OPEN | 降级状态如何被自然表达 | 四种降级状态的最小辨识方案，不使用技术提示 |
| O-011 | OPEN | 旧 Storm/Heat/Snow/Fade 场景与素材的复用比例 | 逐项保留、重制、淘汰清单及许可结果 |
| O-012 | OPEN | 首个最高风险垂直切片选哪个模块、哪个条件 | 风险评分、选择依据、验收脚本 |
| O-013 | OPEN | 舒适性参数 | 亮度、闪烁、运动速度、粒子密度、音量和减少动态策略候选范围 |
| O-014 | OPEN | 可见模块名称与短文案 | 条件中性文案，不泄露研究假设 |
| O-015 | OPEN | 结束画面的情绪与叙事收束 | 中性完成感，不宣告个人效果 |

## 冲突裁定

1. 若历史文档给出了具体天气视觉、统一圆环或角色剧情，而本表列为 `OPEN`，以本表为后续创作边界。
2. 若开放方案要求改变研究条件、输入真值或时间结构，该部分立即停止，转入版本化变更评审。
3. 若一个元素同时承担研究提示与装饰功能，按研究变量管理，并纳入两条件公平审计。
4. 无法分类的显著元素不得进入正式垂直切片。
