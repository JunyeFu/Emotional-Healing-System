## 1. 演练目的

本方案为 U8 产能硬门的真实演练提供执行框架。通过连续 14 个自然日的全流程模拟，验证以下事项：

- **招募漏斗**：从触达到完成会话的各环节转化率是否支撑 528 会话目标；
- **工位吞吐**：在 55~70 分钟/次的真实占用下，4 工位能否达到理论产能（日完成 5~7 次）；
- **技术稳定性**：Unity 构建、PLUX 呼吸胸带、Polar H10 心电在连续运行中的故障率；
- **人员协同**：主实验员、技术实验员、数据管理员的多工位排班与应急响应能力；
- **数据完整性**：从设备签到 → 遥测记录 → 问卷回收 → 数据打包的全链路可追溯性。

> **硬性约束**：正式阶段启动前必须完成本演练并提交报告；若 U8 未通过，按产能模型第 4 节规定的顺序处置，**不得压缩样本、减少模块或降低数据质量以换取通过**。

## 2. 演练周期与里程碑

| 阶段 | 日期（相对） | 核心任务 | 完成标志 |
| :--- | :--- | :--- | :--- |
| **准备期** | D1 ~ D2 | 设备校准、人员分工、招募渠道上线、演练材料就绪 | 所有设备序列号登记，主实验员通过知情同意/SOP 考核 |

| **执行期** | D6 ~ D12 | 连续 7 天全流程运行（含故障模拟/真实故障处理） | 完成至少 **112 次**完整会话（计划演练产能 140 次的 80%），记录全部漏斗数据 |
| **总结期** | D13 ~ D14 | 数据汇总、偏离审计、产能分析、撰写演练报告 | 提交 U8 评估结论（PASS / NO-GO），附完整证据包 |

## 3. 演练人员配置

依据 `G-01-05_研究角色职责.md` 的角色定义，演练期间（执行期 D6~D12）每日配置如下：

| 角色 | 人数 | 职责 | 备注 |
| :--- | :--- | :--- | :--- |
| **主实验员** | 2 人/班次 | 知情同意、流程引导、安全监控、偏离记录、设备佩戴 | 每人负责 2 个工位，班次可轮换 |
| **技术实验员** | 1 人/全天 | Unity 启动与监控、设备故障处理、实时 QC、时钟同步检查 | 必须熟悉 PLUX/Polar SDK 及 Unity 日志解析 |
| **数据管理员** | 1 人/日终 | 数据打包、完整性校验、脱敏存储、备份 | 不参与会话引导，避免角色混同 |

> **每日运行时段**：上午场 09:00–12:00（3 小时），下午场 13:30–17:00（3.5 小时）。每工位每日目标完成 5~6 次。

## 4. 演练流程明细

### 4.1 参与者路径（单次）

```mermaid
graph LR
    A[报名/筛选] --> B[预约确认]
    B --> C[到场签到]
    C --> D[知情同意 & 安全筛查]
    D --> E[设备佩戴 & 训练]
    E --> F[PANAS前测]
    F --> G[核心体验 4模块 800秒]
    G --> H[PANAS后测]
    H --> I[体验后问卷包]
    I --> J[目的/条件猜测]
    J --> K[数据打包 & 设备清理]
```

### 4.2 各环节标准时长与记录要求

| 环节 | 标准时长 | 记录字段 | 关联偏离代码 |
| :--- | :--- | :--- | :--- |
| 知情同意 + 安全筛查 | 5~8 分钟 | 同意书签署时间；筛查结果 | P-ELG |
| 设备佩戴 + 标准化训练 | 10~15 分钟 | 双设备遥测确认（20Hz 自包含）；时钟同步记录 | T-BRE, T-ECG, T-CLK |
| PANAS 前测 | 2~3 分钟 | 提交时间戳 | F-MIS |
| 核心体验（4 模块） | **严格 800 秒** | 每模块起止时间戳；每个机会的 `COMPLIANT` / `NONCOMPLIANT` / `TECH_UNOBSERVABLE` 标记 | T-UNI, F-TIM, T-SPO |
| PANAS 后测 | 2~3 分钟 | 提交时间戳 | F-MIS |
| 体验后问卷包 | ≤ 5 分钟 | 逐题用时；90 分位数是否超 300 秒 | F-MIS, P-ACT |
| 目的/条件猜测 | 2~3 分钟 | 回答记录 | — |
| 设备清理 + 数据打包 | 5~8 分钟 | 数据完整性哈希；L0/L1 存储路径 | — |
