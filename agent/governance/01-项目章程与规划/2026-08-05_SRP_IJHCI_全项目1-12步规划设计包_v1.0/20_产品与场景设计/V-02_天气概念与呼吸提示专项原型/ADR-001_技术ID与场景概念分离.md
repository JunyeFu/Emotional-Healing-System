# ADR-001 技术ID与场景概念分离

- 状态：ACCEPTED
- 日期：2026-08-18 +08:00
- 决策人：傅钧烨
- 适用任务：V-02及其下游Unity设计任务

## 背景

F-01 v2.1合同已经把`storm`、`heat`、`snow`、`fade`冻结为manifest、策略、遥测和回执使用的模块值。V-02又要求从头比较环境概念，若把这些字符串继续解释为必须呈现同名天气，就会在概念发散前预设答案；若直接改名，则会同时影响Python、Unity、记录和重放合同。

## 决策

采用三层分离：

1. 技术模块ID是稳定兼容键，不作为参与者可见语义。
2. 呼吸功能位置承载冻结的呼吸结构与研究功能。
3. 场景概念是V-02需要发散、比较和裁定的可见环境。

入选场景概念先与呼吸功能位置匹配，再绑定既有技术模块ID。技术ID与可见概念允许不同名。

## 结果

- V-02可真正从头设计，不默认旧天气方案。
- F-01合同、P-01编排、P-02记录和重放无需因概念命名变化而修改。
- Unity必须维护明确的“技术ID到场景概念”映射，不能用ID字符串直接推导资产或用户文案。
- 若后续要求技术ID与可见概念同名，必须走版本化合同变更并重新验证上下游。

## 未决定事项

本ADR不选择任何环境概念，不决定世界结构、提示器形态、声音方案或资产来源。
