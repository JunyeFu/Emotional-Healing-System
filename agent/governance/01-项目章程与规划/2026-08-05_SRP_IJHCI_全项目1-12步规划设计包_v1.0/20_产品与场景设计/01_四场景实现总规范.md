# 四场景实现总规范

## 统一四层

每个场景必须实现：

1. `TargetCue`：目标协议；
2. `ActualFeedback`：真实呼吸；
3. `RecoveryState`：累计恢复；
4. `FallbackState`：信号质量不足。

## 统一接口

```text
SetTargetPhase(phase, progress)
SetActualPhase(phase, progress, quality)
SetRecovery(value)
SetFallback(active, reason)
LockAtClosedLoopEnd()
ResetForSession()
```

## 统一时间线

- 目标0至25秒：`demo`；
- 目标25至175秒：`closed_loop`；
- 目标175至200秒：`lock_transition`。

技术预试允许24至30秒、140至160秒和20至30秒区间；正式阶段冻结一次并在条件间完全匹配。

## 视觉公平

场景原生与抽象条件：

- 使用相同场景、音频和累计恢复；
- 原生条件由场景表达目标/实际；
- 抽象条件由外环/内环表达目标/实际；
- 抽象条件的场景不能泄露周期；
- 原生条件不能额外获得更强奖励。

## 固定镜头

- `storm`、`heat`、`snow`与`fade`全部使用固定相机和固定背景；
- 相机位移、旋转、缩放、背景位移和世界视差卷动均为零；
- 旧横向卷轴参数只作历史候选，不进入V-05及后续Unity实现；
- 基础天气可保留非周期局部运动，但不得泄露呼吸步骤；
- 两种提示条件使用完全相同的固定裁切和局部环境状态。

## 性能

- 稳定目标帧率；
- 所有动态参数可日志化；
- 时间戳可关联Python；
- 场景切换不会造成数据时间轴中断；
- 资源预加载避免转场卡顿。
