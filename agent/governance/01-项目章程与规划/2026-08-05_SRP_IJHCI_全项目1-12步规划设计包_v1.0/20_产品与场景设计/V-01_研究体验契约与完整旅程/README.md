# V-01 研究体验契约与完整旅程

> 契约版本：`SRP-V01-EXPERIENCE-CONTRACT/1.0.0`
>
> 制品状态：`CANDIDATE_FOR_REVIEW`
> 任务状态以团队任务注册表为准。本目录只形成 V-01 技术候选，不代表第二人签收、Unity 制品完成或研究结果成立。

## 本步目的

V-01 是从头设计 Unity 参与者体验的第一步。它先冻结研究设计、系统权威、完整旅程和证据边界，再把天气表现、叙事、美术、声音与镜头留给 V-02 之后处理。旧 Unity 场景只可作为资产盘点输入，不是设计权威。

## 权威顺序

发生冲突时按下列顺序处理：

1. `00_总控/protocol_authority_v1.1.json`
2. `00_总控/13_IJHCI独立审稿攻击与升级裁定_v1.1.md`
3. F-01 v2.1 运行合同与 P-01 会话编排公开接口
4. `20_产品与场景设计/00_参与者产品总规格.md`
5. 本目录 V-01 候选契约
6. 历史场景、旧原型和既有素材

本目录不得静默修改上级权威。需要改变模块标识、时间、条件定义、会话权威或研究主张时，必须发起带版本号的变更，并同步更新合同、实现、测试与分析计划。

## 向 V-02 的交接

V-02 只在开放项范围内提出至少两套完整创意方向，并逐项回填：

- 使用了哪些冻结项；
- 选择了哪些开放项；
- 每个显著元素属于研究变量、运行证据还是非研究装饰；
- 两种提示条件如何保持同一事件真值、时长和声音语义；
- 如何在 `GOOD/DEGRADED/UNUSABLE/DISCONNECTED` 下维持可理解性；
- 哪个机制应进入最高风险垂直切片。

V-02 不得以改名、重画或增加故事的方式改变 `storm/heat/snow/fade` 合同标识，也不得让 Unity 推断顺序、计时或交互状态估计。
