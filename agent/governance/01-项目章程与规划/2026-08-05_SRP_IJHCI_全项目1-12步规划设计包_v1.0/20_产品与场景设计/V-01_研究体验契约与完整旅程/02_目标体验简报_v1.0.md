# V-01 目标体验简报 v1.0

## 一句话目标

让参与者在无需操作的连续观看中，能够自然辨认“现在应如何跟随、自己当前处于哪里、累计变化到哪里、系统何时处于降级状态”，同时保留完整环境体验，而不是面对一块独立仪表。

## 服务对象与使用情境

| 角色 | 核心需求 | 本产品承担 |
|---|---|---|
| 参与者 | 低操作负担、连续、可理解、非评价性的引导 | Unity 全屏参与者体验 |
| 现场人员 | 能从外部启动、暂停、结束并识别故障 | Python/TouchDesigner 操作与监控，不进入参与者画面 |
| 数据与论文负责人 | 能把条件、顺序、状态、画面回执和后测连接到同一会话 | manifest、追加记录、构建哈希和分析数据字典 |
| Unity 制作人员 | 知道什么不能改、什么必须创作、什么需要留下证据 | V-01 契约和后续视觉规范 |

## 目标体验质量

1. **清晰**：参与者无需学习技术术语，也能区分目标、实际、累计变化与暂时不可用。
2. **连续**：入口、四模块、转场和结束属于同一完整旅程，不出现编辑器感、操作台感或突兀加载感。
3. **低负担**：核心过程中不要求点击、选择、按键或回答问题。
4. **非评价性**：实际状态可以偏离目标，但画面不把偏离解释为失败。
5. **场景一致**：场景原生条件的提示像环境机制的一部分，抽象条件则明确但不遮挡主要场景。
6. **可追溯**：参与者看到的关键状态都能由上游事件与 Unity 回执重建。
7. **故障诚实**：数据降级时保持体验连续，但不伪装为正常输入，也不诱导参与者自行排障。

## 反目标

- 不把 Unity 做成 TouchDesigner 的屏幕镜像。
- 不让 Unity 依据量表、生理流或本地随机数决定顺序和计时。
- 不把四个天气分别包装成四个独立因果结论。
- 不用一套中央统一提示覆盖场景原生条件的核心表达。
- 不以故事、粒子、亮度或音效差异暗中改变两种条件的信息量与显著度。
- 不在结束画面宣告参与者已经达到某种个人效果。
- 不把旧场景可运行等同于新设计被接受。

## 内容层级

从高到低依次为：

1. **必要真值**：目标、实际、累计变化、降级。
2. **模块语义**：该模块独有的呼吸时序与唯一核心视觉机制。
3. **旅程连续性**：入口、模块间转场、结尾和声音衔接。
4. **环境表达**：天气、空间、角色、材质、色彩与细节。
5. **装饰**：不影响理解、分组或行为的低显著元素。

低层内容不得遮挡、改写或抢占高层信息。无法说明层级归属的元素不进入正式制品。

## 两条件共同底座

两种条件共享：

- 同一参与者、分配、模块顺序和运行时间；
- 同一目标相位、实际相位、累计变化与降级事件；
- 同一场景背景、镜头范围、主要声音内容和转场时点；
- 同一系统故障语义与结束条件；
- 同一记录粒度和渲染回执要求。

两种条件只允许在“完整提示表示包”上产生计划内差异。具体表示形式由 V-02 提案，V-03 冻结规范，F-03/F-04 实现。

## 完成判据

V-01 的完成不是“画面好看”，而是后续团队能一致回答：

- 哪些约束不能擅改；
- 参与者从进入到离开会经历什么；
- 每个画面元素承担哪类功能；
- 两条件为什么仍是可比较的完整表示包；
- 故障时参与者看到什么、系统记录什么；
- 哪些设计结论仍然只是待验证假设。
