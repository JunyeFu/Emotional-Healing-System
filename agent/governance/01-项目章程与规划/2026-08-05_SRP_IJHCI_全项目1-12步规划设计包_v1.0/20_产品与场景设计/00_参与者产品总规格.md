# 参与者产品总规格 v1.1

> 四层语义、两种完整提示表示方案、配置Schema和混杂候选范围以[R-01四层表示方案](R-01_四层表示方案/R-01_四层候选语法与完整表示方案_v0.9-candidate.md)为当前实现输入。

## 产品目标

构建桌面端、无手部操作、推荐13分20秒核心流程、真实呼吸记录闭环的Unity独立体验。参与者不选择场景，不控制界面，只平坐观看并跟随提示。

## 单次流程

```text
研究人员启动、设备检查与标准化训练
-> PANAS前测
-> 四个自动模块
-> PANAS后测
-> SCCI、四层理解、心智努力与其他体验问卷
-> 目的与条件猜测
-> 自动结束与数据检查
```

核心体验内不出现问卷或手部操作。体验后信息不得进入实时交互状态估计。

## 核心体验

每模块推荐25秒示范、150秒闭环、25秒锁定转场，总计200秒。技术预试允许在已冻结小区间内调整一次；同一正式阶段各组必须使用相同冻结时长，不能按个体状态改变模块长度。

四个天气模块统一使用16:9固定镜头。相机、背景和深度层不平移、不旋转、不缩放，也不做横向卷轴或视差卷动；雨、热霭、基础降雪、水面与植被只保留低幅、非周期、可重放的局部环境运动。目标、实际和累计状态继续由各自独立层表达。

## 产品模式

| 模式 | 用途 | 顺序来源 |
|---|---|---|
| `development_mock` | 动画开发与故障注入，持续显示Mock标记 | 测试fixture |
| `pilot_scene_native` | Level B/C场景原生路径 | 预试清单 |
| `pilot_abstract` | Level B/C抽象对照路径 | 预试清单 |
| `formal_stage1_scene_native` | 阶段一场景原生组 | 冻结均衡随机清单 |
| `formal_stage1_abstract` | 阶段一抽象对照组 | 冻结均衡随机清单 |
| `formal_stage3_policy` | 阶段三冻结策略组 | 冻结策略含回退 |
| `formal_stage3_balanced_random` | 阶段三均衡随机组 | 冻结随机清单 |
| `demo_exhibition` | 展览演示，不产生研究数据 | 演示配置 |

阶段三两组必须使用完全相同的`scene_native`场景构建，只有顺序服务不同。

## 参与者界面原则

- 不显示实验员技术信息；
- 不显示中央统一呼吸圈，抽象对照除外；
- 目标、实际、累计、降级可区分，不堆叠成操作台；
- 颜色不是唯一线索，减少运动与静音路径保持同一研究语义；
- 失败或低质量状态不使用评价参与者能力的语言；
- 不强制显示完全恢复；
- 不提供个体健康判断或效果承诺。

## 构建完成门

- Unity在TD未安装、未启动或退出时仍完成入口、四模块、转场、结束和异常提示；
- Unity会话壳只镜像Python控制事件，不自行改变研究顺序或权威时钟；“无TD”不等于“无Python”；
- 四模块恰好各进入一次，顺序与manifest一致；
- 正式构建不依赖Spout、TD或Mock；
- 两提示条件以完整表示方案为处理，不声称单一机制等价；
- 真实设备断流进入冻结降级，不以零值或模拟值冒充记录；
- 运行日志、构建哈希、渲染回执和完整流程录像齐全。
