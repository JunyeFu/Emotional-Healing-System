# V-02 节点12：两条件公平矩阵

> 状态：ACCEPTED
> 原则：事件真值硬匹配，视觉差异测量报告
> 解释边界：比较两种完整提示表示方案，不识别单一视觉变量作用

## 1. 必须硬匹配

| 类别 | 匹配要求 | 证据 |
|---|---|---|
| 分配与顺序 | 同一研究阶段使用同一冻结随机化规则；比较材料按同一模块和步骤对齐 | manifest、分配记录、策略决策 |
| 模块时间 | `demo/closed_loop/lock_transition`时长与边界一致 | 会话事件、配置哈希 |
| 呼吸协议 | 步骤表、目标时长、周期和v2.2协议配置哈希一致 | 协议配置、遥测 |
| 目标事件 | `target_cycle_index/step_id/progress`逐帧一致 | 20 Hz fixture与重放哈希 |
| 实际事件 | 使用同一交互状态估计算法、版本、输入字段和置信语义 | 算法版本、遥测、回放 |
| demo引入 | 首周期目标、第二周期实际淡入时点与长度一致 | 事件日志、录像 |
| 基础场景 | 同一天气背景、图层、随机种子、地标、光照和非周期性运动 | 场景配置、截图、录像 |
| 相机与卷轴 | 同一方向、速度、视差、暂停恢复和安全区 | 相机日志、帧录像 |
| 累计状态 | 同一`recovery_value`、函数、时点和环境变化 | 遥测、参数日志 |
| 降级 | 同一状态、原因、起止时间及受影响信息类别 | 降级fixture、录像 |
| 声音 | 同一背景声、音量、转场和无步骤音规则 | 音频配置、录制 |
| 转场 | 同一山雾长廊、时长、加载时点和下一场景基线 | 转场事件、录像 |
| 运行环境 | 同一Unity构建、显示器、分辨率、亮度、观看距离和帧率目标；仅`cue_mode`不同 | 构建哈希、工位检查表 |

## 2. 唯一处理差异

| 条件 | 目标与实际表示 | 关闭内容 |
|---|---|---|
| `scene_native` | 前方中远景环境机制表达目标，当前近景环境痕迹表达实际 | 居中双环 |
| `abstract_pacer` | 居中外环表达目标、内环表达实际 | 场景原生目标/实际步骤动画 |

两条件继续共享累计环境变化。不得把双环称为无语义、无视觉设计或纯功能基线。

## 3. 必须测量并报告

以下差异属于完整表示方案的组成，原则上不能逐像素消除，但必须在冻结画面中测量：

| 指标 | 核对内容 | 使用方式 |
|---|---|---|
| 提示像素面积 | 目标和实际可见像素占画面比例 | 发现极端面积失衡 |
| 空间偏心 | 提示信息相对视点中心的位置 | 描述中央双环与环境提示的位置差异 |
| 运动能量 | 步骤事件前后的像素变化 | 检查任一条件是否用更强动态抢占注意 |
| 显著度 | 提示区相对背景的预测显著度 | 形成调整候选，不替代真人审查 |
| 遮挡 | 提示与保护区、目标/实际相互遮挡 | 阻断信息不可见片段 |
| 视觉复杂度 | 边缘密度、对象数量和动态层数量 | 记录完整方案负担 |
| 心智努力 | 形成性评审中的主观负担 | 与理解结果联合判断 |

这些指标不得被解释为已经控制了单一机制，也不得用总分掩盖某一信息层明显受损。

## 4. 直接阻断

出现任一项时，不进入正式比较材料：

1. 抽象条件的天气背景泄露目标或实际周期；
2. 任一条件增加步骤文字、倒计时、条件特有声音、奖励或分数；
3. 场景原生实际层复制、吸附或读取目标值；
4. 两条件使用不同延迟、平滑、帧率、累计变化或降级时点；
5. 为补齐面积或动态量而加入没有功能语义的运动元素；
6. 任一条件中目标、实际、累计或降级信息不可辨认；
7. Unity构建、协议哈希、资源版本或显示环境不一致。

## 5. 验收

1. 使用同一fixture同时录制两条件四模块完整材料。
2. 自动比对事件真值、时长、累计、降级、转场和配置哈希。
3. 输出七类视觉与心智差异报告，不隐藏越界项。
4. 由未见条件标签的审查者判断四层信息是否可辨认。
5. 所有硬匹配项通过、阻断项为零后，才可进入后续形成性评审。
