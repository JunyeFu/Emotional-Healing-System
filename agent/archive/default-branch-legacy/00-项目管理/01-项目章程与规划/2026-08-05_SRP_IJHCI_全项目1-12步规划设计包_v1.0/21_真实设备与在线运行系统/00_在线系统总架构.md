# 在线系统总架构

## 单一权威

Python拥有会话状态、单调时间、目标协议、顺序分配核验、设备与信号质量、交互状态估计、关键事件、降级决策与原始记录。Unity是参与者呈现和控制镜像，TouchDesigner是实验员观察与受控请求端。

Unity不依赖TD或Spout完成参与者体验；正式模式仍必须依赖已验证的Python manifest、控制与记录链。“无TD”不等于“无Python”。

## 通信与身份

TCP仅绑定`127.0.0.1:5010`，传输UTF-8 JSON Lines角色握手、关键控制、ACK和渲染回执。UDP 5005/5006以不超过20Hz向TD和Unity镜像自包含状态。具体字段以运行合同和F-05 v2.2接口基线为准。

会话、控制、模块位置、周期和步骤均有身份。目标和实际步骤分别表示；重复步骤由`step_id`区分。实际状态未知时为空，不能从目标、进度回零或历史帧猜测。

## 实现边界

P-01提供确定性会话内核和本机传输；P-02通过同一记录代理先保存权威调用和输出再交付；T-01消费只读遥测。各任务签收只覆盖精确候选。

F-05 v2.2修复步骤身份，不等于自适应顺序已经完成。阶段一保持预分配完整顺序；阶段三实时编排由X-03另行定义版本化决策合同，记录截止时点、合法动作、概率、策略版本、理由、回退与执行回执。

## 呈现、记录与质量

Unity负责四层视觉、渲染回执和本地安全呈现，不能修改条件、协议或阈值。TD只显示设备、波形、目标/实际、SQI、延迟、降级和事件；T-02仅提交请求，Python决定接受或拒绝。

输入中断不切换模拟数据；TD失联不影响主体验；关键控制不能只走UDP。降级、暂停、中止和退出均记录原因与区间。原始设备流、控制与渲染事实、问卷、分配、标注、配置和构建共同组成原始证据束，在线事实不能被离线重算覆盖。

I-01必须在同一候选树、真实双设备、当前资产与环境下运行无TD完整800秒、外部呈现延迟、压力和故障测试。逻辑重放和单元测试不能替代该证据。

## 正式装配门

正式入口必须确认实际适配器、环境、设备、机构与量表资格、身份去重、分配、记录、构建和资产用途。缺任一必需证据保持失败关闭。MCP和Agent只存在于开发平面。
