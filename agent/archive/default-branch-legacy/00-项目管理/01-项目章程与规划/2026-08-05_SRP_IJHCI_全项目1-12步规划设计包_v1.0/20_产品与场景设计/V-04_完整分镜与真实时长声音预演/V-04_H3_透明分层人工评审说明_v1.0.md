# V-04 H3 透明分层人工评审说明 v1.0

## 评审对象

逐天气查看`alpha_contact_sheet`和`solo_layers`，必要时再查看4K单层PNG及重组视频。storm、heat、snow、fade均需独立判断，不以机器门替代人工画面判断。

## 每个天气六项

| 编号 | 项目 | PASS标准 |
|---|---|---|
| R1 | 重组一致性 | 重组画面与已确认固定底片在构图、色彩和细节上无可见差异 |
| R2 | 深度顺序 | 7层从天空到最近景的遮挡关系自然，无明显倒置 |
| R3 | 透明边缘 | 冻结顺序叠放后的可见边缘无显著光边、黑边或透明脏像素；被下一层遮挡的隐藏延展不单独判错 |
| R4 | 结构与安全区 | 固定镜头构图不变，目标与角色安全区未被错误切断 |
| R5 | 语义纯度 | 每层主要承载合同规定的空间层级，不混入明显跨层主体 |
| R6 | 交接可用性 | 层名、画布、原点、排序和预览足以让Unity执行者按固定顺序直接导入，且不误启用单层移动、替换或视差 |

共`4 x 6 = 24`项。仅当24项全部PASS时，团队总监可确认H3通过。

## 记录格式

```text
storm: R1=PASS R2=PASS R3=PASS R4=PASS R5=PASS R6=PASS
heat:  R1=PASS R2=PASS R3=PASS R4=PASS R5=PASS R6=PASS
snow:  R1=PASS R2=PASS R3=PASS R4=PASS R5=PASS R6=PASS
fade:  R1=PASS R2=PASS R3=PASS R4=PASS R5=PASS R6=PASS
H3=PASS
```

若有不通过项，应写明天气、编号和需要调整的边界位置；H3保持未通过，修订后生成新候选目录，不覆盖旧候选。
