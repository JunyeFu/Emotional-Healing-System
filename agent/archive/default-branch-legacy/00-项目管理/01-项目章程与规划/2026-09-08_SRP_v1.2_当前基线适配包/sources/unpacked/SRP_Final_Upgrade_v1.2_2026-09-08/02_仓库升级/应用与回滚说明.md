# v1.2 应用与回滚说明

## 交付是什么

这是新增文件overlay与定点变更工具，不是完整仓库zip。没有复制Unity资产、全部源码或第三方论文。现有源文件在本地读取并修改，以保留未涉及字段与历史DONE；不是用缩写表替换整个注册表。

基线仓库：`JunyeFu/Emotional-Healing-System`，HEAD必须为`145f7b20b5e2b3453235fb79090b982785b4c5a3`。当前远端已复核同一快照；你的未推送状态未被读取。

实际变更：新增v1.2目录与根入口；给README/AGENTS加升级说明；按ID改变15项旧任务的指定字段；添加12项UP任务。运行源代码不修改，旧v1.1与运行v2.2不改。70节点是目标图，不是70项任务都已完成。

## 先审阅

`task_mutations_v1.2.json`含每个旧任务的预期依赖及将写入字段；`new_tasks_v1.2.csv`只含12项新增任务；`历史DONE影响与复核.csv`保留16项历史制品与新复核关系；`overlay/`是新增内容。

本包没有取得可落盘的完整源工作树，完整旧CSV不随包重发。图由同一快照的读取整理；真正应用时必须从本地git对象核验SHA，并核对全部58个旧任务与目标图。没有测试原仓库所有验证器；若其限制任务ID前缀、字段或术语，UP-01须进行显式兼容迁移，不能忽略失败或删除真实限制说明来冒充通过。

## Windows操作

将zip解压到仓库以外，例如下载目录。保持当前目录为解压后的包根目录。

```powershell
$bundle = (Get-Location).Path
$repo = 'D:\Agent\03-SRP'

git -C $repo status --short
py -3.14 "$bundle\03_工具与验证\validate_bundle.py"
py -3.14 "$bundle\03_工具与验证\apply_upgrade.py" --repo $repo --check
```

只读检查核对：干净工作区、HEAD、README/AGENTS/任务表/旧机器权威四份git blob、包校验和、新增路径、旧依赖、历史DONE与目标图。拒绝不是损坏源文件，脚本不会替你reset或clean。

审查后在独立分支应用：

```powershell
git -C $repo switch -c upgrade/srp-v1.2-emotion-comparison
py -3.14 "$bundle\03_工具与验证\apply_upgrade.py" --repo $repo --apply --backup-dir 'D:\SRP-Backups\v1.2_2026-09-08'
git -C $repo diff --stat
git -C $repo diff -- README.md AGENTS.md
```

备份目录必须尚不存在，且在仓库/升级包之外。目录中的`receipt.json`记录每个目标的前后SHA-256与是否新增。脚本不commit/push，不启动研究。分支名字和备份路径冲突时换一个新名字，不删除已有数据。

随后本地Agent完成UP-01，检查真实任务表和所有消费入口的兼容性；优先UP-06接入正式运行拒绝门，再推进测量、SAP与真实准入。`formal_participant_collection_allowed=false`在未读取此字段的旧程序中没有自动强制效果。

## 已有本地修改或HEAD不同

不要为套用包而恢复旧快照。保留已有改动，由本地Agent在当前HEAD逐条复核语义变更，重新产生来源哈希和迁移记录。工具没有force选项，因为不能静默推断新的仓库内容。

## 回滚

在没有对被升级文件再作修改、HEAD未改变时：

```powershell
py -3.14 "$bundle\03_工具与验证\apply_upgrade.py" --repo $repo --restore-from 'D:\SRP-Backups\v1.2_2026-09-08'
```

只恢复备份中原有文件并移除本次新增文件；不执行git reset/clean，不回滚其他内容。检测到后续用户编辑则拒绝，避免覆盖新工作。中断恢复须先读receipt与实际diff；应用过程普通写入异常会尝试恢复已写目标，但电源中断等不能等同可保证的跨文件原子事务。
