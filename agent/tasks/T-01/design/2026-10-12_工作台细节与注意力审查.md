# 工作台细节与注意力审查

日期：2026-10-12。对象：当前 A 主题 TD 原生工作台，源码基线 47131de1。使用当前构建器在独立副本中重新走过流程；原有工作台保持打开。审查只增加取证工具和报告，未修改工作台呈现。

## 结论

现有设备分组、六种曲线切换、单窗口阶段切换和独立场次记录值得保留。主要问题是信息优先级和状态对象：运行页没有突出正在记录的事实，准备信息持续占用右侧，当前流程信息没有完整接到侧栏，历史页容易把当前场次和选中记录混在一起。

它需要一次以操作任务为中心的信息重排。仅增加颜色、边框或把文字全部居中不能解决上述问题。

可直接看 [逐页图文审查](2026-10-12_工作台逐页审查.html)。本轮原生证据在 [审查目录](../evidence/audit-20261012-151235/README.md)。

## 2. 工作台应该让操作员回答什么

| 阶段 | 必须快速回答的问题 | 需要显示的事实 | 当前情况 |
|---|---|---|---|
| 主页面 | 系统是否可开始准备？是否有上一场未收尾？ | 服务与设备概览、未收尾任务、上一场简要结果、准备入口 | 有入口与计数；服务概况是说明文字，缺实际状态摘要。 |
| 准备 | 哪些已经就绪，哪些仍缺？ | 匿名编号/分配、前测、Unity、记录准备、设备数据、操作许可 | 大多已有，但平均排列；禁用蓝按钮和大片“未接入”不利于定位缺项。 |
| 等待开始 | 准备完成了吗？开始请求到哪里了？实验是否已记录？ | 已准备、等待 Unity/收到请求/等待 Python 确认、尚未记录 | 底部有准确状态；视觉主体仍是普通监控页。 |
| 运行 | 当前是谁、什么天气和段？采集与记录是否正常？是否需要处理？ | 匿名编号、条件、天气/位置/段、记录状态、两个设备的连接/质量/新鲜度、呼吸/ECG、HR/RR、必要的引导对照 | 设备波形和值已有；运行上下文和记录事实不完整或不显著。 |
| 暂停 | 体验是否暂停？记录是否继续？如何恢复？ | 暂停状态、有效/总时间、持续记录事实、恢复动作 | 行为已实现；视觉强调和时钟位置不合适。 |
| 收尾 | 体验结束还是整个收尾结束？还缺什么？可以准备下一位吗？ | 正常/中止及原因、有效时长、真实封存、后测、导出、下一步许可 | 有基本字段和门控；缺强明确的收尾结论与集中待办。 |
| 历史 | 正在查看哪一位、哪一场？文件是否完成保存/导出？ | 开始时间、匿名编号、条件、时长、结束状态、封存/导出、明确选择 | 表格过于工程化，选中对象不突出。 |
| 明细 | 是哪一层出了问题？有什么原始证据？ | 设备/信号/记录/链路分组、原始字段和来源 | 当前有完整原始字段，但入口名称及默认顺序不合适。 |

上述内容只能显示真实已有输入。没有 P-01/P-02/设备回执的项目显示等待、未知或暂不可用，不用波形在动推断记录正常，不自行创造质量阈值。

不需要在监控主屏增加 PANAS 得分排行、情绪成效指数或更多设备。情绪结果的正式比较仍属于锁定分析；TD 主屏服务采集、运行与记录核查。

| 主页大标题 | 主屏非必须 | 再次重复工作台名称 | 缩小或合并，把区域给系统就绪及未收尾任务。 |
| “新建实验准备” | 必须 | 居中主动作明确，是现有优点 | 保留主入口；可用性与准备状态就近关联。 |
| 主页第二个历史按钮 | 功能需要 | 与导航入口重复 | 保留一种明显入口；按高频实际使用选择位置。 |
| “Python/Unity等待模拟桥回执” | 当前状态需要 | 仍偏实现语言，没有明确阻断项 | 改为操作员能识别的服务就绪摘要。 |
| 完成/中止/待收尾计数 | 需要概况 | 主页位置合理，待收尾不够突出 | 保留，未收尾应能定位对应记录。 |
| 收尾页第二个大标题 | 状态需要 | 与上两条标题重复 | 一条清楚结果：“体验已结束，记录待封存/收尾完成”。 |
| 会话、结果、有效/总时间 | 必须 | 表格清楚但UUID主导、计时重复 | 匿名编号与场次时间优先，时钟显示一次。 |
| 记录封存和后测 | 必须 | 两个完成门合理，缺集中结论 | 合并成收尾清单；处理中的动作与主要按钮相邻。 |
| 打开目录/导出CSV | 必须可达 | 路径与成功对象不够直观 | 明确导出对象、预览/封存状态、完成反馈和打开位置。 |
| “完成收尾并准备下一次” | 必须 | 长文案、与待办隔着大空白 | 简化为“准备下一位”，保持真实门控。 |
| 返回主页 | 需要 | 是次级动作 | 保留，视觉上弱于准备下一位；阻断原因就近。 |
| 历史表五列 | 必须有记录列表 | 缺辨认场次的字段，更多像日志 | 以时间、匿名编号、条件、状态、有效时长、封存/导出为主。 |
| 行内“查看”与选中态 | 必须 | “查看”操作无明显选中行强调 | 选中行高亮并显示记录摘要；点击对象稳定。 |
| 行下的UUID文件路径 | 调试需要 | 小字路径不能代替历史摘要 | 正常摘要用人可读字段，路径放可复制的详情。 |
| 历史导出按钮 | 必须 | 无选择仍可用且回退当前场次 | 修正对象与禁用态；不能用文案掩盖数据选择逻辑。 |
| 明细原始字段表 | 工程人员需要 | 当前默认占据整页，首屏不能回答设备问题 | 按设备/质量/记录/链路分组，原字段可展开。 |

## 4. 对注意力的判断

本次没有测量操作员眼动。以下是根据实际任务和画面作出的设计判断，不能写成已证明阅读效率提升。

没有一个可以机械套用的“人类视觉中心”。这套工作台应建立稳定的任务锚点：先看到当前阶段与记录，再判断设备数据是否可用，再读最近曲线与引导对照，最后选择必要动作。变化的曲线和高对比蓝按钮容易成为视觉重点，因此关键运行状态应拥有清楚、稳定的层级。

建议维持“状态/记录 → 设备与信号 → 当前引导/实际 → 操作”的扫读路径。字段名左对齐、可比较数值右对齐、少量状态居中；不要把整屏全部居中。

视觉层级用于表达先后重要性，可以参考 [NN/g视觉层级](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)。分组与标题用于让人找到相关内容，可参考 [分层扫描研究](https://www.nngroup.com/articles/layer-cake-pattern-scanning/)。它们来自一般界面研究，不能直接当作本工作台的眼动实验结果。

仪表板研究把数据、元信息、视觉编码和交互分别考虑，支持本次把固定设备/协议元信息移出高频监控区的选择，见 [Dashboard Design Patterns](https://arxiv.org/abs/2205.00757)。

颜色需要与文字、X/Y/Z标签和状态名称共同使用，可借鉴 [W3C颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。本轮没有完成键盘、焦点、辅助技术和完整对比度评估，不能宣称TD程序符合WCAG。

## 5. 建议的呈现层级

### 主层：每次扫读都能看到

- 当前匿名编号、条件、阶段、天气/位置/段。
- 实际记录状态、有效用时与总历时、当前需要处理的异常。
- 呼吸与ECG常用图、两设备连接/质量/数据新鲜度，HR/RR当前值。
- 运行期必要的基准节律、当前引导、呼吸估计对照。
- 当前阶段的一项主要操作和少数次级操作。

### 条件层：在对应阶段或问题出现时显示

- 准备与等待：分配、前测、Unity与记录准备清单。
- 有异常：当前问题、受影响来源、已恢复或持续状态、缺失区间。
- 运动排查：加速度/角速度及各轴量程。
- 收尾：结束原因、封存、后测、导出和下一位准备。

### 明细层：需要核查时展开

- 完整UUID、型号、SDK/配置版本、原始采样率。
- 协议、端口、刷新上限、帧序号、原始时钟和同步参数。
- 完整文件路径、原始字段、事件/控制确认记录。

删除或合并的是重复呈现，不删除实际记录中的字段。

## 6. 各阶段的改进顺序

1. 主页：保留清楚的准备入口，用实际就绪及未收尾摘要替换重复标题和实现说明。
2. 准备：准备清单是主要任务，明确待办及禁用原因，曲线用于设备核查。
3. 等待：主要区域说明开始请求所处状态，“未开始记录”明确可见；曲线作为预览。
4. 运行：身份、场景和记录构成主状态条；呼吸/ECG成为主要绘图区；已通过准备项收起。
5. 暂停：保持数据显示，突出暂停与记录继续，两个时钟相邻，恢复操作就近。
6. 收尾：区分体验结束与收尾完成；封存和后测形成集中清单；准备下一位为主操作。
7. 历史：以人的记录信息辨认场次，选择高亮，详情与导出严格使用同一对象。
8. 明细：按设备、质量、记录、链路组织，原始字段保留在调试层。

仍使用同一个窗口，按阶段替换主体内容。
