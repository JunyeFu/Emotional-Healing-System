# TD 开发会话后端接线

## 本轮用途

原生 TD 页面继续使用单窗口流程。本轮把自动演练中的准备、暂停、继续、中止、自然完成与封存结果，接到现有 P-01 SessionCore 和 P-02 RecordingSessionCore / DurableManifestStore。页面按钮生成的请求先写入 operator-requests.jsonl，演练器读取对应请求后执行后端，不再直接宣告处理成功。

这是开发联调入口，不是已部署的 T-02 通用操作服务。单独打开候选 TOE 不会自动启动 Python 后端；真实设备、Unity TCP 端点、问卷服务和正式准入仍需分别接入。任务状态不变。

## 运行方式

在 D:\Agent\srp 中运行，先关闭上一次专用演练候选，不关闭其他人的未保存工程：

```powershell
py -3.14 agent/tasks/T-01/execution/capture_workbench.py --study agent/local/artifacts/physiology-study-20261008 --backend --speed 5
```

输入使用上一轮生成的 A 和 abort 数据。目标回放倍率为 5，受实际磁盘写入速度限制，不用这一轮推断实时性能。原有不带 --backend 的 A/B/中止页面演练入口保留。

## 页面与记录的对应关系

1. 准备页可查看设备，但不向本轮 P-02 L0 写入预检样本。
2. 提交准备后，P-01 校验开发 manifest，P-02 排他创建记录；模拟 Unity 端确认 prepare。
3. 模拟 Unity 开始操作触发 P-01 start。之后每批合成传感器数据先写 P-02 L0，再发送到 TD。
4. 暂停和继续交给 P-01，继续使用 start 恢复。四天气顺序与有效时长由 P-01 决定；页面时钟与后端快照逐帧核对。
5. 完成必须由 P-01 第四模块结束产生；中止必须消费 TD 的中止请求。不能只因输入文件到末尾就宣告完成。
6. P-02 finish、seal、完整性验证和确定性重放均通过后，才发出封存成功。后测回执仍为单独的模拟输入，不由存储结果推断。
7. 当前记录和历史记录继续使用 TD CSV/ZIP 导出。验证器逐包比较 P-02 L0 与 TD 记录，再与源数组核对；两种记录不相互替代。

## 数据处理分工

- 合成波形、呼吸估计、ECG 峰值及描述性 RR 指标：沿用 Python 模拟与分析工具。
- 会话状态、有效时间及控制：P-01；控制 ACK 来自模拟 Unity 端，不是实际画面回执。
- 原始输入与核心调用记录、封存及离线重放：P-02。
- 波形切换、状态查看、分秒显示与开发记录导出：TD。不在 TD 内另算一套研究指标。

L0 保存的是合成传感器域 JSON 原始字节，并非 Polar/PLUX 的真实通知包。缺失采样仍为 null，未改写成零。manifest 使用 dev_replay / replay；正式能力始终为 false。

## 与新设计的关系

本轮只接固定 A 路径，B 请求明确返回 ADAPTIVE_B_NOT_IMPLEMENTED。现有 v2.2 固定序列和 800 秒候选只用于接口演练，不能替代新设计中 B 的受限适应、教学测量流程或正式时长冻结。I/G/X 的模拟显示不被当作真实控制策略验收。

## 本轮发现并修正的问题

- 完整 sha256 摘要中的数字曾被隐私检查误判为手机号。仅完整、带类型前缀的 64 位十六进制摘要不再按自由文本号码扫描；禁入字段和实际联系方式检查保留。
- Windows 在高频尾记录原子替换时出现 WinError 5。仅对同一替换的 WinError 5/32 最多尝试三次、间隔 20 ms；不重复追加原始记录，持续失败仍报错。
