# B-01【研究批次】Level C会话批次模板

注册为TEMPLATE、BLOCKED_EXTERNAL，依赖Q-03|E-02，每实例最多12人，约1至5人日；模板不是已执行实例。当前负责人、分支及审核人未落实，不创建虚拟批次或代签真人结果。

## 目标与验收

在真实获批范围、可用Level C分配及真机记录链就绪后，执行单条件、单次核心体验，立即核查批次并向E-03交接。

- AC1人员跨阶段唯一，manifest与会话身份唯一；暴露后不再参加其他阶段，也不重跑核心体验。暴露前释放使用G-02既有规则。
- AC2双设备原始流、运行事实、前后量表、分配、标注及配置/构建身份按实际记录；缺失明示原因，不补零或用fixture替换。参与者核心期间平坐观看，无界面作答。
- AC3封存归档与RawEvidenceBundle按既有校验器核查，批次覆盖、两条件分配平衡及偏离有据可查。缺失或未封存不能写PASS，技术延迟不能用render_receipt冒充外部观测。

当前锚点48人、每条件24人，每实例最多12人。平衡按已分配而非完成；最终可用数及退出不足交E-03/研究负责人裁定，不能擅自定向补人。详见outputs/current-batch.md。

## 四段过程

1. 实例准备：活动负责人核对Q-03工具、E-02真实关闭、Level C实际许可、量表权限、真机链和分配来源；记录批次身份、负责人及精确材料版本。工作人员演练与真实批次分开。
2. 会话前检查：操作员核对去重预约、单条件分配、唯一manifest、P-02正式环境与构建；前测和教学顺序沿当前冻结合同，不能自行改研究时序。
3. 真实执行：同一RecordingSessionCore负责记录与控制，G-02在核心start前登记暴露；双设备采集、800秒推荐核心与后测按冻结候选执行。暂停、中止、断流及帮助实际记录，不能恢复中断体验进度或事后补造ACK。
4. 批次关闭：只读校验封存/六类原件，记录分配、暴露、完成、停止、未暴露取消与每条件覆盖；移交缺失、原始偏离、独立标注及真实QC给E-03，明确剩余条件。

## 责任与入口

活动负责人对批准、人数口径与闭环负责；操作员负责现场/设备/量表与会话记录；Q-03工具负责人负责Level C分配/manifest/盲态报告；两独立标注者和第三裁定者负责Actual原始标签；数据负责人负责封存与受限原件；E-03负责人负责跨批次汇总，另一人按精确对象复核。当前均待实名落实，Agent本轮只整理与软件核查。

`outputs/batch-register-template.csv`只提供空表头；`outputs/batch-qc-template.json`只提供NOT_RUN骨架，不是运行合同或QC判定器。实际填表及受限原件置于获批仓库外，不提交身份、联系方式或映射回仓库。共享会话/存储/去重代码仍在模块权威路径，TASK只引用。

从根目录运行`py -3.14 agent/tasks/B-01/execution/verify.py`，检查模板、实际接口及既有合成行为，不启动Unity、TD、设备或真人活动。
