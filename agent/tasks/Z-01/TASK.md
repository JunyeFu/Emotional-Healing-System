# Z-01 构建交付 干净检出复现与候选制品

## 范围与责任

注册状态WAIT_DEP，依赖I-01、A-02、A-03、U-08、G-02，约5人日，岗位P-DELIVERY；领取人、执行分支和复核人未指定。本轮整理与环境权威订正不是候选制品已验收，不替团队领取或签收。

Python拥有会话流程和时钟，Unity独立运行完整体验，TD是操作台。Z-01整合三个交付单元及离线样例，不写研究算法、不放宽许可、不用开发EXE替代U-08/I-01成品。

## 五日过程

1. 接收：核对上游实际交付、提交、运行合同、环境与许可；指定交付负责人及独立重建者。固定本次候选输入，不使用成员缓存补缺。
2. 环境：从指定提交干净检出、取回LFS原件，在独立环境安装完整Python传递依赖锁；记录Unity revision、包锁、TD Build及设备SDK前置。工具可用与构建复现分别验收。
3. 制品：用U-08实际构建入口生成参与者制品，装配Python运行环境与TD操作台；核对协议/配置/步骤版本和实际启动路径。Unity不依赖TD/Spout；不得设置开发授权绕过正式候选门。
4. 样例与清单：用明确合成输入重建离线样例，受限原件留仓库外。为实际发布文件及其运行依赖生成SBOM、许可证清单和字节校验和，记录代码版本及重建命令；资源许可报告与完整SBOM不能互相替代。
5. 独立复现：另一人从干净环境重建并启动三个匹配制品，执行无TD运行及接口核对，保存日志、差异和修复复测。形成候选审阅包，独立复核与真实第二人通过后才转DONE；后续阶段锁定仍归G-03/G-04。

## 验收

- AC1：独立干净检出可按命令或文档重建；不能把当前机器的开发构建或缓存当作证据。
- AC2：Unity、Python、TD版本身份与协议配置匹配；实际流程/回执/记录一致，无TD完成Unity体验。
- AC3：实际候选完整环境锁、SBOM、许可与制品字节哈希清单齐全，资产门未清零阻止发布。候选不是正式阶段锁定或公开批准。

执行核查：`pwsh -File agent/tasks/Z-01/execution/verify.ps1`，只验证当前环境权威、真实资产门与已存在历史材料，不能证明上述完整候选验收。
