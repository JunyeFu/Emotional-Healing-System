# V-05 四模块全旅程灰盒与形成性回退门

## 状态与责任

注册表READY，依赖F-03、U-02、V-04，约5人日，过程配置P-DEV。实际领取人及复核人未指定；过程配置不是已落实的责任人。当前只做任务包规范化与主机侧流程检查，不代为领取或签收，不把READY改成DONE。

## 交付与验收

交付完整灰盒、24顺序报告、双条件占位、构图节奏转场检查和形成性问题关闭矩阵。

- AC1使用DEV-REPLAY记录fixture完成任意合法manifest顺序且四模块各一次不依赖参与者操作。
- AC2简单色块占位声音和标签即可核对构图提示节奏转场及两条件信息匹配。
- AC3关键不理解遮挡节奏断裂或条件不匹配必须回退V-02至V-04关闭且评审人员不进入正式样本。

必需证据是Unity Edit/Play测试、24顺序报告、完整灰盒录像、真实形成性评审表和问题关闭矩阵。本轮主机矩阵不是这些证据全部齐备。

## 五天过程与阶段出口

1. 领取并核对当前V-01旅程、V-03映射、V-04交接和F-05步骤合同；确认Python流程权威及独立素材策略。出口为明确的旅程、灰盒对象和输入基线。
2. 在权威Unity工程建立DEV-REPLAY灰盒，覆盖中性准备、前测边界、条件教学、中性入口及四模块；前后测外置，不读取答案。出口为可启动的灰盒，不借旧场景表示完成。
3. 接入U-01控制镜像及U-02四层适配；24顺序×两条件同源fixture，暂停、中止、空Actual、降级和累计锁定不串扰。出口为Edit/Play结果、真实画面和对应回执。
4. 贯通结束、先后测再其他问卷和数据检查，录制完整灰盒；核对固定镜头、fade有效时间复色与水系提示分离。出口为核心800秒与外部旅程分别计时的录像，评审HUD不混入参与者画面。
5. 真实评审人检查理解、遮挡、节奏、转场、同源信息；关键问题归V-02至V-04修订、回测再签收。出口为有对象版本、问题、责任人和关闭证据的记录，之后才解锁U-03。
