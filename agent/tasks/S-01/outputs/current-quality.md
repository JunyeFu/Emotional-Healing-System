# S01 当前同步与质量交接

## 结论与实际代码

S-01为WAIT_DEP、未领取，D-01/D-02真实接口未完成。当前没有设备时钟映射、实测SQI算法、质量配置或双真机误差报告。旧SignalPipeline的warmup/valid/invalid不是合同四状态，也没有双时钟校准。

本轮修复DeviceManager连接即good的错误：数据流启动成功后才标记已连接，质量字段保持unknown。该字段是旧字符串状态，不是正式v2.2数值SQI；本次不添加无真实数据依据的质量阈值。

## 时钟与记录

原件保留各设备时间、主机接收单调时间、设备时钟域和包序号。S-01将设备时间映射到Python会话时间，设备重置或重连的时钟连续性要由SDK与记录验证，不能仅按主机到达时刻宣称采样同步。

合同现有偏差clock_offset_ns、不确定度sync_uncertainty_ns使用ns，漂移clock_drift_ppm使用ppm；遥测source/received/sent时间按顺序非递减。P-02原件设备时间可以null，F-01/F-05遥测三个校准量必须是有限数；不知道时不能填零或NaN制造合法遥测。实际接入须先取得校准估计，不能满足时记录缺口并通过已有连接故障/降级流程处理。合同不在本包改写。

校准输入和结果记入L1，原始L0不覆盖；在线估计与离线重算各自标识。误差、漂移和不确定度的验收值仍待技术预试冻结，不把fixture常数写成实测精度。

## 质量与下游职责

GOOD、DEGRADED、UNUSABLE、DISCONNECTED是质量/降级状态；设备连接状态的健康枚举是CONNECTED，不是GOOD。分通道保存resp/ecg质量及原因，连接本身不证明信号可用。非GOOD必须有fallback_reason，缺样、失真、未校准和断连不能默认为成功。

S-02依据可用原生信号生成Actual步骤/周期和在线PF，不能由质量不足构造新成功事件。U-02已实现的低确定性与不可用显示属于消费端；其0.7显示候选上限不是SQI阈值，不在S-01重新设计视觉规则。Target与会话顺序和时长仍由P-01决定，TD只读监控。

D-01/D-02交原生样本与通知，S-01做同步和质量，S-02做交互状态估计，P-02追加保存，I-01取双设备全链证据。丢包/漂移/断流故障报告、真实设备校准及责任人仍待交付；软件合同测试不关闭UP-06。
