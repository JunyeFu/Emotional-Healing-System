# F-05 v2.2接口对齐基线

> 状态：`IMPLEMENTED_CANDIDATE`
> 日期：2026-08-31 +08:00
> 适用任务：F-05；下游U-01、U-02、T-01、U-07只消费签收后的版本

## 1. 权威与不可变项

1. `runtime-contract-v2.1.schema.json`、v2.1 fixture、哈希和F-01签收记录保持不可变。
2. v2.2使用新Schema、新fixture和新哈希，不把新增字段伪装成v2.1前向兼容字段。
3. Python继续拥有会话、顺序、目标协议、单调时间、交互状态估计、降级和记录权威。
4. Unity与TouchDesigner只消费自包含帧，不得从粗相位、进度回零或帧历史推断步骤实例。

## 2. 外部seam

P-01与P-02继续只调用：

```python
validate_message(message_type, payload) -> filtered_payload
```

版本分派、Schema选择和字段过滤位于该seam内部。调用方不得直接导入某一版本的字段表。`SessionCore`在`prepare()`后保存manifest中的会话Schema版本，并以同一版本生成控制消息、传输握手和遥测验证上下文。P-02只保存已校验结果，不修改步骤、周期或进度。

## 3. v2.2新增字段

### SessionManifest

| 字段 | 类型 | 规则 |
|---|---|---|
| `breath_protocol_config_version` | 非空字符串 | 指向独立呼吸步骤配置版本 |
| `breath_protocol_config_hash` | `sha256:<64个小写十六进制>` | 必须与Python加载的配置字节一致 |

### TelemetryFrame

| 字段 | 类型 | 规则 |
|---|---|---|
| `target_cycle_index` | 非负整数或`null` | 模块内从0开始；无活动目标步骤时为`null` |
| `target_step_id` | 稳定步骤ID或`null` | 与`target_cycle_index`同时有值或同时为`null` |
| `actual_cycle_index` | 非负整数或`null` | 仅来自交互状态估计；不可判断时为`null` |
| `actual_step_id` | 稳定步骤ID或`null` | 不得用目标步骤补值 |

`target_progress`和`actual_progress`只表示当前步骤内部的`0..1`进度。步骤对为空时，对应粗相位必须为`none`且进度为`0`。步骤对有值时，粗相位必须与冻结步骤表一致。

## 4. 冻结步骤身份

| 模块 | 顺序 | 粗相位 | 已冻结时长 |
|---|---|---|---|
| `storm` | `inhale_1 -> hold_1 -> exhale_1 -> hold_2` | `inhale -> hold -> exhale -> hold` | `3 / 3 / 3 / 3`秒 |
| `heat` | `inhale_1 -> exhale_1` | `inhale -> exhale` | `4 / 6`秒 |
| `snow` | `inhale_1 -> exhale_1` | `inhale -> exhale` | `5 / 5`秒 |
| `fade` | `inhale_1 -> inhale_2 -> exhale_1` | `inhale -> inhale -> exhale` | `2.5 / 1.5 / 6`秒 |

冻结配置为`02-技术研发/srp_session_core/config/breath_protocol_config_v2.2.json`，其规范化SHA-256为`sha256:e5bb3c609f069a31bf9d02af1c987ccafc2be8d4fd01ca2394565c0c10d4a203`。`fade`参数采用V-04候选v10已通过团队总监H2机器门的时间表，作为F-05工程协议输入；不表示效果优劣结论。

## 5. 暂停、重连与重放

- 暂停不推进周期、步骤或步骤内进度；恢复继续同一身份。
- 重连后的第一帧必须自包含，不依赖断连前一帧。
- 重复帧和乱序帧不改变合同字段；序号处理仍由各消费者所属任务实现。
- P-02按原值保存四个新增字段；同一记录链重放必须得到相同字段和最终哈希。
- 目标与实际可以处于不同步骤和周期，消费者不得互相借值。

## 6. 正式模式迁移门

| 模块 | F-05负责 | 不由F-05实现 |
|---|---|---|
| F-01合同 | v2.2 Schema、参考校验、正负fixture、哈希 | 修改v2.1 |
| P-01 | 按会话版本校验和发消息；正式模式要求v2.2握手与配置哈希一致 | U-01重连和Unity运行实现 |
| P-02 | 保存与重放v2.2字段，证明确定性 | 改变会话状态或推断步骤 |
| Unity | 提供可供U-01/U-02消费的合同fixture和失败样例 | `SceneAdapter`、渲染或ACK实现 |
| TouchDesigner | 提供可供T-01消费的合同fixture和失败样例 | UDP 5005、20Hz或页面运行逻辑 |

正式模式下，manifest仍为v2.1、握手版本不等于活动会话版本、缺少呼吸配置哈希、哈希不一致或四个遥测字段缺失时均失败关闭。开发回放可以继续使用v2.1，但不能证明`storm`双停或`fade`双吸运行接口成立。

## 7. 当前实现缺口

1. v2.2 Schema、参考校验器、配置、P-01/P-02版本分派和合同fixture已经形成候选；v2.1文件与hash保持不变。
2. P-02按原值保存v2.2步骤字段，并以同一归档重放验证最终哈希。
3. Unity与TD仅获得消费fixture和迁移指南；没有在F-05中实现运行消费者。
4. 第二人复核前，U-01、U-02、T-01和U-07不得把F-05依赖视为完成。
