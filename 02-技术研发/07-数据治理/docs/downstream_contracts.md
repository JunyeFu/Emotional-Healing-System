# G-02 下游消费合同

> 这些规则是P-01、P-02、X-01、Z-01和W-03的强制门。调用方不得复制G-02内部令牌、绕过失败结果或自行扩大身份字段。

## P-01 会话编排

1. 生成候选manifest后先调用`privacy_lint_manifest(manifest)`；
2. 检查通过后才能交给P-02落盘；
3. 失败时只记录JSON路径和原因码，不记录被拒绝值；
4. manifest只允许使用合同中的随机`research_id`，不得加入联系方式或其哈希。

## P-02 数据记录

- L0/L1只能记录`research_id`、`reservation_id`和`audit_event_id`等不透明引用；
- 联系方式、HMAC令牌、凭据、招募引用和研究编号映射不得进入L0/L1；
- 存储路径和角色能力必须通过G-02配置检查；
- L0保持只追加，后续层必须保留输入哈希、代码提交和配置版本。

## X-01 随机化

```text
check_and_reserve -> allowed=true -> 资格与设备检查 -> 揭示分配
                                      |
                                      +-> 首次核心材料出现时 mark_exposed
```

- 只有`allowed=true`才能揭示分配；
- 暴露前取消调用`release_before_exposure`；
- 暴露、完成或暴露后退出均永久阻止跨阶段再次进入；
- X-01只能保存公开决策字段，不得读取或保存HMAC令牌；
- X-01调用时只传固定角色码`data-admin`；取消原因只传已登记的大写原因码，不传自由文本；
- `KEY_UNAVAILABLE`、`REGISTRY_UNAVAILABLE`、`UNAUTHORIZED`或未知异常都按拒绝处理。

## Z-01 Unity构建交付

- 每次正式候选构建先运行`scan-assets`；
- 机器清单必须与Git跟踪的Unity工程和许可台账哈希一致；
- `UNKNOWN`、`BLOCKED`、`REPLACE`、未登记、未跟踪或哈希漂移均阻止发布；
- `REPLACE`即使存在责任人、期限和排除方案，在替换或排除前仍不得发布；
- Unity `FormalBuildGate`必须同步调用该门，不能用手工勾选替代。

## W-03 投稿复现

- 公开包只包含通过披露复核的L5汇总、允许公开的配置和许可已清零资产；
- L0、L1、联系方式去重库、研究编号映射库、密钥和受控备份不得公开；
- L2至L4是否共享由真实授权和披露复核决定，不由任务执行者自行放宽；
- 论文只能陈述实际通过的合成、专机、真实运行和资产门，不从代码存在推断正式能力。

## 固定失败语义

| 情况 | 下游动作 |
|---|---|
| 去重服务不可用 | 不揭示分配，不开始正式会话 |
| Manifest隐私门失败 | 不落盘，不启动正式会话 |
| 正式环境门失败 | 仅允许合成数据演练 |
| Unity资产门失败 | 不生成可发布制品 |
| 保留期限未获批 | 不录入正式联系方式 |
| 第二人复核未完成 | G-02保持`IN_REVIEW`，不得转`DONE` |
