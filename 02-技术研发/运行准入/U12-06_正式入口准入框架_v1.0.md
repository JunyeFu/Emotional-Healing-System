# U12-06 正式入口准入框架 v1.0

> 适用任务：U12-06【运行准入】正式入口 v1.2 准入合同接线与负测试。
> 本框架只定义“是否允许进入正式运行”的工程门，不替代真实设备、机构回执、研究冻结或参与者活动证据。

## 1. 采用的优秀实践

本框架吸收四类公开实践，并按 SRP 约束收敛：

1. **环境保护规则**：成熟交付系统把环境、允许分支、人工批准和密钥访问绑定到同一个环境门；SRP 将其改为本机正式入口与 G-05 外部回执门。[GitHub Environments](https://docs.github.com/en/actions/concepts/workflows-and-actions/deployment-environments)
2. **构建来源证明**：SLSA 将构建输入、解析依赖、构建者、调用编号和输出制品放入可验证来源证明；SRP 对应为 manifest、Unity 构建标识、Python 提交和协议配置版本。[SLSA Build Provenance](https://slsa.dev/spec/v1.2/provenance)
3. **显式错误与默认拒绝**：OpenFeature 要求提供者报告错误并返回约定默认值；SRP 的正式模式更严格，任何关键门错误直接拒绝启动，不把开发默认值带入正式模式。[OpenFeature Providers](https://openfeature.dev/docs/reference/concepts/provider/)
4. **小范围、可回退发布**：Google SRE 将 canary 定义为有限、限时暴露并保留快速回退；SRP 阶段一不做在线渐进暴露，而是先用开发回放和灰盒验证准入逻辑，再由外部条件决定是否开放正式入口。[Google SRE Canarying](https://sre.google/workbook/canarying-releases/)

## 2. SRP 目标

U12-06 只回答一个问题：

> 当前 manifest、构建、协议、数据治理、分配、存储和外部准入证据是否足以允许一次正式会话开始？

它不回答：

- 天气场景是否已经完成最终视觉质量；
- 真实设备是否已经持续采集；
- 参与者活动是否已经执行；
- 研究数值、样本量或论文结论是否已经冻结。

### 2.1 当前基线裁定

| 项目 | 当前事实 | 对正式入口的影响 |
|---|---|---|
| F-01 | v2.1 机器合同已签收；v2.2 为独立候选 | `formal_*` 必须明确合同版本，不能把 v2.2 字段塞入 v2.1 |
| P-01 | `SessionCore`、TCP `5010`、UDP `5005/5006` 和开发门已完成 | 可作为会话权威；正式适配器仍需逐项提供 `formal_capable=True` |
| P-02 | 不可覆盖追加、封存和重放实现已完成候选 | 正式数据根、权限和运行装配未凭本框架自动通过 |
| G-02 | 隐私门与资产许可门已签收 | 仍需正式环境配置和发布资产清零证据 |
| Unity | `FormalBuildGate` 已存在 | 当前会检查四个场景、`FormalRuntimeController`、旧运行组件和资产许可；失败即阻止构建 |
| D-01/D-02 | 注册表状态均为 `WAIT_DEP_EXTERNAL` | 真实设备适配器和持续采集证据缺失时，`formal_stage_1` 必须 `BLOCK` |
| G-05/U12-05/U12-11 | 依赖真实外部回执，当前未关闭 | 不能用 Agent、仓库模拟或团队签字替代 |

当前仓库因此只能证明“准入框架与阻断逻辑可继续实现”，不能给出正式入口 `PASS`。

## 3. 包结构

U12-06 交付由六层组成：

```text
EntryRequest
  -> IdentityGate
  -> ContractGate
  -> ProvenanceGate
  -> DependencyGate
  -> EnvironmentGate
  -> ApprovalGate
  -> AdmissionDecision
```

每层输出统一的 `GateResult`：

```json
{
  "gate": "contract",
  "status": "PASS|BLOCK",
  "reason_code": "FORMAL_MANIFEST_VERSION_MISMATCH",
  "json_path": "manifest.schema_version",
  "evidence_id": "opaque-id",
  "required_for": ["formal_stage_1"]
}
```

结果中不得出现原手机号、凭据、HMAC、原始联络信息或研究编号映射。

### 3.1 本项目实际接线位置

| 层 | 项目权威实现或输入 | U12-06 的接线责任 |
|---|---|---|
| EntryRequest | `02-技术研发/srp_session_core/models.py`、manifest 模板 | 读取 `runtime_mode`、合同版本、分配和构建身份 |
| IdentityGate | `02-技术研发/srp_session_core/gates.py` | 拒绝未知模式；正式模式拒绝非正式适配器 |
| ContractGate | `02-技术研发/05-通信协议/contracts/` | 调用 v2.1 权威 Schema；v2.2 只走版本适配器 |
| ProvenanceGate | `P-02`归档、Unity `FormalBuildGate`、协议配置 | 绑定 Python 提交、Unity 构建、配置版本和资产许可报告 |
| DependencyGate | `RuntimeDependencies`、G-02、P-02、X-01、D-01/D-02 | 逐项检查 `formal_capable` 与真实能力回执 |
| EnvironmentGate | `SRP_SESSION_DATA_ROOT`、G-02正式配置 | 拒绝仓库内路径、临时目录和开发存储 |
| ApprovalGate | G-05、U12-05、U12-11 的责任人回执 | 只接受真实责任人签署的活动范围和外部条件 |
| AdmissionDecision | U12-06 新增入口编排器 | 只返回 `PASS/BLOCK` 与原因码，不推进会话状态 |

## 4. 门顺序与职责

### Gate 0：身份与模式

- 识别 `dev_replay`、`formal_stage_1`、`formal_stage_3`。
- 只允许明确列出的模式值。
- `dev_replay` 可以使用合成 fixture 和内存适配器，但结果不得生成正式运行证据。
- `formal_*` 缺少任一正式适配器时立即 `BLOCK`。
- 当前 `RuntimeDependencies.development()` 中的 `assignment_gate`、`formal_readiness_gate`、内存 manifest store 和合成暴露门只能用于 `dev_replay`；不得作为正式能力。

### Gate 1：合同与 manifest

- 校验 F-01/F-05 合同版本、Schema、协议配置版本和字段来源。
- 校验四天气顺序、两提示条件、分配索引、清单哈希和阶段字段一致。
- 不读取体验中结果改变顺序或分配。
- 不修改 v1.1 历史合同和运行 v2.2 历史记录。
- v2.1 正式运行入口的协议配置固定为 `protocol_config_version=1.1`；TCP 控制端口为 `5010`，TD/Unity UDP 端口分别为 `5005/5006`，遥测上限为 `20 Hz`。
- 四模块时长默认值为 `demo=25s`、`closed_loop=150s`、`lock_transition=25s`，允许区间分别为 `24–30s`、`140–160s`、`20–30s`。

### Gate 2：来源与构建身份

- 记录 Python 提交、协议配置哈希、Unity 构建哈希、TD 构建信息和资产许可状态。
- Unity 正式构建必须通过 `FormalBuildGate`；开发构建必须带 `DEV-REPLAY` 标记。
- 任何构建身份缺失、漂移或与 manifest 不一致时阻断。
- Unity 构建门当前明确拒绝缺少四个正式场景、缺少 `FormalRuntimeController`、存在旧 `WeatherController/UDPReceiver/SpoutReceiver` 的构建，并调用 G-02 资产扫描。

### Gate 3：依赖能力

正式阶段至少要求：

- G-02 隐私门可用；
- P-02 正式追加存储可用；
- X-01 分配与重复防护回执可用；
- D-01/D-02 真实设备适配器和质量元数据可用；
- Unity 正式客户端完成握手；
- TD 只作为监控与人工标记端，不成为会话状态权威。

### Gate 4：环境与权限

- 正式数据根目录必须是仓库外绝对路径。
- 角色、ACL、加密、资产许可和配置路径必须满足 G-02 约束。
- 不能用开发目录、临时目录或合成数据适配器伪装正式能力。

### Gate 5：外部准入

- `formal_stage_1` 依赖 G-05/U12-05/U12-11 实际回执所要求的部分。
- 机构路径、授权、人员角色、设备准备和保留期限没有真实责任人回执时阻断。
- Agent、团队总监或仓库内模拟检查不能代替外部回执。
- `formal_stage_1` 的最小外部条件包括：G-05 活动范围回执、U12-05 对应活动许可、D-01/D-02 真机准备与质量元数据、数据保留期限和责任人记录；任一缺失均返回 `EXTERNAL_ADMISSION_MISSING`。

### Gate 6：原子化启动

准入通过后按以下顺序执行：

1. 写入不可覆盖 manifest；
2. 写入所有 GateResult；
3. 校验 Unity 握手和构建身份；
4. 登记暴露；
5. 仅此后发送第一次 `start` 控制事件。

任一步骤失败，都不得发送 `start`，并返回明确 `reason_code`。

## 6. 负测试矩阵

至少覆盖以下拒绝路径：

| 编号 | 故障 | 预期结果 |
|---|---|---|
| N01 | manifest 缺失 | `BLOCK`，不写入正式会话 |
| N02 | Schema 或协议版本不匹配 | `BLOCK`，不发送控制 |
| N03 | 分配索引与清单哈希不一致 | `BLOCK` |
| N04 | G-02 隐私门不可用 | `BLOCK` |
| N05 | P-02 正式存储不可用 | `BLOCK` |
| N06 | Unity 构建哈希漂移 | `BLOCK` |
| N07 | Unity 正式握手失败 | `BLOCK` |
| N08 | 真实设备适配器缺失 | `BLOCK` |
| N09 | 外部准入回执缺失 | `BLOCK` |
| N10 | 重复 `start` 或重复事件 | 幂等，不推进第二次 |
| N11 | TCP 连接中断 | 正式模式中止；开发模式暂停 |
| N12 | TD 缺席 | 会话仍可运行，TD 不改变权威状态 |

### 6.1 本项目负测验收映射

| 测试组 | 直接消费 | 最低证据 | 失败含义 |
|---|---|---|---|
| N01–N03 | F-01 Schema、manifest、X-01分配 | `entry_contract_report.json` | 不发送 `start` |
| N04–N05 | G-02、P-02 | `dependency_capability_report.json` | 正式入口关闭 |
| N06–N07 | Unity `FormalBuildGate`、TCP握手 | `formal_build_gate_report.json` | 不生成或不接纳正式构建 |
| N08 | D-01/D-02 | 设备能力回执与断流记录 | 不进入正式阶段 |
| N09 | G-05/U12-05/U12-11 | 外部责任人回执索引 | 活动范围关闭 |
| N10–N12 | P-01控制队列与TD只读约束 | `negative_test_report.json` | 保持权威边界，不静默补值 |

负测必须同时验证“无 `start` 控制事件”和“无正式暴露登记”两个结果；仅抛出异常而未验证副作用禁止记为通过。

## 8. 责任边界与完成门

- 傅钧烨：任务实现负责人。
- 独立 Agent：只读复核代码、合同、负测试和证据关联。
- 真实第二人：签收实现范围，不代签外部条件。
- G-05/D-01/D-02/I-01：提供外部回执、真实设备和全链证据。

U12-06 只有在 AC1、AC2、AC3、专项验证、独立复核、真实第二人签收、commit 和 push 全部完成后才能转为 `DONE`。

### 8.1 U12-06 实施清单

1. 在 `02-技术研发/运行准入/` 实现入口编排器和统一 `GateResult`，不把准入结果写成 `SessionCore` 状态。
2. 接入 F-01 v2.1、G-02、P-02 和 X-01；正式模式拒绝 P-01 当前开发装配中的合成门与内存存储。
3. 接入 Unity `FormalBuildGate` 的结果，并保留四场景、控制器、旧组件和资产许可失败原因。
4. 为 N01–N12 建立可运行 fixture；验证失败时没有 `start`、暴露登记或UDP正式发布副作用。
5. 生成本节证据包，标注 `DEV-REPLAY` 或 `FORMAL-CANDIDATE`，再进行独立复核。
6. 实际外部回执到达前，状态保持 `IN_PROGRESS` 或 `IN_REVIEW`，不得改为 `DONE`。

## 9. 不采纳的外部做法

- 不引入云平台 OIDC：SRP 当前是本机实验系统，没有云部署对象。
- 不把 TD 变成发布控制平面：TD 只读监控和人工标记职责已经冻结。
- 不引入线上 canary：本项目不是持续在线服务，阶段一正式开放仍由研究准入门决定。
- 不用统一默认值掩盖正式门失败：开发默认值只存在于 `dev_replay`。
